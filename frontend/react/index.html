React

Kamu cukup bilang: “kalau datanya begini, tampilannya begini”. React yang mengurus mengubah layar saat data berubah.

$ Tampilan = fungsi dari data.

Setiap data berubah, kita mencari elemen lalu mengubahnya manual. Lupa satu, tampilan salah.

◆ Buat apa ini? Kenapa pakai ini?

Given — tampilan bergantung pada data yang sering berubah.

When — kita mengubah DOM secara manual setiap data berubah.

Then — tampilan dan data sering tidak sinkron.

→ makanya kita pakai React — supaya tampilan selalu mengikuti data secara otomatis.

warm-up

Kenapa angkanya cuma naik 1?

function Counter() {
  const [count, setCount] = useState(0);
  function addThree() {
    setCount(count + 1);
    setCount(count + 1);
    setCount(count + 1);
  }
  return <button onClick={addThree}>{count}</button>;
}
  • Diklik sekali. Hasilnya 3 atau 1?
ide dasar

Komponen, props, dan state

function Counter({ label }) {          // props: data dari induk
  const [count, setCount] = useState(0); // state: ingatan komponen

  return (
    <button onClick={() => setCount(count + 1)}>
      {label}: {count}
    </button>
  );
}

<Counter label="Suka" />

Gampangnya

  • Komponen = fungsi yang mengembalikan tampilan.
  • Props = data dari luar, hanya dibaca.
  • State = ingatan komponen. Ubah lewat setter.
  • setCount → React menggambar ulang.
Ubah state selalu lewat setter, jangan langsung.
kosakata

Hooks yang paling sering

useState

Ingatan

Menyimpan nilai yang bisa berubah.

useEffect

Efek samping

Sinkron dengan dunia luar: fetch, timer, event. Jangan dipakai untuk hitungan biasa.

useMemo

Simpan hasil hitungan

Untuk hitungan mahal saja.

custom hook

Logika dipakai ulang

useCart(), useAuth(). Fungsi biasa yang memakai hooks.

yang perlu dijaga

Jebakan yang sering kejadian

jebakan

Ubah state langsung

items.push(x) tidak memicu render. Pakai [...items, x].

jebakan

useEffect berlebihan

Data turunan cukup dihitung saat render.

jebakan

Lupa key di list

Pakai id unik sebagai key, bukan index.

tips

Komponen kecil

Satu komponen, satu tugas. Mudah dites dan dipakai ulang.

salah → benar

Data turunan: hitung saja, jangan disimpan

✗ state + effect berlebihan
const [items, setItems] = useState([]);
const [total, setTotal] = useState(0);
useEffect(() => {
  setTotal(items.reduce((s, i) => s + i.price, 0));
}, [items]);   // ← render dua kali
✓ hitung saat render
const [items, setItems] = useState([]);
const total = items.reduce(
  (s, i) => s + i.price, 0);
// selalu sinkron, tanpa effect
// mahal? bungkus useMemo
Kalau bisa dihitung dari state lain, itu bukan state.

→
React jadwalkan render

Bandingkan & ubah DOM seperlunya
