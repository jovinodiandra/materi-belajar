◆ Buat apa ini? Kenapa pakai ini?

Given — kita menulis tes untuk komponen frontend.

When — tes mengecek detail implementasi, bukan perilaku yang dilihat user.

Then — tes rapuh saat refactor dan bug nyata tetap lolos.

→ makanya kita pakai testing berbasis perilaku — supaya tes kuat dan benar-benar melindungi user.

ide dasar

Testing Library: cari seperti user

test("menampilkan error kalau email kosong", async () => {
  render(<LoginForm />);

  await userEvent.click(
    screen.getByRole("button", { name: "Masuk" }));

  expect(screen.getByRole("alert"))
    .toHaveTextContent("Email wajib diisi");
});

Gampangnya

  • Cari elemen lewat role & teks, seperti user melihatnya.
  • userEvent meniru klik dan ketik sungguhan.
  • Cek hasil yang terlihat, bukan state di dalam.
Bonus: getByRole sekaligus mengetes aksesibilitas.

Palsukan API dengan MSW

handler
import { http, HttpResponse } from "msw";

export const handlers = [
  http.get("/api/products", () =>
    HttpResponse.json([{ id: 1, name: "Sepatu" }])),
  http.post("/api/cart", () =>
    new HttpResponse(null, { status: 500 })),
];
tes
test("tampilkan error kalau gagal", async () => {
  render(<ProductPage />);
  await user.click(
    await screen.findByRole("button", { name: "Beli" }));
  expect(await screen.findByText(/gagal/i))
    .toBeVisible();
});
MSW memalsukan di level jaringan. Komponen tetap memanggil fetch seperti biasa.
end-to-end

Tes alur penting dengan Playwright

tes e2e
test("checkout berhasil", async ({ page }) => {
  await page.goto("/products/1");
  await page.getByRole("button", { name: "Beli" }).click();
  await page.getByRole("link", { name: "Keranjang" }).click();
  await page.getByRole("button", { name: "Bayar" }).click();
  await expect(page.getByText("Terima kasih"))
    .toBeVisible();
});
