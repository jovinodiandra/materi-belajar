Client–Server

Satu pihak meminta (client), satu pihak melayani (server). Pola paling dasar di balik hampir semua aplikasi.

$ Pembeli dan warung.

Kalau semua data dan logika ada di HP tiap orang, data tidak pernah sama.

📱

Data tersebar di tiap perangkat

HP A dan HP B punya isi berbeda.

🔓

Logika penting bisa diakali

Harga dihitung di HP? Bisa diubah user.

🔄

Update harus ke semua perangkat

Ubah satu aturan, semua orang harus update aplikasi.

Satu pusat

data & aturan penting dijaga server

◆ Buat apa ini? Kenapa pakai ini?

Given — banyak pengguna perlu melihat dan mengubah data yang sama.

When — data dan aturan penting disimpan di perangkat masing-masing.

Then — data tidak sinkron dan aturan bisa diakali.

→ makanya kita pakai Client–Server — supaya ada satu pusat yang menjaga data dan aturan.

contoh

Bentuk paling sederhana: HTTP

// Server (Spring Boot)
@GetMapping("/products/{id}")
Product get(@PathVariable long id) {
    return productService.find(id);
}

// Client (Java HttpClient)
var req = HttpRequest.newBuilder(
    URI.create("https://api.toko.id/products/7")).build();
var res = http.send(req, BodyHandlers.ofString());

Gampangnya

  • Client kirim request: alamat + metode (GET/POST).
  • Server balas response: status + data.
  • Bahasanya sudah disepakati: HTTP.
Selama sama-sama bicara HTTP, bahasa pemrogramannya bebas.

Aturan penting

aturan

Jangan percaya client

Validasi ulang semua input di server. Client bisa diakali.

aturan

Server = satu titik pusat

Server mati, semua client ikut tidak bisa kerja. Siapkan cadangan.

aturan

Jaringan bisa putus

Client harus siap dengan timeout dan pesan error yang jelas.

aturan

Server stateless

Jangan simpan sesi di memori server, supaya gampang ditambah.

salah → benar

Server menghitung sendiri

✗ percaya client
@PostMapping("/checkout")
Order checkout(@RequestBody Req r) {
  return orders.create(r.items(),
                       r.total());   // ← angka dari client
}
✓ hitung di server
@PostMapping("/checkout")
Order checkout(@RequestBody Req r) {
  long total = pricing.calculate(r.items());
  return orders.create(r.items(), total);
}
// client cuma kirim: id barang + jumlah
Client boleh menampilkan total. Yang menentukan tetap server.

Server lambat, client terus mencoba

Server lambat
→
Client timeout
→
Client retry otomatis
→
Server makin berat
  • Client pakai timeout + retry dengan jeda makin lama (backoff).
  • Server pasang batas (rate limit) supaya tidak kebanjiran.
