N+1 Query
Problem

Ambil 100 data pakai 1 query, lalu tanpa sadar bikin 100 query lagi untuk detailnya. Totalnya 101 query.

$ Belanja 100 barang, tapi bolak-balik ke toko 100 kali.

contohnya

Kelihatannya polos, ternyata 101 query

✗ 1 + N query
List<Order> orders = repo.findAll(); // 1 query

for (Order o : orders) {
  // tiap akses customer = 1 query baru
  print(o.getCustomer().getName()); // ← N query
}
✓ Ambil sekaligus (JOIN)
@Query("SELECT o FROM Order o " +
       "JOIN FETCH o.customer")
List<Order> findAllWithCustomer();

// cukup 1 query untuk semuanya
100 order = 101 query. 10.000 order = 10.001 query.

Gimana ketahuan?

cek

Nyalakan log SQL

cek

cek

Cepat di lokal (data sedikit), lambat di production.

→
Prod: 500 order, 501 query
→
Tiap query 2 ms → 1 detik
→

  • Data kecil di dev menyembunyikan N+1. Uji dengan data yang mirip produksi.
di tempat lain

N+1 bukan cuma di JPA

  • GraphQL: resolver per item → pakai DataLoader.
  • Frontend: daftar 50 item, tiap item fetch detail sendiri → buat endpoint batch.
  • Microservices: panggil service user 50 kali → endpoint GET /users?ids=…
  • Template: akses relasi lazy di view (Thymeleaf, JSP).
