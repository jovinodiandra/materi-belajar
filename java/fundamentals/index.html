// Java Fundamentals — dasar bahasa yang jalan di mana saja

Satu bahasa, jalan di mana saja.

Java lahir tahun 1995 dari Sun Microsystems dengan satu janji besar: tulis kode sekali, jalankan di mana saja — lewat lapisan abstraksi bernama JVM. Akar masalah · Portabilitas & keamanan tipe

Kenapa Java masih relevan 30 tahun kemudian

Sebelum Java, kode yang kamu tulis di satu sistem operasi sering harus ditulis ulang atau dikompilasi ulang secara khusus supaya jalan di sistem lain. Java menjawab ini dengan JVM (Java Virtual Machine) sebagai lapisan penerjemah — program dikompilasi sekali ke bentuk netral, lalu JVM di tiap platform yang menjalankannya.

“Java dirancang untuk sederhana, berorientasi objek, dan familiar; kuat dan aman; arsitektur netral dan portabel — dicapai lewat mesin virtual yang membebaskan program dari ketergantungan pada implementasi platform tertentu.”

— James Gosling & tim Sun Microsystems, white paper "The Java Language Environment" (1995)
◆ Analogi — kaset video vs film digital universal

Bayangkan dulu ada kaset VHS yang cuma bisa diputar di pemutar tertentu, dan kaset Betamax yang butuh pemutar lain lagi. Java ibarat membuat format film digital universal: sekali kamu "burn" filmnya (compile), pemutar apa pun (JVM di Windows, Linux, macOS) bisa memutarnya tanpa perlu versi berbeda-beda. Ditambah lagi, karena Java mengecek tipe data secara statis saat compile, banyak kesalahan konyol (salah tipe, salah pemanggilan) ketahuan sebelum program dijalankan — bukan meledak di tangan pengguna.

Kombinasi portabilitas lintas platform dan keamanan tipe statis inilah yang membuat Java tetap jadi pilihan default untuk sistem yang harus jalan lama, stabil, dan bisa dipelihara tim besar — dari backend enterprise sampai jutaan perangkat Android.

Konsep inti · Tipe data

Primitive vs reference — dua dunia tipe data di Java

Java adalah bahasa statically typed: tiap variabel harus punya tipe yang jelas, dan tipe itu terbagi dua kelompok besar dengan perilaku berbeda.

◆ Primitive vs reference
Primitiveint, double, boolean, char, long, float, byte, short
ReferenceString, Integer, array, dan semua class/object lain

Primitive menyimpan nilai langsung di variabelnya. Reference menyimpan alamat ke objek yang sesungguhnya hidup di memori lain — mirip menyimpan alamat rumah, bukan rumahnya sendiri.

TipeData.javaJava
public class TipeData {
    public static void main(String[] args) {
        // primitive - nilai disimpan langsung
        int umur = 25;
        double harga = 15990.50;
        boolean isAktif = true;
        char grade = 'A';

        // reference - variabel menyimpan alamat objek
        String nama = "Budi Santoso";
        Integer umurObjek = 25; // autoboxing ke wrapper class

        // operator & konversi tipe
        int hasil = umur + 10;
        double umurDouble = (double) umur; // casting eksplisit
        var totalHarga = harga * 2; // type inference, tetap statically typed

        System.out.println(nama + " berumur " + hasil);
    }
}

Perhatikan var — itu bukan berarti Java jadi dynamically typed. Compiler tetap menyimpulkan tipe pastinya saat compile (di sini double); var cuma menghemat penulisan, bukan mengubah aturan tipe statisnya.

Konsep inti · Alur program & method

Control flow & method — mengatur jalannya logika

Java punya perkakas standar untuk mengatur alur: if/else, switch, dan tiga jenis perulangan. Logika yang berulang dikemas jadi method — bisa punya banyak versi lewat overloading.

AlurProgram.javaJava
public class AlurProgram {

    static String cekNilai(int skor) {
        // switch expression modern (arrow syntax)
        return switch (skor / 10) {
            case 10, 9 -> "A";
            case 8 -> "B";
            case 7 -> "C";
            default -> "D";
        };
    }

    // method overloading - nama sama, parameter beda
    static int tambah(int a, int b) { return a + b; }
    static double tambah(double a, double b) { return a + b; }

    public static void main(String[] args) {
        int skor = 87;
        if (skor >= 60) {
            System.out.println("Lulus: " + cekNilai(skor));
        } else {
            System.out.println("Tidak lulus");
        }

        for (int i = 0; i < 3; i++) {
            System.out.println("Percobaan ke-" + i);
        }

        int j = 0;
        do {
            j++;
        } while (j < 3);

        System.out.println(tambah(2, 3));
        System.out.println(tambah(2.5, 1.5));
    }
}

Method di atas punya parameter, return type yang eksplisit (String, int, double), dan dua versi tambah() dengan tipe parameter berbeda — itulah overloading: nama sama, tanda tangan (signature) beda.

Konsep inti · Struktur data & OOP dasar

Array & class/object — membungkus data jadi satu kesatuan

Array menyimpan banyak nilai bertipe sama dalam satu variabel. Class membungkus data (field) dan perilaku (method) jadi satu cetak biru; object adalah instans nyata dari cetak biru itu, dibuat lewat constructor.

BankDemo.javaJava
class BankAccount {
    private double saldo;
    private final String pemilik;

    // constructor
    BankAccount(String pemilik, double saldoAwal) {
        this.pemilik = pemilik;
        this.saldo = saldoAwal;
    }

    void deposit(double jumlah) {
        if (jumlah > 0) saldo += jumlah;
    }

    boolean withdraw(double jumlah) {
        if (jumlah <= 0 || jumlah > saldo) return false;
        saldo -= jumlah;
        return true;
    }

    double getSaldo() { return saldo; }
}

public class BankDemo {
    public static void main(String[] args) {
        // array berisi object
        BankAccount[] rekening = new BankAccount[2];
        rekening[0] = new BankAccount("Budi", 100000);
        rekening[1] = new BankAccount("Sari", 250000);

        rekening[0].deposit(50000);
        rekening[1].withdraw(30000);

        for (BankAccount akun : rekening) {
            System.out.println(akun.getSaldo());
        }
    }
}

Field saldo bersifat private — hanya bisa diubah lewat method deposit()/withdraw() yang punya aturan (validasi jumlah). Ini contoh sederhana encapsulation, salah satu pilar dasar OOP di Java.

Konsep inti · Mesin di baliknya

JVM & bytecode — compile-once, run-anywhere

Kode .java yang kamu tulis tidak langsung dijalankan oleh sistem operasi. Ada satu langkah perantara: compiler javac mengubahnya jadi bytecode netral platform (.class), lalu JVM di tiap mesin yang benar-benar mengeksekusinya.

◆ Alur compile-once-run-anywhere
TulisBankDemo.java — kode sumber yang kamu tulis
Compilejavac BankDemo.java → BankDemo.class
BytecodeBankDemo.class — instruksi netral, bukan kode mesin OS tertentu
Jalankanjava BankDemo → dieksekusi oleh JVM (Windows/Linux/macOS)

JVM di Windows, Linux, dan macOS berbeda-beda implementasinya, tapi semuanya sepakat memahami format bytecode yang sama. Karena itu, satu file .class yang sama bisa jalan di mana pun ada JVM terpasang — kamu tidak perlu compile ulang per platform.

Inilah yang membedakan Java dari bahasa yang dikompilasi langsung ke kode mesin (seperti C): lapisan bytecode + JVM itulah yang menjadi "penerjemah universal" di balik janji write once, run anywhere.

◆ Praktik · Kebiasaan yang bikin kode Java rapi

Best practice dasar sebelum lanjut ke OOP

Syntax yang benar belum tentu kode yang baik. Beberapa kebiasaan berikut layak dibiasakan sejak awal.

“Kelas yang immutable lebih mudah dirancang, diimplementasikan, dan dipakai; minimalkan mutability sebisa mungkin, dan lebih utamakan komposisi daripada pewarisan.”

— Joshua Bloch, Effective Java
  • Ikuti naming convention — PascalCase untuk nama class, camelCase untuk variabel & method, UPPER_SNAKE_CASE untuk konstanta.
  • Pakai final untuk field yang tidak seharusnya berubah — mendekatkan kamu pada immutability yang disarankan Bloch, mengurangi bug akibat state berubah tak terduga.
  • Hindari null tanpa perlu — pertimbangkan Optional<T> atau nilai default yang jelas, alih-alih membiarkan NullPointerException muncul di runtime.
  • Gunakan try-with-resources untuk resource seperti file/stream/koneksi, supaya otomatis ditutup meski terjadi exception.
  • Satu class, satu tanggung jawab jelas — hindari class raksasa yang mengurus terlalu banyak hal sekaligus.
  • Favor composition over inheritance — gabungkan object lewat komposisi ketimbang membangun hierarki pewarisan yang dalam & rapuh.

◆ Harga · Tidak ada bahasa yang sempurna

Trade-off: kekuatan Java vs harganya

Java bukan bahasa "terbaik" secara mutlak — ia punya kekuatan yang jelas, dan juga harga yang sering dikeluhkan dibanding bahasa yang lebih modern.

// Kekuatan Java

  • Tipe statis — banyak error ketahuan saat compile.
  • Ekosistem matang — library & tooling untuk hampir semua kebutuhan.
  • JVM portable — jalan konsisten lintas platform.
  • Backward compatibility kuat — kode lama tetap jalan di JVM baru.

// Yang dikorbankan

  • Verbose — butuh lebih banyak baris untuk hal sederhana.
  • Boilerplate lebih banyak dibanding Kotlin/Python.
  • Startup JVM & konsumsi memori relatif lebih berat.
  • Sebagian syntax terasa kaku untuk pemula.
◆
Verbosity Java bukan cuma "kekurangan tanpa alasan" — eksplisitnya tipe data & struktur membuat kode besar lebih mudah dilacak & dipelihara tim besar, meski menulisnya terasa lebih panjang dibanding bahasa yang lebih ringkas seperti Kotlin.

Penutup

Fondasi ini yang akan kamu pakai terus

Java Fundamentals bukan tujuan akhir — ini fondasi. Tipe data, control flow, class/object, dan pemahaman JVM di atas akan terus kamu pakai begitu masuk ke OOP yang lebih dalam.

  • Write once, run anywhere — berkat JVM sebagai lapisan abstraksi dari OS.
  • Tipe statis — primitive menyimpan nilai, reference menyimpan alamat objek.
  • Control flow & method — alat dasar mengatur logika & membungkusnya jadi reusable.
  • Class = cetak biru, object = instansnya — fondasi OOP dimulai dari sini.
  • Bytecode di tengah — .java → javac → .class → dieksekusi JVM.
  • Immutability & komposisi — kebiasaan baik sejak level fundamental.

Langkah berikutnya

Setelah nyaman dengan dasar ini, lanjutkan ke topik OOP Java (inheritance, polymorphism, interface & abstract class secara mendalam), lalu Collections & Streams API untuk mengolah data secara idiomatis di Java modern.
