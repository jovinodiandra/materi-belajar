Next.js

Framework lengkap di atas React: routing dari folder, render di server, dan API dalam satu project.

$ React + perlengkapan lengkap untuk produksi.

Aplikasi React biasa: layar putih dulu, Google susah membaca isinya.

⬜

Layar putih saat dimuat

Browser harus unduh dan jalankan JS dulu.

🔍

SEO lemah

Mesin pencari melihat halaman kosong.

🧩

Router, build, server dirakit sendiri

Banyak keputusan dan konfigurasi.

Render di server

HTML sudah jadi sebelum sampai browser

◆ Buat apa ini? Kenapa pakai ini?

Given — kita membuat aplikasi React yang perlu cepat tampil dan mudah ditemukan Google.

When — semua halaman dirender di browser setelah JS selesai diunduh.

Then — tampilan awal lambat dan SEO lemah.

→ makanya kita pakai Next.js — supaya halaman sudah jadi dari server dan routing tersedia.

ide dasar

App Router: folder = alamat halaman

// app/products/[id]/page.tsx  ->  /products/42
export default async function ProductPage({ params }) {
  const { id } = await params;
  const product = await db.product.find(id); // jalan di server

  return (
    <main>
      <h1>{product.name}</h1>
      <AddToCart id={id} />   {/* komponen client */}
    </main>
  );
}

Gampangnya

  • Nama folder = alamat URL.
  • Server Component (default): boleh akses DB, tidak dikirim ke browser.
  • Komponen interaktif diberi "use client".
Default di server. Butuh klik/state? Tandai "use client".

Env var tanpa NEXT_PUBLIC_ aman. Jangan kirim kunci ke client.

tips

Taruh use client di ujung

Bungkus hanya tombol interaktif, bukan seluruh halaman.

server actions

Kirim form tanpa membuat API sendiri

app/todos/actions.ts
"use server";

export async function addTodo(formData: FormData) {
  const title = String(formData.get("title"));
  await db.todo.create({ data: { title } });
  revalidatePath("/todos");   // segarkan halaman
}
app/todos/page.tsx
import { addTodo } from "./actions";

<form action={addTodo}>
  <input name="title" required />
  <button>Tambah</button>
</form>
// tetap jalan walau JS belum dimuat
Server action tetap endpoint publik: validasi dan cek izin di dalamnya.

cache

Mengatur kesegaran data

TulisArtinya
fetch(url, { cache: "force-cache" })Simpan, pakai terus
fetch(url, { next: { revalidate: 60 } })Segarkan tiap 60 detik (ISR)
fetch(url, { cache: "no-store" })Selalu ambil baru
revalidatePath / revalidateTagSegarkan setelah data diubah
