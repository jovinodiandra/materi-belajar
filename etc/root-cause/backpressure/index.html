Backpressure

Kalau yang ngirim lebih cepat dari yang ngolah, antrean bakal numpuk sampai meledak. Backpressure = cara bilang "pelan-pelan dong".

contoh

Antrean tanpa batas vs antrean dibatasi

✗ Antrean tak terbatas
// terima terus, ngolahnya belakangan
queue = new LinkedBlockingQueue<>(); // ← tanpa batas!

onRequest(req) {
  queue.add(req); // selalu diterima
}
// lama-lama RAM habis
✓ Antrean ada batasnya
queue = new ArrayBlockingQueue<>(1000);

onRequest(req) {
  if (!queue.offer(req)) {
    // penuh → tolak dengan sopan
    return status(429, "coba lagi nanti");
  }
}
Menolak sebagian lebih baik daripada mati semuanya.

Reactor

Backpressure di reactive stream

tanpa batas
Flux.fromIterable(millionOrders)
    .flatMap(o -> callPartnerApi(o))   // ← semua sekaligus
    .subscribe();
dibatasi
Flux.fromIterable(millionOrders)
    .flatMap(o -> callPartnerApi(o), 16)   // maks 16 paralel
    .onBackpressureBuffer(1_000,
        dropped -> log.warn("drop {}", dropped.id()))
    .subscribe();
Angka 16 = berapa banyak yang boleh dikerjakan bersamaan. Sisanya menunggu giliran.

Tiga hal untuk diingat

❯ masalahnya

Producer lebih cepat dari consumer, antrean numpuk.

❯ tanda

Queue, memori, dan latency naik terus.

❯ obatnya

Batasi antrean, tolak dengan sopan, atau pakai pull.
