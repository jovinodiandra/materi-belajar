Sebelum jadi algoritma, banyak soal itu soal matematika dulu.

Cek bilangan prima, cari pembagi terbesar dua angka, hitung hasil kombinatorial yang bisa raksasa — semuanya berakar dari number theory dasar. Deck ini buat pemula: dari kenapa topik ini muncul terus di soal problem solving, algoritma intinya (primality test, GCD/LCM, sieve of Eratosthenes, modular arithmetic), sampai kapan dipakai di production — diselingi kalimat dari buku rujukan.

Akar masalah · Kenapa number theory ada di mana-mana

Banyak soal problem solving fundamentalnya masalah matematis

Kriptografi butuh bilangan prima besar. Hash function butuh bilangan prima untuk distribusi yang merata. Sistem yang berjalan berulang di interval berbeda butuh LCM untuk tahu kapan mereka bertemu lagi. Di balik semua itu, pertanyaannya sering sesederhana: apakah angka ini prima?, berapa pembagi terbesar dari dua angka ini?, atau berapa sisa bagi dari angka yang sangat besar?

◆ Buat apa ini? Kenapa pakai ini?

Given — kamu cek "apakah n prima?" dengan loop naif dari 2 sampai n-1, dan cari GCD dua angka dengan coba-coba semua kemungkinan pembagi satu per satu.

When — n naik jadi jutaan (generate prime besar buat kunci kriptografi), atau fungsi itu dipanggil ribuan kali dalam sistem scheduling/hashing, atau perkalian modulonya melibatkan angka yang jauh melebihi batas integer biasa.

Then — waktu eksekusi meledak jadi O(n) per pengecekan padahal harusnya bisa O(√n), sieve yang harusnya sekali precompute malah dihitung ulang terus, dan hasil perkalian besar overflow diam-diam karena tidak dibungkus modular arithmetic.

→ makanya kita pakai Math & Number Theory.

◆ Analogi — dua bus yang bertemu lagi di halte yang sama

Bus A berangkat dari terminal setiap 12 menit, bus B setiap 18 menit. Keduanya berangkat bersamaan jam 6 pagi. Kapan mereka berangkat bersamaan lagi? Jawabannya bukan coba-coba satu-satu — itu adalah LCM(12, 18) = 36 menit. Soal jadwal, penjadwalan ulang sistem, atau sinkronisasi proses yang berjalan di interval berbeda, semuanya adalah soal ini dengan baju berbeda.

Number theory bukan cabang matematika yang terpisah dari pemrograman — ia adalah alat yang muncul begitu soal melibatkan pembagi, kelipatan, sisa bagi, atau bilangan prima dalam skala besar. Menguasai fondasinya berarti bisa mengenali pola ini secepat mengenali pola array atau tree.

Konsep inti · Dua algoritma paling dasar

Primality test O(√n) & GCD lewat Euclidean algorithm

Untuk cek apakah n prima, kamu tidak perlu mencoba semua pembagi sampai n. Cukup sampai √n — kalau n punya pembagi lebih besar dari √n, pasti ada pasangan pembagi lain yang lebih kecil dari √n. Itu langsung memangkas kompleksitasnya dari O(n) jadi O(√n).

Primes.java — primality test O(√n)Java
public class Primes {

    static boolean isPrime(int n) {
        if (n < 2) return false;
        for (int i = 2; (long) i * i <= n; i++) { // cek sampai √n, bukan n
            if (n % i == 0) return false;
        }
        return true;
    }

    public static void main(String[] args) {
        System.out.println(isPrime(97));  // true
        System.out.println(isPrime(100)); // false
    }
}

Pertanyaan kedua yang sering muncul berdampingan: GCD (Greatest Common Divisor / pembagi bersama terbesar) dan LCM (Least Common Multiple / kelipatan persekutuan terkecil). Cara paling efisien mencari GCD adalah Euclidean algorithm: gcd(a, b) = gcd(b, a % b), sampai b jadi 0.

“Algoritma Euclidean untuk mencari pembagi bersama terbesar adalah salah satu algoritma tertua yang masih dipakai luas hingga sekarang — contoh klasik bagaimana pengulangan sederhana bisa menyelesaikan masalah matematis secara efisien tanpa perlu memfaktorkan angkanya sama sekali.”

— parafrase dari Donald Knuth, The Art of Computer Programming, Volume 2: Seminumerical Algorithms
Gcd.java — Euclidean algorithm untuk GCD & LCMJava
public class Gcd {

    static int gcd(int a, int b) {
        if (b == 0) return a;      // base case
        return gcd(b, a % b);      // (a, b) → (b, a mod b)
    }

    static int lcm(int a, int b) {
        return a / gcd(a, b) * b; // bagi dulu biar tak overflow
    }

    public static void main(String[] args) {
        System.out.println(gcd(48, 18)); // 6
        System.out.println(lcm(12, 18)); // 36 — dua bus di analogi tadi
    }
}

Perhatikan: lcm(a, b) = a / gcd(a, b) * b. Pembagian dilakukan sebelum perkalian supaya angkanya tidak sempat membengkak lebih dari yang perlu — kebiasaan kecil ini akan sering muncul lagi saat bicara overflow di bab berikutnya.

Konsep inti · Efisiensi & keamanan angka besar

Sieve of Eratosthenes & modular arithmetic

isPrime() bagus untuk satu angka. Tapi kalau kamu butuh semua bilangan prima sampai N, mengecek satu-satu itu boros. Sieve of Eratosthenes mencoret semua kelipatan tiap bilangan prima sekali jalan, menghasilkan seluruh daftar prima dalam O(n log log n) — jauh lebih cepat dari cek satu-satu yang totalnya O(n√n).

cek prima satu-satu untuk banyak angkaJava
int N = 1_000_000;
for (int x = 2; x <= N; x++) {
    if (isPrime(x)) {   // tiap cek O(√n) sendiri-sendiri
        primes.add(x);
    }
}
// total: O(n * √n) — lambat untuk n besar
sieve of Eratosthenes — sekali jalanJava
static boolean[] sieve(int n) {
    boolean[] isComposite = new boolean[n + 1];
    for (int i = 2; (long) i * i <= n; i++) {
        if (!isComposite[i]) {
            for (int j = i * i; j <= n; j += i) {
                isComposite[j] = true; // coret semua kelipatan i
            }
        }
    }
    return isComposite;
}
// total: O(n log log n) — sieve sekali, pakai berkali-kali

Masalah kedua muncul begitu hasil hitungan bisa sangat besar — jumlah cara menyusun sesuatu, hasil perpangkatan, dsb — angkanya bisa melampaui batas int atau bahkan long. Solusinya: kerjakan semuanya modulo m (biasanya 10^9 + 7) di sepanjang proses, bukan cuma di akhir.

“Modular arithmetic penting dalam algoritma karena banyak masalah komputasi melibatkan angka yang tumbuh sangat besar, seperti hasil kombinatorial — bekerja modulo m di sepanjang komputasi mencegah overflow sekaligus menjaga hasilnya tetap benar secara matematis.”

— parafrase dari Thomas H. Cormen, Charles E. Leiserson, Ronald L. Rivest, Clifford Stein, Introduction to Algorithms (CLRS)
ModMath.java — modular arithmetic dasarJava
static final long MOD = 1_000_000_007L;

static long modAdd(long a, long b) {
    return ((a % MOD) + (b % MOD)) % MOD;
}

static long modMul(long a, long b) {
    return (a % MOD) * (b % MOD) % MOD; // modulo dulu sebelum kali, cegah overflow
}
◆
Urutan operasi penting: (a * b) % MOD bisa overflow kalau a dan b sudah dekat batas long sebelum dikalikan. Selalu ambil modulo secukupnya di setiap langkah — bukan cuma menaruhnya di baris terakhir dan berharap aman.
◆ Praktik · Kebiasaan aman menulis kode matematis

Best practice number theory dalam problem solving

Sebagian besar bug di soal matematis bukan salah logika, tapi salah kebiasaan kecil — overflow, precompute yang telat, atau lupa modulo di satu tempat. Berikut kebiasaan yang menyelamatkan.

  1. Precompute sieve kalau butuh cek banyak angka prima — jangan panggil isPrime() di dalam loop besar kalau bisa hitung sekali di awal.
  2. Pakai modular arithmetic begitu hasil bisa sangat besar — kombinatorial, perpangkatan, atau perkalian berantai wajib dikerjakan modulo m di sepanjang proses.
  3. Hati-hati integer overflow saat perkalian sebelum modulo — gunakan long (atau tipe lebih besar) dan ambil modulo sesering mungkin, bukan cuma di akhir.
  4. Gunakan Euclidean algorithm untuk GCD, bukan mencoba semua pembagi satu-satu — gcd(a, b) = gcd(b, a % b) jauh lebih cepat.
  5. Untuk LCM, bagi dulu baru kalikan — a / gcd(a, b) * b, bukan a * b / gcd(a, b), supaya angka sementara tidak membengkak tanpa perlu.
  6. Uji edge case angka kecil — 0, 1, angka negatif, dan bilangan prima terkecil (2) — sebelum percaya solusi benar untuk angka besar.
◆ Roadmap · Bertahap sesuai levelmu

Tier belajar math & number theory

Number theory punya jalur yang cukup jelas — mulai dari algoritma dasar, naik ke teknik yang lebih efisien untuk skala besar, sampai ke fondasi kriptografi modern.

Beginner

Dasar: prima & pembagi

Titik awal yang wajib dikuasai sebelum lanjut — dua algoritma paling sering muncul di soal dasar.

  • Primality test O(√n)
  • GCD lewat Euclidean algorithm
  • LCM dari GCD
  • Faktorisasi prima sederhana
Middle

Efisiensi untuk skala besar

Saat soal butuh banyak query atau angka yang sangat besar, algoritma dasar tidak cukup lagi.

  • Sieve of Eratosthenes
  • Modular arithmetic dasar
  • Modular exponentiation (fast power)
  • Sieve untuk faktorisasi banyak angka
Advance

Fondasi kriptografi

Di level ini, number theory jadi dasar sistem keamanan & struktur data yang lebih rumit.

  • Modular inverse
  • Extended Euclidean algorithm
  • Chinese Remainder Theorem
  • Aplikasi ke kriptografi dasar (mis. RSA)
◆ Harga · Precompute vs on-demand

Trade-off: setup di awal vs hitung tiap query

Sieve itu cepat kalau kamu butuh banyak jawaban dari rentang yang sama. Tapi kalau kamu cuma perlu cek satu angka sesekali, membangun sieve besar-besar duluan justru sia-sia. Pilihannya bergantung pada pola pemakaian, bukan mana yang "lebih canggih".

// Precompute sekali (sieve)

  • Setup awal O(n log log n), sekali saja.
  • Tiap query sesudahnya jadi O(1) — cukup baca tabel.
  • Cocok saat jumlah query besar & rentang angka diketahui di awal.

// Hitung on-demand tiap query

  • Tidak ada setup awal — langsung jalan.
  • Tiap query O(√n) sendiri-sendiri, menumpuk kalau query-nya banyak.
  • Cocok saat query sedikit atau rentang angka tidak diketahui/berubah-ubah.
◆ Aturan kasarnya

Kalau jumlah query dikalikan biaya per query on-demand lebih mahal dibanding biaya sieve sekali di awal, precompute menang. Untuk soal dengan ribuan query dalam rentang tetap, sieve nyaris selalu lebih murah — tapi ia butuh memori sebesar rentang angkanya, yang bisa jadi masalah sendiri kalau N sangat besar.

◆ Keputusan · Mengenali sinyal soal

Kapan number theory relevan untuk sebuah soal

Sebagian soal problem solving tidak terlihat seperti soal matematika di permukaan, tapi punya sinyal yang jelas begitu kamu tahu ke mana mencarinya.

// Sinyal soal ini butuh number theory

  • Melibatkan bilangan prima, faktor, atau kelipatan.
  • Ada kata "pembagi terbesar" / "kelipatan terkecil".
  • Muncul frasa "jumlah cara mod 10^9+7".
  • Hasil hitungan berpotensi sangat besar (kombinatorial, perpangkatan).
  • Ada pola berulang di interval berbeda (jadwal, siklus).

// Bukan sinyal number theory

  • Soal murni tentang urutan/susunan tanpa aritmatika (lebih ke sorting/searching).
  • Angka kecil & tidak ada risiko overflow sama sekali.
  • Fokusnya struktur data (tree, graph) tanpa hitungan matematis di dalamnya.
◆ Pertanyaan penentu

Tanyakan ke soalmu: "Apakah jawabannya melibatkan pembagi, kelipatan, atau sisa bagi dari angka yang bisa sangat besar?" Kalau ya, kemungkinan besar kamu butuh salah satu dari primality test, GCD/LCM, sieve, atau modular arithmetic — kadang gabungan beberapa sekaligus.

Studi kasus · Di dunia nyata

Di mana number theory benar-benar dipakai di production

Tiga area nyata di mana fondasi matematis ini bukan sekadar latihan soal, tapi menopang sistem yang dipakai jutaan orang setiap hari.

// kriptografi

RSA & enkripsi kunci publik

Kasus: mengamankan komunikasi & transaksi digital. Kenapa number theory: RSA fundamentalnya adalah bilangan prima besar & modular arithmetic — kunci publik/privatnya dibangun dari perkalian dua prima raksasa yang sulit difaktorkan ulang.

// hashing

Hash function & distribusi merata

Kasus: menyebar data secara merata ke dalam hash table agar tabrakan (collision) minim. Kenapa number theory: banyak hash function memakai bilangan prima sebagai ukuran tabel atau pengali, karena sifatnya membantu distribusi yang lebih merata.

// scheduling

Sistem yang berulang di interval berbeda

Kasus: banyak job/proses berjalan berulang dengan periode masing-masing (tiap 12 menit, tiap 18 menit, dst). Kenapa number theory: LCM dipakai untuk menghitung kapan semua jadwal itu akan bertemu/selaras lagi.

◆ Benang merahnya

Di ketiga kasus di atas, angka bukan sekadar angka — sifat matematisnya (prima, pembagi, kelipatan) langsung menentukan keamanan, performa, atau ketepatan sistem. Bukan kebetulan kalau soal-soal number theory terus muncul di problem solving: ia adalah alat yang benar-benar dipakai di production, bukan cuma latihan akademis.

◆ Tips pemula

Kalau baru mulai, jangan buru-buru ke Chinese Remainder Theorem atau modular inverse. Kuasai dulu isPrime(), Euclidean GCD, dan sieve sampai reflex — hampir semua soal number theory tingkat menengah cukup dijawab dengan kombinasi tiga hal itu plus modular arithmetic dasar.

Penutup

Angka besar, aturan kecil, hasil yang tetap benar

Number theory dalam problem solving bukan soal menghafal rumus rumit — ia soal mengenali kapan sebuah masalah sebenarnya adalah masalah pembagi, kelipatan, atau sisa bagi, lalu memakai alat yang sudah terbukti efisien selama ribuan tahun.

  • Primality test O(√n) — cek pembagi cukup sampai akar kuadrat.
  • Euclidean algorithm — gcd(a, b) = gcd(b, a % b), efisien tanpa faktorisasi.
  • Sieve of Eratosthenes — precompute semua prima sekali, pakai berkali-kali.
  • Modular arithmetic — cegah overflow, jaga hasil tetap benar secara matematis.
  • Precompute vs on-demand — pilih sesuai jumlah query, bukan yang "terlihat canggih".
  • Fondasi kriptografi — bilangan prima besar & modular arithmetic menopang keamanan digital.

Aturan emasnya

Begitu soal menyebut pembagi, kelipatan, bilangan prima, atau "mod 10^9+7" — curigai number theory. Batasi pencarian sampai √n, precompute kalau query-nya banyak, dan selalu jaga perkalian tetap di bawah modulo sebelum ia sempat overflow.
