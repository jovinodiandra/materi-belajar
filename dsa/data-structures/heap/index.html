// Data Structures & Algorithms — saat kamu butuh elemen paling ekstrem, terus-menerus

Selalu tahu yang tertinggi/terendah, tanpa harus mengurutkan semuanya.

Bayangkan kamu harus terus-menerus tahu siapa pasien paling kritis di ruang UGD, sementara pasien baru datang & pergi tiap menit. Mengurutkan ulang seluruh antrean tiap kali itu buang-buang waktu. Heap adalah struktur data yang dirancang khusus untuk ini: complete binary tree yang menjaga elemen paling ekstrem selalu ada di puncak, dengan insert & extract secepat O(log n). Deck ini membahas kenapa ia lahir, cara kerjanya, trade-off-nya, sampai kapan dipakai — diselingi kalimat dari buku rujukan.

Sakit
Butuh min/max terus-menerus — sort ulang tiap kali terlalu mahal

Akar masalah · Butuh min/max secepat mungkin

Sort semua data tiap kali cari min itu boros

Kalau kamu punya kumpulan angka dan cuma sesekali butuh yang terkecil, sorting sekali di awal sudah cukup. Masalahnya muncul saat data itu dinamis — elemen baru terus masuk, elemen lama terus diambil, dan tiap saat kamu harus tahu siapa yang paling ekstrem saat ini juga. Sort ulang seluruh koleksi tiap kali ada perubahan adalah pemborosan besar.

◆ Buat apa ini? Kenapa pakai ini?

Given — kamu bangun priority queue pakai array biasa: tiap ada elemen baru masuk, kamu sort() ulang seluruh array supaya elemen terkecil/terbesar selalu ada di depan; atau kamu pakai linked list dan tiap butuh elemen paling ekstrem, kamu scan semua elemen satu-satu.

When — sistem kamu menerima ribuan insert & extract per detik secara bergantian — misalnya task scheduler OS yang terus menerima task baru sambil mengeksekusi task berprioritas tertinggi, atau algoritma Dijkstra yang di tiap langkah harus mengambil node berjarak terpendek dari kumpulan node yang terus berubah.

Then — sort ulang penuh tiap insert costnya O(n log n), scan linear tiap extract costnya O(n) — dikali ribuan operasi, aplikasi jadi lambat drastis, padahal yang sebenarnya kamu butuh cuma tahu satu elemen paling ekstrem tiap saat, bukan urutan lengkap seluruh data.

→ makanya kita pakai Heap.

◆ Analogi — antrean prioritas UGD rumah sakit

Di ruang UGD, pasien tidak dilayani berdasarkan siapa yang datang duluan — pasien paling kritis harus dilayani duluan, siapa pun dia, kapan pun datangnya. Setiap ada pasien baru masuk, petugas triase tidak perlu mengurutkan ulang seluruh daftar pasien dari awal; ia cukup menyisipkan pasien itu ke posisi yang tepat, dan begitu satu pasien selesai ditangani, petugas cukup tahu siapa yang paling kritis berikutnya — tanpa melihat ulang semua orang di ruangan. Itulah persis apa yang dilakukan heap: menjaga "siapa yang paling ekstrem" selalu siap diambil, tanpa harus mengurutkan semuanya.

Struktur data yang menjawab kebutuhan ini disebut priority queue — antrean di mana tiap elemen punya prioritas, dan yang diambil selalu yang berprioritas tertinggi (atau terendah). Heap adalah implementasi klasik & paling umum dari priority queue, karena ia menyeimbangkan dua hal yang sulit dioptimalkan bersamaan: insert yang cepat, dan ambil-yang-paling-ekstrem yang juga cepat.

“Priority queue adalah salah satu tipe data abstrak paling berguna dalam ilmu komputer, dan heap adalah implementasi klasiknya — ia menyeimbangkan kecepatan penyisipan dengan kecepatan mengambil elemen berprioritas tertinggi, dua hal yang sulit dioptimalkan bersamaan lewat struktur data lain.”

— parafrase gagasan Robert Sedgewick & Kevin Wayne, Algorithms
Konsep inti · Heap property & representasi array

Complete tree yang disimpan sebagai array biasa

Heap adalah complete binary tree (semua level terisi penuh, kecuali level terakhir yang terisi dari kiri) yang menjaga satu aturan sederhana — heap property: di min-heap, tiap parent selalu ≤ child-nya (akar = elemen terkecil). Di max-heap, tiap parent selalu ≥ child-nya (akar = elemen terbesar). Yang menarik: karena bentuknya complete tree, heap tidak butuh pointer node sama sekali — cukup disimpan sebagai array. Untuk elemen di indeks i, parent-nya ada di (i-1)/2, anak kirinya di 2i+1, anak kanannya di 2i+2.

“Binary heap dapat dipandang sebagai array yang direpresentasikan hampir sebagai complete binary tree, dan properti heap — nilai sebuah node selalu lebih ekstrem daripada nilai anak-anaknya — memungkinkan operasi extract-min atau extract-max berjalan dalam O(log n), tanpa perlu menyimpan seluruh data dalam keadaan terurut.”

— parafrase gagasan Thomas H. Cormen dkk., Introduction to Algorithms (CLRS)
◆ Kenapa array cukup — tidak butuh pointer
Parentindex (i - 1) / 2
Leftindex 2 * i + 1
Rightindex 2 * i + 2

Karena heap selalu complete tree (tidak ada "lubang" di tengah), posisi tiap node bisa dihitung dari indeksnya saja. Tidak ada pointer left/right yang perlu disimpan — hemat memori & ramah cache dibanding binary tree berbasis node.

Di Java, kamu jarang perlu implementasi heap manual — java.util.PriorityQueue sudah menyediakan min-heap siap pakai. Berikut contoh insert (offer) dan extract-min (poll):

MinHeapDemo.java — insert & extract-min pakai PriorityQueueJava
import java.util.PriorityQueue;

public class MinHeapDemo {
    public static void main(String[] args) {
        // default PriorityQueue di Java = min-heap
        PriorityQueue<Integer> minHeap = new PriorityQueue<>();

        // insert — O(log n), sift-up otomatis
        minHeap.offer(15);
        minHeap.offer(4);
        minHeap.offer(9);
        minHeap.offer(1);

        // peek — lihat elemen terkecil tanpa menghapus, O(1)
        System.out.println("Terkecil saat ini: " + minHeap.peek()); // 1

        // extract-min — O(log n), sift-down otomatis
        while (!minHeap.isEmpty()) {
            System.out.println(minHeap.poll()); // 1, 4, 9, 15 — urut naik
        }
    }
}
Cara kerja · Heapify & kompleksitas

Sift-up saat masuk, sift-down saat keluar

Heap menjaga heap property lewat dua gerakan yang disebut heapify: sift-up (bubble-up) saat insert, dan sift-down (bubble-down) saat extract.

// Sift-up (saat insert)

  • Elemen baru ditaruh di posisi paling akhir array.
  • Bandingkan dengan parent-nya; kalau melanggar heap property, tukar.
  • Ulangi naik ke atas sampai property terpenuhi atau sampai akar.
  • Tinggi tree = log n, jadi maksimal log n pertukaran.

// Sift-down (saat extract)

  • Elemen akar (min/max) diambil & dikembalikan sebagai hasil.
  • Elemen paling akhir dipindah ke akar, ukuran heap berkurang 1.
  • Bandingkan dengan child terkecil/terbesar; tukar kalau perlu, turun terus.
  • Sama-sama maksimal log n langkah.

Karena kedua operasi ini hanya menyentuh satu jalur dari akar ke daun (bukan seluruh data), kompleksitasnya O(log n) — jauh lebih murah daripada mengurutkan ulang semuanya tiap kali ada perubahan. Heap sort memanfaatkan sifat ini: bangun heap dari seluruh data (O(n)), lalu extract berulang kali (O(log n) × n) sampai heap kosong — hasilnya array terurut dalam O(n log n), in-place, tanpa memori tambahan.

naive — sort ulang tiap kali cari minPseudocode
// tiap ada elemen baru / cari min:
data.add(newValue)
data.sort()          // O(n log n) SETIAP KALI
min = data[0]

// n operasi insert+cari-min = O(n^2 log n) total
heap — insert & peek/extract murahPseudocode
// tiap ada elemen baru / cari min:
heap.offer(newValue)  // O(log n) — sift-up
min = heap.peek()     // O(1) — tinggal baca akar
heap.poll()          // O(log n) — sift-down

// n operasi insert+extract = O(n log n) total
◆ Praktik · Cara pakai yang benar

Best practice memakai heap di production

Heap sederhana secara konsep, tapi ada beberapa kebiasaan yang membedakan kode yang aman dari yang rawan bug.

  1. Pakai PriorityQueue built-in, jangan implementasi manual — di production, hampir semua bahasa modern (Java, Python heapq, C++ priority_queue) sudah punya heap teruji & teroptimasi. Implementasi manual cuma masuk akal untuk belajar atau kasus sangat khusus.
  2. Custom Comparator untuk max-heap di Java — default PriorityQueue Java adalah min-heap. Untuk max-heap, pakai new PriorityQueue<>(Comparator.reverseOrder()) alih-alih menegasikan nilai secara manual.
  3. Jangan asumsikan urutan iterasi — meng-iterasi PriorityQueue lewat for-each tidak menjamin urutan terurut. Hanya poll() berulang yang menjamin urutan sesuai prioritas.
  4. Set kapasitas awal kalau ukurannya sudah diketahui — mengurangi resize array internal berulang kali saat insert massal.
  5. Untuk objek kompleks, definisikan Comparable atau Comparator eksplisit — jangan bergantung pada equals()/hashCode(), karena heap hanya peduli urutan, bukan identitas.
  6. Ingat: heap bukan struktur pencarian — mencari elemen sembarang (bukan min/max) tetap O(n). Kalau butuh pencarian cepat sekaligus prioritas, pertimbangkan struktur tambahan seperti indexed heap atau balanced BST.
◆ Jenjang · Dari dasar sampai lanjutan

Tier belajar heap

Heap punya jenjang soal yang jelas — mulai dari operasi dasar, naik ke pola top-K yang sering muncul di interview, sampai teknik lanjutan menggabungkan beberapa heap sekaligus.

Beginner

Operasi dasar

Fokus memahami insert & extract-min/max lewat PriorityQueue bawaan, tanpa perlu tahu detail implementasi internal.

  • Insert & extract-min dasar
  • Peek elemen teratas
  • Min-heap vs max-heap dengan Comparator
Middle

Pola top-K

Menjaga heap berukuran tetap K untuk melacak K elemen paling ekstrem tanpa menyimpan/mengurutkan seluruh data.

  • Kth largest/smallest element
  • Top-K frequent elements
  • K closest points
Advance

Multi-heap & gabungan

Menggabungkan beberapa heap atau mengombinasikan heap dengan struktur lain untuk masalah yang lebih kompleks.

  • Merge K sorted lists
  • Median dari data stream (2 heap)
  • Dijkstra shortest path dengan heap
◆ Harga · Heap vs sorted array

Trade-off: heap dibanding sorted array

Kalau kamu cuma butuh min/max sekali, sorted array baik-baik saja. Bedanya baru terasa saat data itu berubah terus-menerus.

// Heap

  • Insert O(log n) — tidak perlu geser elemen lain.
  • Selalu tahu min/max lewat peek() di O(1).
  • Tidak perlu resort setelah tiap perubahan.
  • Cocok untuk data dinamis & streaming.

// Sorted array

  • Insert O(n) — harus geser elemen supaya tetap terurut.
  • Harus resort penuh kalau banyak elemen berubah sekaligus.
  • Kelebihan: pencarian elemen sembarang O(log n) (binary search) — heap tidak bisa ini.
  • Cocok kalau data jarang berubah & butuh akses terurut penuh.
◆ Intinya

Heap menang saat kebutuhanmu sempit tapi sering: "beri aku yang paling ekstrem, terus-menerus, sambil data terus berubah." Sorted array menang saat kamu butuh seluruh urutan, bukan cuma ujungnya.

◆ Keputusan · Pakai atau jangan

Kapan harus pakai heap

Aturan praktisnya: kalau kamu berulang kali butuh elemen paling ekstrem dari kumpulan data yang terus berubah, pakai heap. Kalau kamu butuh urutan penuh atau pencarian elemen sembarang, jangan.

// Pakai heap saat…

  • Butuh akses min/max berulang kali dari data dinamis.
  • Implementasi priority queue (scheduler, event, job).
  • Soal top-K (K terbesar/terkecil/terdekat).
  • Algoritma graf butuh "ambil node terdekat" (Dijkstra, Prim).
  • Butuh heap sort in-place tanpa memori tambahan.

// Jangan, pilih struktur lain saat…

  • Butuh pencarian elemen sembarang (bukan min/max) — pakai hash table/BST.
  • Butuh seluruh data dalam urutan penuh terus-menerus — pakai sorted array/BST.
  • Butuh range query (elemen antara X dan Y) — heap tidak dirancang untuk ini.
  • Data statis & hanya dibaca sekali — sort sekali sudah cukup.
◆ Pertanyaan penentu

Tanyakan: "Apakah aku terus-menerus butuh elemen paling ekstrem, sambil datanya terus berubah?" Kalau ya → heap. Kalau kamu lebih butuh seluruh data dalam urutan, atau mencari elemen tertentu di tengah — heap bukan alat yang tepat.

Studi kasus · Di dunia nyata

Kapan heap dipakai di production

Tiga skenario nyata di mana heap jadi pilihan struktural, bukan sekadar soal latihan — perhatikan polanya: selalu ada kebutuhan "ambil yang paling prioritas, berulang kali, sambil data berubah."

// operating system

Task scheduler OS

Kasus: sistem operasi harus terus memilih proses mana yang dijalankan berikutnya berdasarkan prioritas, sementara proses baru terus masuk & proses lama selesai. Kenapa heap: priority queue berbasis heap memungkinkan pemilihan proses berprioritas tertinggi tanpa mengurutkan ulang seluruh antrean proses tiap kali ada perubahan.

// graph algorithm

Algoritma Dijkstra

Kasus: mencari jalur terpendek di graf berbobot, di mana algoritma harus berulang kali memilih node belum-dikunjungi dengan jarak sementara terkecil. Kenapa heap: min-heap membuat langkah "ambil node terdekat berikutnya" jadi O(log n), bukan O(n) seperti pencarian linear — inilah yang membuat Dijkstra dengan heap jauh lebih efisien di graf besar.

// simulation

Event-driven simulation

Kasus: simulasi (jaringan, lalu lintas, sistem antrean) yang harus memproses event-event berdasarkan waktu kejadian tercepat, sambil event baru bisa muncul kapan saja selama simulasi berjalan. Kenapa heap: min-heap berdasarkan timestamp menjaga event berikutnya yang harus diproses selalu bisa diambil dalam O(log n).

◆ Benang merahnya

Ketiga kasus di atas punya pola yang sama: ada aliran data yang terus berubah (proses baru, node yang dikunjungi, event baru), dan sistem harus berulang kali menjawab pertanyaan yang sama — "apa yang paling prioritas sekarang?" Itulah tepat celah yang diisi heap.

Penutup

Puncak yang selalu tahu siapa dirinya

Heap lahir dari kebutuhan sederhana: tahu elemen paling ekstrem, secepat mungkin, sambil data terus berubah. Bentuknya complete tree, tempatnya cukup array, dan kecepatannya O(log n) untuk insert maupun extract.

  • Heap property — parent selalu ≤ (min-heap) atau ≥ (max-heap) child-nya.
  • Representasi array — complete tree tanpa perlu pointer node.
  • Sift-up & sift-down — menjaga property tetap valid dalam O(log n).
  • Pakai PriorityQueue built-in — jangan implementasi manual di production.
  • Bukan struktur pencarian — kuat di min/max, lemah di pencarian sembarang.
  • Pilih dari pola akses — butuh ekstrem berulang & dinamis, bukan urutan penuh.

Aturan emasnya

Tanya: "Apakah aku berulang kali butuh elemen paling ekstrem, sambil data terus berubah?" Kalau ya, heap memberimu kecepatan O(log n) tanpa perlu data terurut penuh. Langkah berikutnya: lihat bagaimana heap dipakai bersama struktur graf untuk mencari jalur terpendek.
