Immutable vs Mutable

Mutable: bisa diubah setelah dibuat. Immutable: tidak bisa diubah — kalau perlu beda, buat yang baru.

$ Pensil vs pulpen: tulisan pulpen tidak bisa dihapus diam-diam.

Method hitungDiskon() ternyata diam-diam mengubah harga di keranjang.

Given — satu objek dipakai bersama oleh banyak bagian kode.

When — objek itu bisa diubah oleh siapa saja kapan saja.

→ makanya kita pakai objek immutable — supaya objek tidak bisa diubah diam-diam.

Mutable vs immutable

✗ Mutable (rawan)
class Money {
    long amount;
    void add(long x) { amount += x; }   // mengubah diri
}
Money price = cart.getPrice();
price.add(-5000);   // harga di keranjang ikut berubah!
✓ Immutable (aman)
record Money(long amount) {
    Money add(long x) {
        return new Money(amount + x);   // objek baru
    }
}
Money discounted = cart.price().add(-5000);
// cart.price() tetap sama
Java: record, List.of(). JS: spread {...obj}. const ≠ immutable!

Getter yang membocorkan isi

✗ list asli diberikan
class Order {
  private List<Item> items = new ArrayList<>();
  List<Item> getItems() { return items; }
}
order.getItems().clear();   // ← isi order hilang
                            //   tanpa lewat aturan
✓ salinan / tampilan baca-saja
class Order {
  private final List<Item> items = new ArrayList<>();
  List<Item> getItems() { return List.copyOf(items); }
  void addItem(Item i) { /* cek aturan */ items.add(i); }
}
// atau langsung: record Order(List<Item> items)
//   { Order { items = List.copyOf(items); } }
final mengunci variabelnya, bukan isinya. List final tetap bisa di-clear().
