// Data Structures & Algorithms — struktur data yang cuma mau bicara dengan ujung atasnya

Tumpukan yang selalu ingat siapa yang terakhir naik.

Bayangkan tumpukan piring di dapur restoran: piring baru dicuci ditaruh di atas, dan yang diambil untuk dipakai lagi juga selalu yang paling atas. Itulah stack — struktur data LIFO (Last In, First Out) dengan tiga operasi inti: push (taruh), pop (ambil & buang dari atas), peek (lihat yang teratas tanpa mengambil) — semuanya O(1). Deck ini membahas kenapa stack ada, cara pakainya di Java, sampai kenapa ia diam-diam menopang setiap pemanggilan fungsi di programmu.

Akar masalah · Kenapa stack ada

Kadang urutan yang penting justru urutan mundur

◆ Buat apa ini? Kenapa pakai ini?

Given — kamu bikin fitur undo di text editor, riwayat aksi cuma disimpan berurutan di array biasa dari yang pertama sampai yang terakhir dilakukan.

When — user pencet Ctrl+Z berkali-kali; tiap tekan, aksi yang paling akhir dilakukan itulah yang harus dibatalkan duluan — bukan aksi paling lama.

Then — array biasa tidak "tahu" mana ujung yang benar untuk dibaca; kalau logika ambil-elemennya keliru, urutan pembatalan kebalik — aksi lama ikut ke-undo lebih dulu padahal aksi baru belum disentuh, dan tiap ambil-dari-depan butuh geser sisa elemen satu-satu.

→ makanya kita pakai Stack.

Banyak masalah butuh aturan "yang terakhir masuk, yang pertama keluar": batalkan aksi terakhir dulu (undo), tutup kurung yang paling baru dibuka dulu, selesaikan pemanggilan fungsi paling dalam dulu sebelum kembali ke pemanggilnya. Array biasa tidak punya disiplin ini secara bawaan — kamu perlu struktur yang memaksa urutan itu.

◆ Analogi — tumpukan piring di dapur

Piring bersih ditumpuk satu per satu. Piring yang terakhir ditaruh di atas adalah piring yang pertama diambil lagi saat dibutuhkan — bukan piring paling bawah yang sudah menunggu dari tadi. Kamu tidak bisa asal comot piring dari tengah tumpukan tanpa merobohkan semuanya. Itulah LIFO: satu-satunya pintu masuk sekaligus keluar ada di ujung atas.

Stack mengunci akses hanya di satu ujung. Kelihatannya seperti "keterbatasan", tapi justru itulah yang membuatnya cepat & sederhana — tidak perlu menggeser elemen lain, tidak perlu mencari posisi, cukup sentuh puncaknya.

Konsep inti · Push, pop, peek

Tiga operasi, semuanya O(1)

Stack cuma butuh tiga gerakan: push menaruh elemen baru di puncak, pop mengeluarkan & menghapus elemen puncak, peek (kadang disebut top) mengintip elemen puncak tanpa mengeluarkannya. Tidak ada satu pun yang perlu menggeser elemen lain — makanya ketiganya berjalan dalam waktu konstan.

“Stack adalah struktur data dinamis paling sederhana yang menganut disiplin Last-In, First-Out (LIFO): elemen yang terakhir dimasukkan lewat operasi PUSH adalah elemen pertama yang dikeluarkan lewat operasi POP — keduanya berjalan dalam waktu O(1).”

— parafrase dari Thomas H. Cormen dkk., Introduction to Algorithms (CLRS)
push / pop / peek — Deque sebagai stack (Java modern)Java
import java.util.ArrayDeque;
import java.util.Deque;

public class StackDemo {
    public static void main(String[] args) {
        Deque<Integer> stack = new ArrayDeque<>(); // Deque sebagai stack

        stack.push(10);   // O(1)
        stack.push(20);
        stack.push(30);

        System.out.println(stack.peek()); // 30 — lihat tanpa mengeluarkan
        System.out.println(stack.pop());  // 30 — keluarkan & hapus dari puncak
        System.out.println(stack.pop());  // 20
        System.out.println(stack.isEmpty()); // false — tersisa 10
    }
}

Contoh klasik yang langsung terasa manfaat LIFO-nya: validasi kurung/tanda kurung seimbang. Tiap buka kurung di-push, tiap tutup kurung harus cocok dengan yang paling baru dibuka (pop) — persis logika "tutup dari dalam ke luar".

matching bracket validatorJava
import java.util.ArrayDeque;
import java.util.Deque;
import java.util.Map;

public class BracketValidator {
    static boolean isValid(String s) {
        Deque<Character> stack = new ArrayDeque<>();
        Map<Character, Character> pair = Map.of(')', '(', ']', '[', '}', '{');

        for (char c : s.toCharArray()) {
            if (c == '(' || c == '[' || c == '{') {
                stack.push(c);
            } else if (pair.containsKey(c)) {
                if (stack.isEmpty() || stack.pop() != pair.get(c)) {
                    return false; // tutup tanpa pasangan buka yang cocok
                }
            }
        }
        return stack.isEmpty(); // semua sudah terpasangkan
    }
}
Konsep inti · Call stack & rekursi

Setiap pemanggilan fungsi diam-diam pakai stack

Saat fungsi A memanggil B, runtime bahasa (JVM, dsb.) menaruh stack frame baru berisi variabel lokal & alamat kembali di puncak call stack. Ketika B selesai, frame-nya di-pop dan eksekusi kembali ke A — persis LIFO. Rekursi memanfaatkan mekanisme ini: tiap panggilan diri sendiri menambah frame baru.

“Stack secara alami merepresentasikan struktur pemanggilan fungsi yang bersarang — itulah sebabnya setiap program yang berjalan menyimpan call stack di baliknya, dan memahami stack membantu menjelaskan kenapa rekursi yang terlalu dalam berakhir dengan stack overflow.”

— parafrase dari Robert Sedgewick & Kevin Wayne, Algorithms
rekursi dalam — menumpuk frame tanpa batasJava
static long factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}

// factorial(1_000_000) suatu saat
// -> StackOverflowError
// tiap panggilan nambah 1 frame di call stack thread
iteratif — tanpa menumpuk frame sama sekaliJava
static long factorialIter(int n) {
    long result = 1;
    for (int i = 2; i <= n; i++) {
        result *= i;
    }
    return result;
}

// aman untuk n besar — memori stack tetap datar

Kalau kedalaman rekursi tidak terprediksi (mis. menjelajah pohon/graph yang dalam), pola umum adalah mengganti call stack implisit dengan stack eksplisit yang kamu kendalikan sendiri di heap — bukan di stack memory thread yang terbatas.

DFS rekursif → DFS iteratif dengan stack eksplisitJava
// versi rekursif — mengandalkan call stack JVM
void dfs(Node node, Set<Node> visited) {
    if (visited.contains(node)) return;
    visited.add(node);
    process(node);
    for (Node next : node.neighbors) dfs(next, visited);
}

// versi iteratif — stack eksplisit menggantikan call stack
void dfsIterative(Node start) {
    Deque<Node> stack = new ArrayDeque<>();
    Set<Node> visited = new HashSet<>();
    stack.push(start);

    while (!stack.isEmpty()) {
        Node node = stack.pop();
        if (visited.contains(node)) continue;
        visited.add(node);
        process(node);
        for (Node next : node.neighbors) stack.push(next);
    }
}
◆ Praktik · Best practice

Enam kebiasaan sehat pakai stack di Java

Stack itu sederhana, tapi ada beberapa jebakan klasik — terutama soal kelas mana yang dipakai & batas kedalaman rekursi.

Pakai Deque, bukan class Stack lama

java.util.Stack mewarisi Vector, ter-synchronized (lebih lambat) & API-nya campur aduk dengan method list. ArrayDeque lewat interface Deque lebih cepat & API-nya jelas untuk semantik stack.

Waspada stack overflow di rekursi dalam

Tiap panggilan fungsi menambah frame di call stack thread yang ukurannya terbatas. Rekursi tanpa base case yang benar, atau kedalaman rekursi sebesar input data, bisa menghabiskannya.

Konversi ke iteratif kalau kedalaman tak terprediksi

Untuk pohon/graph yang bisa sangat dalam, ganti rekursi dengan stack eksplisit di heap — ukurannya jauh lebih longgar daripada stack memory thread.

Jangan pakai stack untuk pencarian data

Mencari elemen di tengah stack itu O(n) & merusak urutan kalau dilakukan lewat pop berulang. Kalau butuh akses acak/pencarian, pakai struktur lain (list, map, set).

Perhatikan thread-safety

ArrayDeque tidak thread-safe. Kalau stack diakses dari banyak thread sekaligus, pakai ConcurrentLinkedDeque atau sinkronisasi manual.

Batasi ukuran untuk kasus seperti histori/undo

Stack undo yang tidak dibatasi bisa tumbuh tanpa henti selama sesi aplikasi berjalan. Tetapkan kapasitas maksimum (mis. simpan N langkah terakhir saja) supaya memori terkendali.

◆ Jalur belajar · Tier

Dari push/pop dasar sampai monotonic stack

Progres belajarnya bertahap: kuasai operasi dasar dulu, baru masuk ke pola yang butuh dua stack, lalu ke teknik yang sering muncul di soal wawancara tingkat lanjut.

Beginner

Operasi dasar

Kuasai push/pop/peek dulu sampai reflek, lalu coba soal klasik yang langsung memakainya.

  • Push, pop, peek, isEmpty pakai Deque
  • Validasi kurung seimbang (matching bracket)
  • Balikkan urutan string/array pakai stack
Middle

Dua stack bekerja sama

Naik level: satu stack saja kadang tidak cukup — kombinasikan dua stack untuk logika yang lebih rumit.

  • Evaluate expression/calculator dengan 2 stack (operand & operator)
  • Konversi infix ke postfix (shunting-yard)
  • Evaluasi ekspresi postfix/prefix
Advance

Pola tingkat lanjut

Stack yang "dijaga urutannya" (monotonic) & pengganti rekursi jadi andalan di soal-soal graph/array kompleks.

  • Monotonic stack — "next greater element"
  • DFS iteratif dengan stack eksplisit
  • Largest rectangle in histogram, trapping rain water
◆ Trade-off · LIFO vs FIFO

Stack vs queue: dua ujung, dua filosofi

Stack & queue sama-sama "cuma bisa disentuh dari ujung" dan sama-sama O(1) di operasi intinya — bedanya cuma ujung mana yang jadi pintu keluar. Itu bedanya kecil di kode, tapi besar di jenis masalah yang cocok.

// Stack — LIFO (last in, first out)

  • Undo/redo — batalkan aksi paling baru dulu.
  • Call stack & rekursi — fungsi terdalam selesai duluan.
  • DFS & backtracking — jelajahi satu jalur habis dulu.
  • Matching bracket/syntax — tutup dari dalam ke luar.
  • Tombol "back" di browser — halaman terakhir dulu.

// Queue — FIFO (first in, first out)

  • Antrian tugas/job — yang lebih dulu masuk, lebih dulu diproses.
  • BFS traversal — jelajahi level demi level.
  • Message/task queue antar service — urutan pengiriman terjaga.
  • Print queue / print job — dokumen pertama dicetak duluan.
  • Buffer streaming — data diproses sesuai urutan datang.
◆ Cara cepat memilih

Tanya: "kalau ada beberapa hal menunggu, mana yang harus diproses lebih dulu — yang paling baru masuk, atau yang paling lama menunggu?" Baru → stack. Lama → queue.

◆ Keputusan · Pakai atau jangan

Kapan harus reach for a stack

Stack bersinar begitu urutan mundur atau "kembali ke titik sebelumnya" jadi kebutuhan inti. Di luar itu, biasanya ada struktur lain yang lebih pas.

// Pakai stack saat…

  • Butuh disiplin LIFO eksplisit (undo/redo).
  • Butuh urutan pemrosesan terbalik (matching bracket, evaluasi ekspresi).
  • Melakukan backtracking atau DFS.
  • Menyimpan histori sementara yang dibatalkan urut mundur.
  • Mengubah rekursi jadi iteratif demi kontrol memori.

// Pertimbangkan struktur lain saat…

  • Butuh akses acak ke elemen tengah — pakai array/list.
  • Butuh urutan FIFO — pakai queue.
  • Butuh pencarian cepat by key — pakai map/set.
  • Butuh elemen selalu terurut — pakai heap/tree.
  • Histori bisa tumbuh tak terbatas & perlu ditelusuri jauh ke belakang — pertimbangkan struktur lain atau batasi ukurannya.
◆ Pertanyaan penentu

Tanyakan ke masalahmu: "Apakah aku selalu hanya perlu menyentuh elemen yang paling terakhir masuk?" Kalau ya — stack. Kalau kamu ternyata sering butuh elemen di tengah atau elemen yang paling lama menunggu, stack bukan jawabannya.

Studi kasus · Di dunia nyata

Stack yang bekerja diam-diam di balik layar

Stack jarang terlihat langsung di UI, tapi hampir selalu ada di balik fitur-fitur yang kamu pakai tiap hari.

// runtime bahasa

Call stack di setiap runtime

Kasus: JVM, CPython, V8, dan runtime bahasa lain semuanya menjaga call stack per thread untuk melacak pemanggilan fungsi & jalan kembali (return) setelah selesai. Kenapa stack: pemanggilan fungsi memang bersarang secara alami — LIFO.

// editor / IDE

Undo/redo aplikasi editor

Kasus: tiap aksi edit (ketik, hapus, format) ditaruh di stack undo. Tekan undo → pop aksi paling baru & kembalikan state sebelumnya. Kenapa stack: "batalkan yang paling baru dulu" persis LIFO.

// browser

Tombol back di browser

Kasus: tiap kali membuka halaman baru, URL sebelumnya ditaruh di history stack. Tekan tombol back → pop entri paling atas, kembali ke halaman sebelumnya. Kenapa stack: navigasi mundur mengikuti urutan kunjungan terbalik.

// parser / compiler

Matching syntax di parser

Kasus: compiler & parser memakai stack untuk memastikan kurung, tanda kutip, atau tag HTML/XML dibuka & ditutup dengan pasangan yang benar & urutan yang cocok. Kenapa stack: tag/kurung yang paling baru dibuka harus ditutup lebih dulu.

◆ Benang merahnya

Di semua kasus di atas, polanya sama: ada urutan pembukaan/masuk, dan penutupan/keluarnya harus mengikuti urutan terbalik dari pembukaannya. Begitu pola itu muncul di masalahmu, stack biasanya jadi kandidat pertama.

⚙ Ekosistem · Alat yang dipakai

Tools & referensi buat belajar stack

Tidak perlu library eksternal untuk mulai — di Java cukup dari koleksi bawaan. Yang lebih penting: alat untuk melihat stack bekerja, terutama call stack.

// Java

Deque / ArrayDeque

Interface & implementasi standar Java untuk stack modern. Lebih cepat & lebih jelas semantiknya dibanding class Stack lama.

// visualizer

Visualizer struktur data

Tools visualisasi interaktif (mis. VisuAlgo) menampilkan animasi push/pop & call stack langkah demi langkah — bagus untuk membangun intuisi sebelum menulis kode.

// debugging

Debugger & stack trace

Debugger IDE (IntelliJ, VS Code) menampilkan call stack aktif secara langsung, dan setiap exception di Java membawa stack trace — jejak call stack persis saat error terjadi.

// browser

DevTools — panel Call Stack

Saat men-debug JavaScript, panel "Call Stack" di DevTools browser menunjukkan tumpukan pemanggilan fungsi secara real-time — cara paling nyata melihat konsep stack bekerja.

Penutup

Struktur sederhana yang di mana-mana

Stack cuma punya tiga operasi & satu aturan — LIFO — tapi aturan sesederhana itu ternyata menopang hal-hal yang jauh lebih besar: setiap fungsi yang kamu panggil, setiap undo yang kamu tekan, setiap kurung yang kompilermu validasi.

  • LIFO — yang terakhir masuk, yang pertama keluar.
  • Push, pop, peek — semua O(1), semua menyentuh ujung atas saja.
  • Deque, bukan Stack lama — di Java, ArrayDeque adalah pilihan modern.
  • Call stack = stack sungguhan — di balik tiap pemanggilan fungsi & rekursi.
  • Rekursi dalam → risiko overflow — pertimbangkan stack eksplisit untuk kedalaman besar.
  • Stack vs queue — pilih berdasarkan siapa yang harus diproses lebih dulu: yang baru, atau yang lama.

Aturan emasnya

Tanya: "Apakah aku hanya perlu menyentuh elemen yang paling terakhir masuk, dan urutan keluarnya harus terbalik dari urutan masuknya?" Kalau ya, stack memberimu kesederhanaan & kecepatan O(1) tanpa drama. Kalau yang kamu butuhkan justru urutan yang sama dengan urutan masuknya — saatnya beralih ke struktur data selanjutnya.
