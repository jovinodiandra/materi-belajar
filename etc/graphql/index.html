GraphQL

Client meminta persis field yang dibutuhkan dalam satu request. Tidak kelebihan, tidak kekurangan.

$ Prasmanan: ambil yang kamu mau, bukan paket tetap.

Halaman profil butuh 4 request REST. Satu endpoint mengirim 50 field, yang dipakai 5.

🔁

/user, /user/orders, /user/points, ...

🐘

Kelebihan data (over-fetching)

50 field dikirim, 5 dipakai.

✍️

Endpoint baru untuk tiap layar

Backend terus menambah endpoint khusus.

Minta sesuai kebutuhan

satu query, field pilihan sendiri

◆ Buat apa ini? Kenapa pakai ini?

Given — banyak layar dan aplikasi butuh bentuk data yang berbeda-beda.

When — REST mengirim bentuk tetap, jadi client mengambil terlalu banyak atau harus memanggil berkali-kali.

Then — boros data dan backend terus membuat endpoint khusus.

→ makanya kita pakai GraphQL — supaya client meminta persis apa yang dibutuhkan.

mutation

Mengubah data: mutation

schema
type Mutation {
  addToCart(input: AddToCartInput!): AddToCartPayload!
}
input AddToCartInput { productId: ID!, qty: Int! }
type AddToCartPayload {
  cart: Cart
  errors: [UserError!]!
}
dari client
mutation {
  addToCart(input: { productId: "11", qty: 2 }) {
    cart { totalItems }
    errors { field message }
  }
}
# minta kembali data yang langsung
# dibutuhkan layar
Error bisnis (stok habis) dikembalikan sebagai data, bukan exception.
