Broker Pattern

Pengirim dan penerima tidak perlu saling kenal. Ada perantara di tengah yang menerima, menyimpan, dan meneruskan pesan.

$ Kantor pos: kamu cukup kenal kantor pos, bukan rumah semua orang.

Service saling memanggil langsung. Satu sibuk, yang lain ikut menunggu.

🔗

Semua saling kenal alamat

Pindah server? Semua yang memanggilnya harus diubah.

⏳

Penerima sibuk = pengirim menunggu

Lonjakan trafik membuat semuanya antre.

💥

Penerima mati = pesan hilang

Tidak ada yang menyimpan pesannya.

Ada perantara

titip ke broker, broker yang antar

◆ Buat apa ini? Kenapa pakai ini?

Given — banyak service perlu saling mengirim pesan.

When — mereka memanggil langsung satu sama lain tanpa perantara.

Then — service saling menempel, pesan bisa hilang, dan lonjakan trafik menjatuhkan penerima.

→ makanya kita pakai Broker — supaya pesan dititipkan, disimpan, lalu diantar dengan aman.

bagian 2 · queue vs topic

Queue vs topic

Queue (antrean)Topic (pengumuman)
AnalogiAntrean tiket: satu tiket, satu loketGrup WhatsApp: semua anggota baca
Siapa yang menerimaSatu consumer sajaSemua subscriber
Cocok untukBagi-bagi pekerjaan (kirim email, resize foto)Kabar ke banyak service (OrderCreated)
Queue = bagi pekerjaan. Topic = sebar kabar.
bagian 2 · queue vs topic

Kirim dan terima lewat broker (Spring + RabbitMQ)

✗ Pengirim
@Service
class SignupService {
  void signup(User u) {
    users.save(u);
    rabbit.convertAndSend(
        "email-queue", new WelcomeEmail(u.email()));
    // tidak menunggu email terkirim
  }
}
✓ Penerima
@Component
class EmailWorker {
  @RabbitListener(queues = "email-queue")
  void handle(WelcomeEmail msg) {
    mailer.send(msg.to(), "Selamat datang!");
  }
}
// worker mati? pesan tetap di queue
Pengirim tidak menunggu. Penerima mati? Pesan tetap aman di antrean.

Jebakan yang sering kejadian

jebakan

Pesan dobel

Broker bisa mengirim ulang. Penerima harus idempotent.

jebakan

Pesan beracun

Pesan yang selalu gagal diulang terus. Pindahkan ke dead letter queue.

jebakan

Antrean menumpuk

Pantau panjang antrean. Tambah worker kalau perlu.

jebakan

Simpan + kirim

Simpan DB lalu kirim = dual write. Pakai Outbox.
