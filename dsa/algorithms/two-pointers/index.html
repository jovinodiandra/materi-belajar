Dua index, satu lintasan, tanpa nested loop.

Banyak soal array "cari pasangan" atau "hapus elemen tertentu" mula-mula terasa butuh dua loop bersarang — cek semua kombinasi, O(n²). Padahal kalau datanya terurut atau punya properti tertentu, dua index yang bergerak terkoordinasi lewat array (atau linked list) sudah cukup untuk menjawabnya dalam satu lintasan, O(n). Deck ini buat pemula: dari kenapa two pointers ada, dua pola utamanya (opposite direction & same direction), sampai kapan dipakai di production — diselingi kalimat dari buku rujukan.

Sakit
Brute force nested loop — cek semua pasangan, O(n²)
Ide
Dua index bergerak terkoordinasi — eksploitasi data terurut
Untung
Satu lintasan, O(n) — tanpa memori tambahan
Batas
Butuh properti khusus — terurut / monotonic, tidak universal
Pakai
Two sum, dedup, cycle detection — array terurut & linked list

◆ Buat apa ini? Kenapa pakai ini?

Given — array angka yang sudah terurut (atau linked list), dan tugasnya cari pasangan berjumlah target, buang duplikat, atau deteksi cycle.

When — solusi pertama yang kepikiran: nested loop bandingkan semua kombinasi i, j, atau alokasi hash set tambahan cuma buat lookup tiap elemen.

Then — waktu meledak jadi O(n²) untuk array sebesar jutaan elemen, atau kalaupun dipangkas pakai hash set, tetap boros O(n) memori ekstra — padahal properti "terurut"-nya data (atau struktur linked list-nya) sebenarnya sudah cukup buat menjawabnya tanpa loop bersarang maupun memori tambahan.

→ makanya kita pakai two pointers.

Akar masalah · Nested loop yang boros

Cari pasangan angka berjumlah target — versi naif-nya O(n²)

Soal klasik: diberi array angka terurut, cari dua angka yang jumlahnya sama dengan target. Cara paling gampang kepikiran: coba semua pasangan — loop i dari depan, loop j di dalamnya dari depan lagi, cek tiap kombinasi. Untuk array berisi n elemen, itu berarti sampai n² kali pengecekan — padahal array-nya sudah terurut, informasi yang sebenarnya sangat berharga itu tidak dipakai sama sekali.

“Banyak masalah yang kelihatannya butuh memeriksa semua pasangan elemen — nested loop, O(n²) — sebenarnya bisa diselesaikan dalam O(n) kalau kita mengeksploitasi properti terurut dari data lewat dua pointer yang bergerak secara terkoordinasi, bukan memeriksa semua kombinasi satu per satu.”

— parafrase dari Steven S. Skiena, The Algorithm Design Manual
◆ Analogi — dua orang jalan dari ujung berlawanan menuju tengah

Bayangkan sebuah lorong panjang berisi angka-angka yang sudah berbaris rapi dari kecil ke besar. Alih-alih satu orang berjalan bolak-balik memeriksa setiap kombinasi dua angka (capek & lama), kirim dua orang: satu mulai dari ujung kiri (angka terkecil), satu dari ujung kanan (angka terbesar). Mereka berjalan saling mendekat ke tengah, dan di tiap langkah cukup lihat jumlah posisi mereka berdua untuk tahu harus siapa yang maju. Tak perlu memeriksa ulang pasangan yang sudah jelas tidak mungkin — satu lintasan sudah cukup.

Inilah inti two pointers: dua index (bukan dua nested loop independen) yang bergerak melalui data — biasanya array terurut — dengan aturan pergerakan yang saling terkait, sehingga tiap elemen paling banter dikunjungi beberapa kali saja, bukan dikombinasikan dengan semua elemen lain.

Konsep inti · Pola pertama

Opposite direction — dua pointer dari kedua ujung

Pola paling umum: left mulai di index 0, right mulai di index terakhir. Keduanya bergerak saling mendekat ke tengah. Di tiap langkah, bandingkan arr[left] + arr[right] dengan target — kalau kurang, left++ (butuh angka lebih besar); kalau lebih, right-- (butuh angka lebih kecil); kalau pas, ketemu.

TwoSumSorted.java — two sum di array terurutJava
public class TwoSumSorted {

    // arr sudah terurut naik. return index [i, j] atau null kalau tak ada.
    static int[] twoSum(int[] arr, int target) {
        int left = 0, right = arr.length - 1;
        while (left < right) {
            int sum = arr[left] + arr[right];
            if (sum == target) {
                return new int[] { left, right };
            } else if (sum < target) {
                left++;   // butuh angka lebih besar
            } else {
                right--;  // butuh angka lebih kecil
            }
        }
        return null; // tidak ada pasangan
    }

    public static void main(String[] args) {
        int[] arr = { 1, 3, 5, 7, 9, 12 };
        System.out.println(java.util.Arrays.toString(twoSum(arr, 12))); // [1, 3] -> 3+9
    }
}

Kenapa ini benar? Karena array-nya terurut, kalau arr[left] + arr[right] sudah kurang dari target, menggeser right ke kiri (mengecilkan) tidak akan pernah membantu — jumlahnya cuma makin kecil. Satu-satunya arah yang masuk akal adalah menaikkan left. Logika simetris berlaku untuk kasus lebih. Setiap langkah membuang satu kemungkinan yang pasti gagal, bukan menebak-nebak.

◆ Kompleksitas — brute force vs two pointers
Naifnested loop semua pasangan → O(n²) waktu
Two ptrleft & right saling mendekat → O(n) waktu, O(1) memori

Setiap pointer bergerak searah & total pergerakan maksimum n langkah gabungan (left maju sampai n kali, right mundur sampai n kali) — bukan n dikali n. Itulah sumber penurunan dari O(n²) ke O(n).

Konsep inti · Pola kedua

Same direction — fast & slow pointer

Pola kedua: kedua pointer bergerak ke arah yang sama, tapi dengan kecepatan berbeda. Satu pointer "lambat" menandai posisi yang sudah pasti valid, satu pointer "cepat" menjelajah lebih dulu untuk mencari elemen berikutnya yang perlu diproses. Varian populer pola ini adalah sliding window (dibahas terpisah) — jendela dengan dua batas yang sama-sama bergerak maju.

RemoveDuplicates.java — hapus duplikat in-place, array terurutJava
public class RemoveDuplicates {

    // arr terurut naik. kembalikan panjang bagian unik di depan array (in-place).
    static int removeDuplicates(int[] arr) {
        if (arr.length == 0) return 0;
        int slow = 0; // batas terakhir elemen unik
        for (int fast = 1; fast < arr.length; fast++) {
            if (arr[fast] != arr[slow]) {
                slow++;
                arr[slow] = arr[fast]; // pindahkan elemen unik ke depan
            }
        }
        return slow + 1; // panjang bagian unik
    }
}

fast menjelajah tiap elemen sekali; slow hanya maju saat menemukan elemen baru yang benar-benar unik. Karena array sudah terurut, duplikat pasti bersebelahan — cukup satu lintasan, tanpa struktur data tambahan.

Varian same-direction yang lebih terkenal: Floyd's cycle detection ("tortoise and hare") untuk mendeteksi siklus di linked list. slow melangkah satu node, fast melangkah dua node per iterasi — kalau ada siklus, fast pasti akan "menyusul dari belakang" dan bertemu slow lagi.

“Teknik fast-slow pointer — juga dikenal sebagai tortoise and hare — adalah cara elegan mendeteksi siklus dalam struktur data linked tanpa memori tambahan, karena pointer yang bergerak lebih cepat pasti akan bertemu pointer yang lebih lambat jika memang ada siklus.”

— parafrase dari Robert Sedgewick & Kevin Wayne, Algorithms
CycleDetection.java — Floyd's tortoise and hareJava
class Node { int val; Node next; }

public class CycleDetection {
    static boolean hasCycle(Node head) {
        Node slow = head, fast = head;
        while (fast != null && fast.next != null) {
            slow = slow.next;         // 1 langkah
            fast = fast.next.next;    // 2 langkah
            if (slow == fast) return true; // bertemu -> ada siklus
        }
        return false; // fast mencapai null -> tidak ada siklus
    }
}
brute force — cek semua pasangan node (bad)Pseudocode
// simpan setiap node yang sudah dikunjungi ke Set,
// atau bandingkan tiap node dengan semua node sebelumnya
for node in list:
    for visited in list_visited_so_far:
        if node == visited: return true
// O(n²) waktu tanpa Set, atau O(n) memori tambahan dengan Set
two pointers — fast & slow (good)Pseudocode
slow = head; fast = head
while fast and fast.next:
    slow = slow.next
    fast = fast.next.next
    if slow == fast: return true
// O(n) waktu, O(1) memori tambahan — tanpa Set
◆ Praktik · Kebiasaan aman menulis two pointers

Best practice memakai two pointers

Beberapa kebiasaan ini akan menyelamatkanmu dari bug two pointers yang paling umum — dari infinite loop sampai jawaban yang salah karena invariant keliru.

  1. Pastikan datanya terurut (atau punya properti monotonic) untuk pola opposite-direction — tanpa itu, keputusan "geser left" atau "geser right" tidak lagi valid.
  2. Tentukan invariant yang jelas sebelum menulis loop — apa yang selalu benar tiap iterasi? (mis. "semua pasangan di luar [left, right] sudah pasti bukan solusi").
  3. Pastikan pointer bergerak searah invariant — tiap iterasi harus membuat progres nyata (left naik, right turun, atau fast maju), bukan diam di tempat, supaya loop pasti berhenti.
  4. Cek kondisi berhenti dengan hati-hati — left < right vs left <= right sering jadi sumber off-by-one, terutama saat elemen tengah perlu ditangani khusus.
  5. Tangani duplikat & edge case eksplisit — array kosong, satu elemen, semua elemen sama; soal seperti 3Sum butuh skip duplikat manual supaya tidak menghasilkan pasangan berulang.
  6. Untuk linked list, selalu cek null sebelum .next — fast.next.next tanpa cek fast != null && fast.next != null akan crash dengan NullPointerException.
◆ Roadmap · Bertahap sesuai levelmu

Tier belajar two pointers

Two pointers punya banyak variasi — mulai dari pola dua-ujung yang paling dasar, sampai kombinasi dengan sorting & struktur data lain. Berikut jalurnya dari dasar sampai lanjut.

Beginner

Dua pointer, satu array terurut

Mulai dari pola opposite-direction paling dasar pada array yang sudah terurut.

  • Two sum di array terurut
  • Remove duplicates in-place
  • Cek apakah array punya pasangan dengan selisih tertentu
  • Reverse array in-place pakai dua pointer
Middle

Kombinasi & optimasi luas area

Menggabungkan two pointers dengan sorting atau perluasan ke tiga elemen sekaligus.

  • 3Sum (sort + two pointers per elemen tetap)
  • Container With Most Water
  • Palindrome check pada string
  • Sort colors / partisi array (Dutch flag)
Advance

Fast-slow & struktur linked

Di level ini, two pointers dipakai pada struktur data yang tidak sesederhana array biasa.

  • Fast-slow pointer untuk cycle detection
  • Cari titik tengah linked list dalam satu lintasan
  • Merge dua sorted array/list in-place
  • Deteksi titik awal siklus (Floyd's, fase kedua)
◆ Harga · Two pointers vs brute force

Trade-off: O(n) cepat, tapi butuh prasyarat

Two pointers bukan solusi ajaib untuk semua soal array — ia menang telak saat prasyaratnya terpenuhi, dan tidak berlaku begitu saja kalau tidak.

// Yang kamu dapat

  • Kompleksitas waktu turun dari O(n²) ke O(n).
  • Biasanya O(1) memori tambahan — tanpa hash set/map.
  • Kode relatif ringkas & mudah dibuktikan benar lewat invariant.
  • Alami untuk operasi in-place (hemat memori sekaligus).

// Yang kamu korbankan / butuhkan

  • Butuh data terurut atau punya properti monotonic — kalau belum, harus sort dulu (O(n log n)).
  • Tidak semua soal punya struktur yang cocok dipetakan ke dua pointer.
  • Invariant yang salah gampang menghasilkan bug halus (off-by-one, kelewat elemen).
  • Untuk kasus non-monotonic, hash map/set kadang justru lebih langsung dipakai.
◆ Soal biaya sorting

Kalau array-mu belum terurut, biaya sort() sebesar O(n log n) tetap harus dibayar di depan sebelum two pointers bisa dipakai. Total tetap O(n log n), bukan O(n) murni — tapi ini masih lebih baik dibanding brute force O(n²) untuk n yang besar, dan seringnya array memang sudah terurut atau perlu diurutkan untuk alasan lain juga.

◆ Keputusan · Pakai atau jangan

Kapan harus pakai two pointers

Aturan praktisnya: kalau soalnya melibatkan array terurut dan mencari pasangan/triplet, atau linked list dan perlu mendeteksi siklus/titik tengah, two pointers biasanya jawaban paling ringkas.

// Pakai two pointers saat…

  • Array/string sudah terurut & kamu cari pasangan/triplet dengan kondisi jumlah/selisih.
  • Perlu menghapus/menyusun ulang elemen in-place tanpa memori tambahan.
  • Bekerja dengan linked list & perlu deteksi siklus atau titik tengah.
  • Soal terasa seperti "geser dua batas mendekat/searah" secara alami.

// Pertimbangkan lain saat…

  • Data tidak terurut & tidak ada properti monotonic yang bisa dieksploitasi.
  • Butuh mencari berdasarkan kunci arbitrer → hash map/set lebih langsung.
  • Relasi antar elemen tidak linear (mis. graph umum, bukan sekadar list/array).
  • Soal butuh melihat semua subset/kombinasi, bukan pasangan berurutan.
◆ Pertanyaan penentu

Tanyakan ke soalmu: "Apakah data ini terurut (atau bisa diurutkan) dan aku mencari pasangan/kondisi antar elemen, atau apakah ini linked list yang butuh dua kecepatan berbeda?" Kalau ya, two pointers biasanya memangkas kompleksitas secara signifikan dibanding brute force.

Studi kasus · Di dunia nyata

Di mana two pointers benar-benar dipakai di production

Tiga contoh nyata di mana two pointers bukan sekadar latihan interview, tapi jadi fondasi operasi yang sering berjalan di balik layar sistem produksi.

// log processing

Merge dua log file terurut waktu

Kasus: menggabungkan dua file log yang masing-masing sudah terurut berdasarkan timestamp menjadi satu urutan gabungan yang tetap terurut. Kenapa two pointers: ini persis merge step pada merge sort — satu pointer di tiap file, ambil yang timestamp-nya lebih kecil, majukan pointer itu — fondasi dari algoritma merge sort itu sendiri.

// dependency graph

Deteksi siklus di struktur linked/dependency

Kasus: memeriksa apakah rantai referensi/dependency (mis. linked structure antar objek, atau rantai "next pointer" custom) mengandung siklus yang bisa menyebabkan infinite loop atau memory leak. Kenapa two pointers: fast-slow pointer (Floyd's) mendeteksi siklus tanpa memori tambahan untuk menyimpan node yang sudah dikunjungi.

// data pipeline

Deduplikasi data terurut di pipeline

Kasus: data yang sudah terurut (mis. hasil query terurut by key, atau batch yang diproses berurutan) perlu dibuang duplikatnya sebelum ditulis ke tahap berikutnya. Kenapa two pointers: pola same-direction (slow/fast) membuang duplikat yang bersebelahan dalam satu lintasan, in-place, tanpa struktur data tambahan.

◆ Benang merahnya

Di ketiga kasus di atas, datanya sudah terurut atau punya struktur linear yang jelas — timestamp log, rantai node, hasil query terurut. Two pointers cuma mengeksploitasi properti itu; ia bukan solusi ajaib untuk data acak tanpa struktur.

Penutup

Eksploitasi struktur data, jangan cek semua kombinasi

Two pointers lahir dari pengamatan sederhana: kalau data sudah terurut atau punya properti monotonic, kita tidak perlu memeriksa semua pasangan — dua index yang bergerak terkoordinasi sudah cukup. Ia bersinar di array terurut & linked list, dan tersandung kalau prasyarat terurut/monotonic-nya tidak terpenuhi.

  • Nested loop = O(n²) — brute force cek semua pasangan.
  • Opposite direction — dua pointer dari ujung berlawanan, saling mendekat.
  • Same direction — fast & slow pointer, termasuk varian sliding window.
  • Butuh data terurut/monotonic — prasyarat, bukan jaminan universal.
  • O(n) waktu, O(1) memori — satu lintasan, tanpa struktur tambahan.
  • Fondasi teknik lain — merge step, sliding window, cycle detection.

Aturan emasnya

Sebelum menulis nested loop, tanyakan: apakah datanya terurut, atau bisa diurutkan dengan biaya wajar? Kalau ya, dua pointer yang bergerak dengan invariant yang jelas — searah atau berlawanan arah — hampir selalu memangkas kompleksitas dari kuadratik ke linear.
