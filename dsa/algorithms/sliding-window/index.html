// DSA — Algorithms · teknik dua pointer untuk subarray/substring kontigu

Jendela yang bergeser, bukan dihitung ulang dari nol tiap posisi.

Banyak soal minta kamu mencari subarray atau substring kontigu dengan sifat tertentu — jumlah maksimum ukuran K, substring terpanjang tanpa karakter berulang. Cara paling naif: hitung ulang tiap posisi dari nol. Tapi antar posisi yang berdekatan, sebagian besar isi jendela itu sama saja — cuma satu elemen keluar, satu elemen masuk. Sliding window memanfaatkan itu: menjaga satu jendela yang membesar/mengecil secara dinamis di atas array/string, tanpa mengulang kerja yang sudah dilakukan. Deck ini buat pemula: dari kenapa ia ada, fixed vs variable window, sampai kapan dipakai di production — diselingi kalimat dari buku rujukan.

Sakit
Recompute tiap posisi — O(n·k) atau O(n²), padahal banyak kerja terulang
Ide
Geser jendela — buang elemen lama, tambah elemen baru
Untung
O(n) — tiap elemen masuk & keluar jendela paling banyak satu kali
Batas
Hanya kontigu — khusus subarray/substring berurutan, bukan subsequence
Pakai
Rate limiting, buffering, moving average — rentang berurutan yang bergerak

◆ Buat apa ini? Kenapa pakai ini?

Given — kamu punya array/string dan diminta cari sesuatu di semua subarray/substring kontigu berukuran tertentu (jumlah maksimum window K, substring terpanjang tanpa karakter berulang), lalu ditulis dengan menghitung ulang seluruh isi window dari nol di tiap posisi awal.

When — array/string-nya besar dan window itu digeser satu-per-satu sepanjang seluruh data, padahal antar posisi yang berdekatan isi window sebagian besar sama, cuma satu elemen keluar dan satu elemen masuk.

Then — kerja yang sama dihitung ulang sia-sia, kompleksitas melar jadi O(n·k) atau bahkan O(n²), dan program jadi lambat atau timeout begitu input-nya besar.

→ makanya kita pakai Sliding Window.

Akar masalah · Kerja berulang yang terbuang

Brute force menghitung ulang hal yang sama berkali-kali

Bayangkan soal: cari jumlah maksimum dari subarray sepanjang K di sebuah array. Cara paling naif: untuk tiap posisi awal, jumlahkan K elemen dari situ. Itu O(k) kerja per posisi, dikali n posisi → O(n·k). Untuk substring, versi naifnya malah bisa O(n²) atau lebih — cek ulang setiap kombinasi awal-akhir dari nol.

◆ Analogi — jendela kereta yang bergerak

Duduk di kereta yang berjalan, kamu melihat pemandangan lewat jendela. Pemandangan itu tidak berganti total tiap detik — sebagian besar yang kamu lihat sekarang sama dengan sedetik lalu, cuma satu sisi hilang di belakang dan satu sisi baru muncul di depan. Kamu tidak perlu "memuat ulang" seluruh pemandangan dari nol tiap detik; kamu cukup memperbarui apa yang berubah di tepi jendela.

“Banyak algoritma efisien lahir dari mengenali bahwa pekerjaan yang dilakukan berulang di antara iterasi yang berdekatan bisa dipertahankan secara incremental, bukan dihitung ulang dari nol setiap kali.”

— parafrase dari Steven Skiena, The Algorithm Design Manual

Sliding window adalah contoh konkret dari prinsip itu, diterapkan khusus pada subarray/substring kontigu: alih-alih menghitung ulang seluruh isi jendela tiap kali posisinya bergeser satu langkah, kamu cukup membuang kontribusi elemen yang keluar dan menambah kontribusi elemen yang masuk. Kerja per langkah turun dari O(k) menjadi O(1) — total jadi O(n).

Konsep inti · Fixed-size window

Ukuran jendela tetap, isinya yang bergeser

Bentuk paling sederhana: jendela punya ukuran tetap K. Contoh klasik: cari jumlah maksimum dari subarray sepanjang K. Hitung jumlah jendela pertama sekali, lalu tiap geser satu langkah ke kanan, kurangi elemen yang keluar & tambah elemen yang masuk — tak perlu menjumlahkan ulang seluruh K elemen.

MaxSumFixedWindow.java — jumlah maksimum subarray ukuran KJava
public class MaxSumFixedWindow {

    static int maxSumSubarray(int[] arr, int k) {
        int windowSum = 0;
        for (int i = 0; i < k; i++) {
            windowSum += arr[i];              // isi jendela pertama, sekali saja
        }
        int maxSum = windowSum;

        for (int i = k; i < arr.length; i++) {
            windowSum += arr[i] - arr[i - k]; // masuk satu, keluar satu — O(1)
            maxSum = Math.max(maxSum, windowSum);
        }
        return maxSum;
    }

    public static void main(String[] args) {
        int[] arr = { 2, 1, 5, 1, 3, 2 };
        System.out.println(maxSumSubarray(arr, 3)); // 9 → [5,1,3]
    }
}
◆ Kompleksitas: brute force vs sliding window
Brutehitung ulang K elemen tiap posisi → O(n · k)
Slidingupdate O(1) tiap geser, total → O(n)

Perbedaannya makin terasa saat K besar — brute force melambat sebanding K, sliding window tetap linear terhadap n berapa pun K-nya.

Konsep inti · Variable-size window

Ukurannya berubah dinamis — expand & shrink

Sebagian soal tidak punya ukuran jendela tetap — jendelanya harus membesar selama kondisi masih valid, dan mengecil begitu kondisi dilanggar. Pola ini pakai dua pointer, left & right: right selalu maju untuk memperluas jendela, left maju untuk mempersempitnya saat perlu.

LongestUniqueSubstring.java — substring terpanjang tanpa karakter berulangJava
import java.util.HashSet;
import java.util.Set;

public class LongestUniqueSubstring {

    static int lengthOfLongestSubstring(String s) {
        Set<Character> window = new HashSet<>();
        int left = 0, maxLen = 0;

        for (int right = 0; right < s.length(); right++) {
            char c = s.charAt(right);
            while (window.contains(c)) {      // shrink sampai valid lagi
                window.remove(s.charAt(left));
                left++;
            }
            window.add(c);                     // expand
            maxLen = Math.max(maxLen, right - left + 1);
        }
        return maxLen;
    }

    public static void main(String[] args) {
        System.out.println(lengthOfLongestSubstring("abcabcbb")); // 3 → "abc"
    }
}

Tiap karakter cuma masuk jendela sekali lewat right, dan keluar paling banyak sekali lewat left — total pergerakan kedua pointer terbatas 2n, bukan bertumpuk kombinasi i,j.

brute force — cek ulang tiap kombinasi (i, j)Java
static int lengthOfLongestSubstring(String s) {
    int maxLen = 0;
    for (int i = 0; i < s.length(); i++) {
        for (int j = i; j < s.length(); j++) {
            if (isAllUnique(s, i, j)) {   // cek ulang dari nol tiap (i,j)
                maxLen = Math.max(maxLen, j - i + 1);
            }
        }
    }
    return maxLen;
}
// O(n^2) kombinasi, tiap cek isAllUnique bisa O(n) lagi → O(n^3)
sliding window — left/right, tanpa cek ulangJava
static int lengthOfLongestSubstring(String s) {
    Set<Character> window = new HashSet<>();
    int left = 0, maxLen = 0;
    for (int right = 0; right < s.length(); right++) {
        while (window.contains(s.charAt(right))) {
            window.remove(s.charAt(left++));
        }
        window.add(s.charAt(right));
        maxLen = Math.max(maxLen, right - left + 1);
    }
    return maxLen;
}
// tiap karakter masuk & keluar HashSet paling banyak 1x → O(n)
◆ Praktik · Kebiasaan aman menulis sliding window

Best practice menulis sliding window

Sliding window terasa mudah begitu paham polanya, tapi gampang salah kalau kondisi shrink-nya kabur. Beberapa kebiasaan ini membantu kamu menulisnya dengan benar sejak awal.

  1. Identifikasi dulu kondisi kapan window harus shrink — tulis eksplisit "jendela tidak valid ketika ...", baru terjemahkan jadi while yang menggeser left.
  2. Pakai hash map/set untuk melacak isi jendela — frekuensi karakter, elemen unik, atau jumlah kejadian; ini yang membuat cek validitas jendela jadi O(1) alih-alih O(k).
  3. Jaga invariant window tetap jelas — pastikan di setiap iterasi, sebelum kamu membaca hasil (misal maxLen), jendela [left, right] sudah dalam keadaan valid.
  4. Update state saat elemen masuk & keluar, jangan hitung ulang — tiap kali right maju atau left maju, cukup ubah kontribusi satu elemen itu ke total/set/map.
  5. Untuk fixed-size window, inisialisasi jendela pertama secara terpisah — baru mulai loop geser dari elemen ke-K, supaya tidak ada pengecekan kondisi ukuran di tiap iterasi.
  6. Uji dengan edge case — string/array kosong, K lebih besar dari panjang array, seluruh elemen sama, seluruh elemen unik.
◆ Roadmap · Bertahap sesuai levelmu

Tier belajar sliding window

Mulai dari jendela ukuran tetap yang paling sederhana, lalu naik ke jendela dinamis dengan kondisi majemuk, sampai varian yang butuh struktur data tambahan seperti monotonic deque.

Beginner

Fixed-size window

Jendela berukuran tetap — cukup update saat satu elemen keluar & satu elemen masuk.

  • Max sum subarray ukuran K
  • Rata-rata tiap subarray ukuran K
  • Cek apakah ada subarray ukuran K dengan sifat tertentu
Middle

Variable-size window

Jendela membesar & mengecil dinamis, dipandu satu kondisi validitas yang jelas.

  • Longest substring tanpa duplikat
  • Minimum window substring
  • Longest subarray dengan jumlah ≤ target
  • Subarray dengan tepat K elemen berbeda
Advance

Window dengan struktur data tambahan

Jendela dikombinasikan dengan struktur data lain untuk menjawab query yang lebih kompleks.

  • Sliding window maximum (monotonic deque)
  • Multiple constraint window (dua+ kondisi sekaligus)
  • Sliding window dengan frequency map ketat
◆ Harga · Cepat, tapi tidak untuk segalanya

Trade-off: O(n) yang hebat, tapi terbatas kontigu

Sliding window memangkas kompleksitas secara dramatis — tapi hanya berlaku untuk masalah yang memang berbentuk subarray/substring kontigu. Salah kenali bentuk soal, dan teknik ini tidak bisa dipaksakan.

// Yang kamu dapat

  • Turun dari O(n·k)/O(n²) ke O(n).
  • Tiap elemen diproses masuk & keluar jendela terbatas (paling banyak sekali).
  • Memori tambahan kecil — cukup jumlah/hash map isi jendela.
  • Pola yang sama dipakai berulang di banyak soal string/array.

// Yang kamu korbankan

  • Hanya untuk data kontigu — tidak berlaku untuk subsequence (boleh loncat).
  • Butuh invariant/kondisi shrink yang benar-benar jelas, atau hasilnya salah diam-diam.
  • Untuk kondisi majemuk, tracking state jendela bisa jadi rumit.
  • Tidak semua soal "maksimum/minimum" otomatis bisa di-sliding-window-kan.

“Teknik dua pointer yang membentuk sebuah ‘jendela’ bergerak adalah pola desain algoritma yang berulang muncul di banyak masalah string & array — mengenali pola ini membantu mengubah solusi kuadratik menjadi linear tanpa mengorbankan kebenaran.”

— parafrase dari Robert Sedgewick & Kevin Wayne, Algorithms
◆ Keputusan · Pakai atau jangan

Kapan harus pakai sliding window

Sinyal paling jelas ada di kalimat soalnya sendiri. Kalau kamu menemukan kombinasi kata ini, curigai sliding window sebagai kandidat solusi.

// Sinyal: pakai sliding window

  • Kata "subarray" atau "substring" — artinya kontigu, bukan subsequence.
  • Digabung kata "maksimum"/"minimum"/"terpanjang"/"terpendek".
  • Ada batasan ukuran tetap K, atau kondisi validitas yang bisa dicek incremental.
  • Brute force natural-nya berbentuk dua loop bersarang di atas rentang yang sama.

// Sinyal: JANGAN pakai sliding window

  • Kata "subsequence" — elemen boleh tidak berurutan/loncat, bukan kontigu.
  • Relasi antar elemen tidak monoton (menambah elemen bisa membuat jendela "lebih valid").
  • Butuh mengingat kombinasi bukan-jendela, mis. semua pasangan index tanpa syarat berurutan.
  • Soal graph/tree yang tidak berbentuk rentang linear.
◆ Pertanyaan penentu

Tanyakan ke soalmu: "Apakah bagian yang dicari harus berurutan (kontigu) di array/string aslinya?" Kalau ya, dan ada sifat "maksimum/minimum/terpanjang/terpendek" yang menyertainya, sliding window kemungkinan besar berlaku. Kalau elemen boleh loncat-loncat (subsequence), sliding window tidak berlaku — butuh teknik lain seperti dynamic programming.

Studi kasus · Di dunia nyata

Di mana sliding window benar-benar dipakai di production

Tiga contoh nyata di mana "jendela rentang waktu/data yang bergerak" bukan sekadar soal latihan, tapi memang bentuk alami dari masalahnya.

// API

Rate limiting

Kasus: membatasi berapa banyak request yang boleh masuk dari satu klien dalam rentang waktu tertentu, mis. "maksimum 100 request per menit". Kenapa sliding window: yang dihitung adalah request dalam jendela waktu bergerak — request lama di luar rentang otomatis "keluar" dari hitungan seiring waktu berjalan.

// networking

Network buffering & streaming

Kasus: memproses data streaming (video, sensor, paket jaringan) yang datang terus-menerus, tapi diproses per-batch dari sebuah buffer berukuran terbatas. Kenapa sliding window: buffer itu sendiri adalah jendela — data lama digeser keluar begitu data baru masuk, tanpa memuat ulang seluruh stream dari awal.

// observability

Monitoring metrik

Kasus: menghitung moving average atau agregat metrik (CPU usage, latency, error rate) dalam rentang waktu tertentu yang terus bergerak seiring waktu. Kenapa sliding window: nilai agregat di-update incremental tiap titik data baru masuk & titik data terlama keluar dari rentang.

◆ Benang merahnya

Di ketiga kasus di atas, yang diproses adalah rentang berurutan yang bergerak seiring waktu/posisi — bukan kumpulan data statis yang dihitung ulang total tiap kali. Sifat inilah yang membuat sliding window relevan di luar soal algoritma: dari infrastruktur (rate limiting), sistem terdistribusi (streaming), sampai observability (moving average).

Penutup

Geser jendelanya, jangan hitung ulang dari nol

Sliding window lahir dari pengamatan sederhana: antar posisi yang berdekatan, isi jendela hampir sama — cuma tepinya yang berubah. Ia bersinar untuk subarray/substring kontigu, dan tersandung begitu soalnya bukan lagi tentang rentang berurutan.

  • Kerja incremental — jangan hitung ulang, cukup update tepi jendela.
  • Fixed-size — ukuran tetap, satu masuk satu keluar.
  • Variable-size — expand dengan right, shrink dengan left.
  • Invariant jelas — tahu persis kapan jendela valid/tidak valid.
  • Hanya kontigu — bukan untuk subsequence yang boleh loncat.
  • O(n) — tiap elemen diproses terbatas, bukan berulang-ulang.

Aturan emasnya

Kalau soalnya minta subarray/substring kontigu dengan sifat maksimum, minimum, terpanjang, atau terpendek — curigai sliding window. Definisikan dulu kapan jendela shrink, jaga invariant-nya, dan biarkan left/right melakukan sisanya tanpa pernah menghitung ulang dari awal.
