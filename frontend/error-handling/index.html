◆ Buat apa ini? Kenapa pakai ini?

Given — aplikasi frontend berjalan di jutaan browser yang berbeda.

When — error tidak ditangkap, tidak dibatasi, dan tidak dicatat.

Then — user melihat layar putih dan tim tidak tahu ada masalah.

→ makanya kita pakai error handling di frontend — supaya kerusakan terbatas dan tim langsung tahu.

warm-up

Error apa yang tidak tertangkap?

try {
  fetch("/api/orders").then(r => r.json()).then(render);
} catch (e) {
  showError(e);   // ← apakah ini akan jalan?
}
  • Kalau API mati, apakah showError terpanggil?
ide dasar

Error boundary di React

<ErrorBoundary
  fallback={<p>Rekomendasi gagal dimuat.
             <button onClick={retry}>Coba lagi</button></p>}
  onError={(err) => Sentry.captureException(err)}
>
  <Recommendations />   {/* kalau error, hanya bagian ini yang diganti */}
</ErrorBoundary>

Gampangnya

  • Error di dalam batas tidak menular ke luar.
  • User melihat pesan + tombol coba lagi.
  • Error dikirim ke alat monitoring (Sentry).
Bagian rusak diganti pesan. Halaman lain tetap jalan.

salah → benar

await di dalam try

✗ try tidak menunggu
try {
  fetch(url).then(r => r.json());
} catch (e) {
  // tidak pernah sampai sini
}
✓ await + cek status
try {
  const res = await fetch(url);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  render(await res.json());
} catch (e) {
  showError("Gagal memuat pesanan", e);
}
Promise tanpa await atau .catch = error yang hilang tanpa jejak.
