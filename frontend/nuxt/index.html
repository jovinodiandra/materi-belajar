◆ Buat apa ini? Kenapa pakai ini?

Given — kita membangun aplikasi Vue untuk produksi.

When — router, rendering, dan import diatur manual.

Then — banyak konfigurasi berulang dan halaman lambat tampil.

→ makanya kita pakai Nuxt — supaya struktur dan rendering sudah diatur dengan konvensi.

warm-up

Kenapa API dipanggil dua kali?

<script setup>
const res = await fetch("/api/products");   // ← fetch biasa
const products = await res.json();
</script>
  • Di halaman SSR, request ini jalan di server lalu di browser lagi. Kenapa?
ide dasar

Halaman + ambil data di Nuxt

<!-- pages/products/[id].vue  ->  /products/42 -->
<script setup>
const route = useRoute();
const { data: product } = await useFetch(
  `/api/products/${route.params.id}`);
</script>

<template>
  <h1>{{ product.name }}</h1>
</template>

// server/api/products/[id].get.ts  ->  API-nya

Gampangnya

  • Folder pages/ = halaman.
  • Folder server/api/ = endpoint API.
  • useFetch mengambil data di server, tidak diulang di browser.
  • Komponen & composable auto-import.
useFetch: ambil data sekali di server, diteruskan ke browser.
konvensi

Folder dengan arti khusus

FolderIsinya
pages/Halaman, otomatis jadi rute
components/Komponen, otomatis bisa dipakai tanpa import
composables/Fungsi reaktif yang dipakai ulang (useCart)
server/api/Endpoint backend
layouts/Kerangka halaman (header, footer)
Hafal struktur folder = paham sebagian besar Nuxt.
API server

Backend kecil di folder server/

server/api/products/[id].get.ts
export default defineEventHandler(async (event) => {
  const id = getRouterParam(event, "id");
  const p = await db.product.find(id);
  if (!p) throw createError({ statusCode: 404 });
  return p;
});
dipakai di halaman
<script setup>
const route = useRoute();
const { data, error } = await useFetch(
  `/api/products/${route.params.id}`);
</script>
<!-- tipe data ikut terbaca otomatis -->
Nama file .get.ts / .post.ts menentukan metode HTTP.
