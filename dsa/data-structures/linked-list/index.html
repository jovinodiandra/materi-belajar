// Data Structures & Algorithms — saat array terlalu kaku untuk disisipi

Data yang saling menunjuk, bukan berjajar dalam larik.

Array itu enak diakses langsung lewat index, tapi kaku saat kamu perlu sering menyisip atau menghapus di tengah — semua elemen setelahnya harus digeser. Linked list menyelesaikannya dengan cara berbeda: tiap elemen jadi node mandiri yang menyimpan alamat node berikutnya. Deck ini membahas dari kenapa ia lahir, singly vs doubly linked list, trade-off-nya, sampai studi kasus production seperti LRU cache — diselingi kalimat dari buku rujukan.

Sakit
Array kaku — insert/delete di tengah = geser semua elemen, O(n)
Ide
Node saling menunjuk — tiap elemen simpan alamat elemen berikutnya
Untung
Insert/delete O(1) — di posisi mana pun yang sudah diketahui pointer-nya
Batas
Akses O(n) — tak ada index langsung, harus menyusuri dari awal
Pakai
Saat sering sisip/hapus — stack, queue, LRU cache, undo history

◆ Buat apa ini? Kenapa pakai ini?

Given — kamu simpan data pakai array, dan fiturmu sering menyisip atau menghapus elemen di tengah, bukan cuma membaca lewat index.

When — daftar itu tumbuh (misalnya antrian task, riwayat undo, atau cache), dan tiap insert/delete di tengah harus menggeser semua elemen setelahnya, plus array kadang perlu dialokasikan ulang saat kapasitasnya penuh.

Then — tanpa struktur node yang saling menunjuk, tiap operasi sisip/hapus tetap O(n): makin banyak data, makin lambat, dan kode jadi sibuk menggeser memori alih-alih fokus pada logika.

→ makanya kita pakai linked list — cukup sambung-ulang pointer ke node tetangga, tanpa menggeser elemen lain sama sekali.

Akar masalah · Array yang kaku

Array cepat diakses, tapi mahal disisipi

Array menyimpan elemen berurutan di memori sehingga array[i] bisa langsung dihitung alamatnya — akses O(1). Tapi begitu kamu ingin menyisip atau menghapus di tengah, seluruh elemen setelah posisi itu harus digeser satu-satu. Di banyak bahasa, ukuran array juga harus diketahui atau dialokasikan ulang saat penuh.

array — sisip di tengah = geser semua elemenJava
// sisipkan 99 di index 2, array penuh berisi [10,20,30,40,50]
int[] arr = { 10, 20, 30, 40, 50 };
for (int i = arr.length - 1; i > 2; i--) {
    arr[i] = arr[i - 1];      // geser satu-satu ke kanan
}
arr[2] = 99;
// -- O(n): elemen ke-3 sampai terakhir semua ikut bergerak
◆ Analogi — gerbong kereta yang saling terhubung

Array itu seperti bangku bioskop — nomor kursi sudah dicetak berurutan, mudah dicari, tapi kalau mau menambah satu kursi di tengah baris, semua orang di kanan harus geser. Linked list itu seperti gerbong kereta: tiap gerbong hanya perlu tahu gerbong berikutnya. Mau menyisip satu gerbong baru? Cukup putuskan satu sambungan & pasang ulang dua kait — gerbong lain tidak perlu bergeser sama sekali.

Konsep inti · Struktur node

Node: data + pointer ke next

Unit paling dasar sebuah linked list adalah node: sebuah "kotak" yang menyimpan data, plus satu referensi (next) ke node berikutnya. List itu sendiri hanya perlu menyimpan satu pointer: head, yang menunjuk node pertama. Ini disebut singly linked list — rantainya hanya bisa disusuri maju.

"Sebuah linked list memungkinkan operasi INSERT dan DELETE dilakukan dalam waktu O(1) di posisi mana pun yang pointer-nya sudah diketahui — sebagai gantinya, ia kehilangan kemampuan akses acak O(1) yang dimiliki array."

— parafrase dari Thomas H. Cormen dkk., Introduction to Algorithms (CLRS), bab struktur data dasar
SinglyLinkedList.java — node, insert di head, traversalJava
class Node {
    T data;
    Node next;

    Node(T data) {
        this.data = data;
        this.next = null;
    }
}

class SinglyLinkedList {
    private Node head;

    // insert di head — O(1), tak peduli sepanjang apa list-nya
    public void insertAtHead(T data) {
        Node newNode = new Node<>(data);
        newNode.next = head;
        head = newNode;
    }

    // traversal — HARUS O(n), tak ada index langsung ke elemen ke-i
    public void traverse() {
        Node current = head;
        while (current != null) {
            System.out.println(current.data);
            current = current.next;
        }
    }
}
◆ Padanan istilah array ↔ linked list
arr[i]→ node.next diikuti sebanyak i kali (traversal)
index 0→ head (pointer ke node pertama)
length→ tidak tetap, tumbuh/susut per node
memori→ berurutan (contiguous) → tersebar, disatukan pointer

Intinya: array menghitung alamat elemen secara matematis (base + i × ukuran), sedangkan linked list menyimpan alamat elemen berikutnya secara eksplisit di tiap node — itu sebabnya harus disusuri satu per satu.

Konsep inti · Dua arah

Doubly linked list: pointer prev & next

Singly linked list cuma bisa maju. Kalau kamu perlu menghapus sebuah node dan hanya tahu node itu sendiri (bukan node sebelumnya), kamu terpaksa menyusuri ulang dari head untuk mencari prev-nya — itu O(n). Doubly linked list menambah satu pointer lagi, prev, sehingga tiap node sudah "kenal" tetangga kiri dan kanannya sekaligus.

singly — hanya majuJava
class Node {
    T data;
    Node next;
}

// hapus node "target": prev-nya tidak diketahui
Node prev = head;
while (prev.next != target) {
    prev = prev.next;        // telusuri dari head
}
prev.next = target.next;
// -- O(n) hanya untuk MENCARI prev-nya
doubly — maju & mundurJava
class Node {
    T data;
    Node prev;
    Node next;
}

// hapus node "target": prev sudah dikenal node itu sendiri
target.prev.next = target.next;
target.next.prev = target.prev;
// -- O(1) murni, tanpa traversal cari prev
◆
Kemampuan mundur ini tidak gratis: tiap node doubly linked list butuh satu pointer ekstra (prev), artinya overhead memori per elemen lebih besar dibanding singly linked list. Pakai doubly hanya kalau kamu memang butuh navigasi dua arah atau delete O(1) dari referensi node langsung — kalau cuma perlu maju, singly sudah cukup & lebih hemat.
◆ Praktik · Kebiasaan baik

Best practice memakai linked list

Linked list gampang salah kalau lupa mengurus pointer-nya. Beberapa kebiasaan ini bikin implementasimu jauh lebih aman & jarang bug.

  1. Pakai dummy/sentinel node di depan head (dan/atau setelah tail) supaya insert/delete tidak perlu penanganan khusus untuk kasus "list masih kosong" — kode jadi lebih seragam.
  2. Simpan pointer tail terpisah kalau kamu sering insert di akhir list, supaya tidak perlu traversal O(n) hanya untuk sampai ke ujung.
  3. Simpan counter size kalau butuh tahu panjang list — jangan hitung dengan traversal penuh tiap kali dibutuhkan.
  4. Di bahasa dengan manajemen memori manual (C/C++), selalu free/delete node yang sudah dihapus dari rantai — tanpa garbage collector, node yatim itu jadi memory leak.
  5. Urutkan update pointer dengan benar saat insert/delete di doubly linked list — salah urutan menyambung prev/next bisa memutus rantai atau bikin cycle tak sengaja.
  6. Waspada dangling pointer — setelah sebuah node dihapus, pastikan tidak ada node atau variabel lain yang masih menunjuk ke situ.
◆ Level · Peta belajar

Tier belajar linked list

Dari operasi dasar sampai struktur turunan yang dipakai di sistem nyata — begini kira-kira jenjangnya.

Beginner

Operasi dasar

Kuasai dulu manipulasi node paling mendasar sampai lancar tanpa bug pointer.

  • Insert di head & di tail
  • Delete berdasarkan nilai atau posisi
  • Traversal & print isi list
  • Cari panjang & cari elemen tertentu
Middle

Manipulasi struktur

Mulai memutar & menganalisis bentuk rantai node, bukan cuma insert/delete lurus.

  • Reverse linked list (iteratif & rekursif)
  • Deteksi cycle — Floyd's slow/fast pointer
  • Cari node tengah dengan two-pointer
  • Gabung dua sorted linked list
Advance

Struktur turunan

Linked list jadi bahan bangunan untuk struktur data yang dipakai di sistem production.

  • LRU cache — doubly linked list + hash map
  • Skip list — ekstensi probabilistik untuk search cepat
  • Implementasi deque & circular buffer
◆ Harga · Tidak ada makan siang gratis

Trade-off: linked list vs array

Linked list bukan "lebih baik" dari array — ia menukar satu kelebihan dengan kelebihan lain. Sedgewick & Wayne menyebut ide struktur "linked" ini sebagai salah satu gagasan paling fundamental dalam ilmu komputer.

"Struktur data yang saling terhubung lewat referensi ('linked') adalah salah satu ide paling fundamental dalam ilmu komputer — ia membebaskan struktur data dari kebutuhan alokasi memori berurutan, membuka jalan untuk struktur yang lebih kompleks seperti tree dan graph."

— parafrase dari Robert Sedgewick & Kevin Wayne, Algorithms, bab struktur data fundamental

// Yang kamu dapat

  • Insert/delete O(1) di posisi yang pointer-nya sudah diketahui.
  • Ukuran dinamis — tumbuh/susut tanpa realokasi besar-besaran.
  • Tidak butuh blok memori berurutan yang besar.
  • Fondasi untuk struktur lebih kompleks (tree, graph, hash chaining).

// Yang kamu korbankan

  • Akses elemen ke-i jadi O(n) — tak ada index langsung.
  • Overhead memori: tiap node menyimpan pointer ekstra.
  • Cache locality buruk — node tersebar di memori, bukan berdekatan.
  • Lebih rawan bug pointer dibanding operasi index array.
◆ Keputusan · Pakai atau jangan

Kapan harus pakai linked list

Aturan praktisnya: kalau pola aksesmu didominasi sisip/hapus di posisi yang sudah kamu pegang referensinya, pilih linked list. Kalau kamu sering butuh akses acak cepat ke elemen ke-i, pilih array.

// Pakai linked list saat…

  • Sering insert/delete di depan, tengah, atau akhir.
  • Ukuran data tidak diketahui & berubah-ubah drastis.
  • Implementasi stack, queue, atau deque.
  • Butuh LRU cache atau undo/redo history.
  • Kamu sudah pegang referensi node — bukan indeksnya.

// Jangan, pilih array saat…

  • Butuh akses acak cepat lewat index (arr[i]).
  • Perlu binary search atau operasi berbasis index.
  • Ukuran data sudah tetap/diketahui dari awal.
  • Perhitungan numerik berat yang butuh cache locality.
  • Iterasi sekuensial murni tanpa insert/delete di tengah.
◆ Pertanyaan penentu

Tanyakan ke pola aksesmu: "Apakah aku lebih sering menyisip/menghapus, atau lebih sering melompat langsung ke elemen tertentu?" Kalau sisip/hapus yang dominan → linked list. Kalau lompat ke index yang dominan → array.

Studi kasus · Di dunia nyata

Linked list di sistem production

Tiga skenario di mana linked list (khususnya doubly linked list) jadi bahan bangunan struktur data yang dipakai luas — perhatikan polanya: butuh navigasi dua arah atau insert/delete O(1) di ujung rantai.

// caching

LRU Cache

Kasus: sistem cache perlu tahu item mana yang paling lama tidak dipakai untuk dibuang saat kapasitas penuh. Kenapa linked list: doubly linked list + hash map memberi get/put O(1) — node yang diakses dipindah ke depan, node paling belakang yang dibuang.

// text editor

Undo / redo history

Kasus: editor teks perlu mengingat riwayat perubahan & bisa maju-mundur di antaranya. Kenapa linked list: doubly linked list pas untuk navigasi dua arah — undo jalan ke prev, redo jalan ke next.

// media player

Playlist next / prev

Kasus: pemutar musik perlu berpindah ke lagu berikutnya atau sebelumnya, kadang berulang (mode "repeat"). Kenapa linked list: doubly (atau circular) linked list membuat navigasi maju-mundur antar lagu jadi O(1) tanpa index array.

◆ Benang merahnya

Di ketiga kasus di atas, kebutuhannya bukan "akses elemen ke-i", melainkan berpindah relatif dari posisi sekarang (maju, mundur, atau buang ujung) — dan itu persis kekuatan utama linked list.

// keputusan

Built-in vs implementasi manual

Pakai LinkedList bawaan untuk kebutuhan umum & correctness yang sudah teruji. Implementasikan manual saat belajar/latihan interview, atau saat butuh kontrol penuh atas struktur (mis. sentinel node custom untuk LRU cache).

Penutup

Pilih berdasarkan pola akses, bukan kebiasaan

Linked list lahir dari keinginan menyisip & menghapus data tanpa harus menggeser semuanya. Ia bersinar saat kamu sering mengubah posisi node yang sudah kamu pegang, dan tersandung saat kamu butuh akses acak cepat.

  • Node — data + pointer next (dan prev untuk doubly).
  • Insert/delete O(1) — di posisi mana pun yang pointer-nya sudah diketahui.
  • Akses O(n) — tak ada index langsung, harus menyusuri dari head.
  • Singly — hanya maju; Doubly — maju & mundur dengan prev.
  • Sentinel node — sederhanakan edge case list kosong.
  • Studi kasus nyata — LRU cache, undo/redo, playlist next/prev.

Aturan emasnya

Tanya: "Apakah aku lebih sering menyisip/menghapus dari posisi yang sudah kupegang, atau melompat ke index tertentu?" Kalau sisip/hapus yang dominan, linked list memberimu O(1) di situ. Kalau lompat ke index yang dominan, array (dengan akses O(1))-nya akan lebih cocok. Selanjutnya, gagasan "sisip/hapus di satu ujung, O(1)" ini akan kamu pakai lagi saat belajar struktur data berikutnya.
