State Management

State = ingatan aplikasi: siapa yang login, isi keranjang, filter aktif. Pertanyaannya: ingatan ini disimpan di mana?

$ Simpan barang sedekat mungkin dengan yang memakainya.

Semua state dimasukkan ke satu store global. Ubah input form, seluruh aplikasi render ulang.

◆ Buat apa ini? Kenapa pakai ini?

Given — aplikasi punya banyak jenis data yang perlu diingat.

When — semuanya dimasukkan ke satu store global tanpa dibedakan.

Then — kode rumit, data server basi, dan aplikasi lambat.

→ makanya kita pakai state management yang tepat — supaya tiap state disimpan di tempat yang pas.

contoh

Store global vs alat yang pas

✗ Semua di store
// slice produk di Redux
dispatch(fetchProductsStart());
const res = await api.get("/products");
dispatch(fetchProductsSuccess(res.data));
// + loading, error, refetch, cache: manual
✓ State server pakai Query
const { data, isLoading, error } = useQuery({
  queryKey: ["products", page],
  queryFn: () => api.get(`/products?page=${page}`),
});
// cache, loading, retry, refetch: otomatis
Cache, loading, retry, refetch: otomatis.

Zustand

Store global yang kecil

membuat store
import { create } from "zustand";

export const useCart = create((set) => ({
  items: [],
  add: (item) => set((s) => ({
    items: [...s.items, item],
  })),
  clear: () => set({ items: [] }),
}));
memakai
// hanya render ulang saat items berubah
const count = useCart((s) => s.items.length);
const add = useCart((s) => s.add);

<button onClick={() => add(product)}>
  Beli ({count})
</button>
Ambil sebagian kecil dari store (selector) supaya render ulang seperlunya.
