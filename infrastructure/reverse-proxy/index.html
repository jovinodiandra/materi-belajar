◆ Buat apa ini? Kenapa pakai ini?

Given — beberapa aplikasi perlu diakses dari internet lewat satu domain.

When — setiap aplikasi menghadap internet langsung dan mengurus HTTPS sendiri.

Then — konfigurasi berulang, aplikasi terbebani, dan routing rumit.

→ makanya kita pakai reverse proxy — supaya ada satu pintu depan yang mengurus urusan umum.

ide dasar

Contoh konfigurasi Nginx

server {
  listen 443 ssl;
  server_name toko.id;
  ssl_certificate     /etc/ssl/toko.crt;
  ssl_certificate_key /etc/ssl/toko.key;
  gzip on;

  location /api/ {
    proxy_pass http://backend:8080/;
    proxy_set_header X-Forwarded-For $remote_addr;
  }
  location / {
    root /usr/share/nginx/html;    # file frontend
  }
}

Gampangnya

  • Satu tempat untuk HTTPS.
  • /api/ diteruskan ke backend.
  • File statis dilayani langsung oleh Nginx.
  • Header X-Forwarded-For membawa IP asli user.
Teruskan X-Forwarded-For, supaya aplikasi tahu IP asli user.
