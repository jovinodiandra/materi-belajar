◆ Buat apa ini? Kenapa pakai ini?

Given — halaman mengambil data dari server saat user berinteraksi.

When — fetch dipanggil tanpa mengurus loading, error, pembatalan, dan cache.

Then — hasil salah tampil, request dobel, dan error tidak terlihat.

→ makanya kita pakai data fetching yang benar — supaya data yang tampil selalu benar dan terbaru.

ide dasar

Batalkan request lama

✗ Rawan race condition
useEffect(() => {
  fetch(`/api/search?q=${q}`)
    .then(r => r.json())
    .then(setResults);   // balasan lama bisa menimpa
}, [q]);
✓ Batalkan yang lama
useEffect(() => {
  const ctrl = new AbortController();
  fetch(`/api/search?q=${q}`, { signal: ctrl.signal })
    .then(r => r.json())
    .then(setResults)
    .catch(e => { if (e.name !== "AbortError") setError(e); });
  return () => ctrl.abort();   // batalkan saat q berubah
}, [q]);
Tambah debounce (tunggu user berhenti mengetik ±300ms).

TanStack Query

Biarkan library mengurus cache

ambil data
function useMe() {
  return useQuery({
    queryKey: ["me"],
    queryFn: () => api("/me"),
    staleTime: 60_000,   // segar selama 1 menit
  });
}
const { data, isPending, error } = useMe();
yang didapat gratis
✓ 3 komponen → 1 request
✓ Hasil disimpan di cache
✓ Ambil ulang saat tab difokuskan lagi
✓ Retry otomatis kalau gagal
✓ Loading & error state siap pakai
queryKey = nama laci cache. Key sama = data sama.

setelah mengubah

Segarkan data setelah mutasi

useMutation
const qc = useQueryClient();
const addTodo = useMutation({
  mutationFn: (t) => api("/todos", { method: "POST", body: t }),
  onSuccess: () => {
    qc.invalidateQueries({ queryKey: ["todos"] });
  },
});
