// Data Structures & Algorithms — struktur data paling dasar, dipakai di hampir semua program

Akses data secepat mengetuk pintu bernomor, bukan mencarinya satu per satu.

Array adalah blok memori yang berurutan, dibagi jadi slot-slot bernomor (index). Karena slotnya berurutan dan berukuran sama, komputer bisa langsung menghitung alamat elemen ke berapa pun tanpa perlu menelusuri satu-satu — itulah kenapa akses by index selalu O(1). Tapi kecepatan ini ada harganya: menyisipkan atau menghapus di tengah berarti menggeser banyak elemen lain. Deck ini membahas array dari nol: konsepnya, kompleksitasnya, sampai dynamic array (ArrayList/vector) yang bisa membesar sendiri.

Sakit
Variabel lepas-lepas — nyimpen 100 nilai pakai 100 nama variabel? nggak scalable
Ide
Blok memori berurutan — satu nama, banyak slot bernomor index
Untung
Akses O(1) — alamat elemen dihitung langsung, bukan ditelusuri
Batas
Insert/delete di tengah O(n) — elemen lain harus digeser

Saat ukuran diketahui & random access dominan — buffer, matrix, lookup table

→ makanya kita pakai Array.

Akar masalah · Kenapa array ada

Bayangkan deretan loker bernomor

Kalau kamu punya 5 nilai ujian, bikin 5 variabel terpisah (nilai1, nilai2, ...) cepat jadi berantakan — apalagi kalau jumlahnya ratusan. Kamu butuh satu wadah yang bisa menampung banyak nilai, tapi tetap bisa mengambil salah satunya secara langsung, tanpa mencari.

◆ Analogi — loker bernomor di stasiun

Array itu seperti deretan loker bernomor berurutan di stasiun kereta: loker 0, loker 1, loker 2, dan seterusnya, berjejer tanpa celah. Kalau kamu tahu nomor lokernya, kamu jalan lurus ke sana dan buka — tidak perlu memeriksa loker lain satu per satu. Itulah kenapa array cocok saat kamu tahu "ambil elemen ke-berapa" dan ingin itu terjadi seketika.

Karena lokernya berjejer dengan ukuran seragam dan tanpa celah, alamat loker ke-i bisa dihitung langsung dari alamat loker pertama — tidak perlu jalan dari loker 0 ke loker i satu demi satu. Prinsip aritmatika sederhana inilah yang membuat array begitu cepat diakses.

“Memilih struktur data yang tepat sering kali adalah keputusan desain paling penting dalam sebuah program.”

— disarikan dari Robert Sedgewick & Kevin Wayne, Algorithms (4th ed.)
Konsep inti · Memory layout & index

Elemennya berdempetan di memori, index-nya cuma alamat relatif

Array menyimpan elemennya di lokasi memori yang berurutan & berdempetan. Index bukan "label" ajaib — ia cuma jarak (offset) dari alamat elemen pertama. Karena semua elemen berukuran sama, komputer tinggal kalikan: alamat = alamat_awal + (index * ukuran_elemen).

“Array menyimpan elemen-elemennya di lokasi memori yang berurutan, sehingga alamat elemen ke-i bisa dihitung langsung secara aritmatika dari alamat awal array — tanpa perlu menelusuri struktur apa pun.”

— disarikan dari Cormen, Leiserson, Rivest, Stein, Introduction to Algorithms (CLRS)
array.java — deklarasi, akses, iterasiJAVA
// deklarasi array berukuran tetap: 5 slot berurutan
int[] umur = new int[5];

// isi tiap slot lewat index-nya
umur[0] = 17;
umur[1] = 20;
umur[2] = 25;
umur[3] = 19;
umur[4] = 22;

// akses langsung by index -> O(1), nggak peduli seberapa besar array-nya
int nilaiKetiga = umur[2]; // = 25

// iterasi = jalan lurus dari index 0 sampai length-1
for (int i = 0; i < umur.length; i++) {
    System.out.println("umur[" + i + "] = " + umur[i]);
}

Konsekuensi dari layout berdempetan ini: ukuran array biasanya harus ditentukan di awal. Kalau di tengah jalan kamu butuh slot ke-6 padahal array cuma dialokasikan 5 slot, tidak ada tempat kosong di sebelahnya untuk ditambahkan begitu saja — kamu harus bikin blok baru yang lebih besar (lihat bab dynamic array).

Konsep inti · Operasi & kompleksitas

Cepat untuk akses, mahal untuk sisip-hapus di tengah

Layout berdempetan yang membuat akses super cepat, justru itu juga yang membuat insert/delete di tengah jadi mahal — elemen-elemen setelahnya harus digeser supaya tidak ada celah kosong di tengah array.

kompleksitas operasi arrayBIG-O
Operasi                              | Kompleksitas | Kenapa
--------------------------------------|--------------|--------------------------------------
Akses by index      arr[i]            | O(1)         | alamat dihitung langsung
Search nilai tertentu (posisi belum   | O(n)         | harus scan satu-satu, tak tahu posisinya
tahu)                                  |              |
Insert / delete di AKHIR              | O(1)*        | tinggal tambah/kurangi slot terakhir
                                        |              | (*amortized, kalau dynamic array resize)
Insert / delete di AWAL / TENGAH      | O(n)         | semua elemen setelah posisi itu digeser

Array dengan ukuran tetap (fixed-size, seperti int[] di Java) tidak bisa membesar sendiri. Solusinya adalah dynamic array — seperti ArrayList di Java, vector di C++, atau list di Python — yang di baliknya tetap array biasa, tapi otomatis membuat array baru yang lebih besar & menyalin isinya ketika penuh.

fixed array — penuh, harus resize manualJAVA
int[] arr = new int[3];
arr[0]=1; arr[1]=2; arr[2]=3;

// arr[3] = 4;  -> ArrayIndexOutOfBoundsException!

// harus bikin array baru & salin manual
int[] baru = new int[6];
System.arraycopy(arr, 0, baru, 0, arr.length);
arr = baru;
arr[3] = 4; // baru bisa
ArrayList — resize otomatis di baliknyaJAVA
List<Integer> list = new ArrayList<>();
list.add(1); list.add(2); list.add(3);

list.add(4); // penuh? otomatis bikin array baru
             // (kapasitas biasanya jadi ~1.5-2x), lalu salin isi lama
◆
Proses resize itu sendiri O(n) (menyalin semua elemen lama), tapi karena tidak terjadi di setiap penambahan — hanya sesekali saat kapasitas habis — biaya rata-rata per operasi add() tetap O(1). Inilah maksud "amortized O(1)": mahal sesekali, murah rata-rata.
◆ Praktik · Best practice

Cara pakai array yang nggak nyusahin diri sendiri

Array itu sederhana, tapi salah pakai bisa bikin kode lambat atau rawan error. Beberapa kebiasaan baik berikut membantumu memilih & memakainya dengan tepat.

  1. Pilih fixed array kalau ukurannya benar-benar tetap & kamu butuh akses super cepat by index (mis. papan catur 8x8, buffer sensor).
  2. Pilih ArrayList/dynamic array kalau jumlah elemennya berubah-ubah selama program berjalan — jangan paksakan fixed array lalu resize manual berulang kali.
  3. Preallocate kapasitas kalau kamu sudah tahu perkiraan jumlah elemen (mis. new ArrayList<>(1000)) — mengurangi jumlah resize di belakang layar.
  4. Hindari insert/delete di awal/tengah array besar dalam loop ketat — tiap operasi menggeser banyak elemen, O(n) yang berulang bisa jadi O(n²) total.
  5. Selalu cek batas index sebelum akses (0 <= i < length) — akses di luar batas adalah sumber bug/klasik IndexOutOfBounds.
  6. Manfaatkan cache locality-nya — iterasi berurutan (index 0, 1, 2, ...) jauh lebih cepat di praktik dibanding lompat-lompat acak, karena elemen yang berdekatan sudah termuat di CPU cache.

◆ Harga · Tidak ada makan siang gratis

Trade-off: array vs linked list

Array & linked list sama-sama menyimpan koleksi elemen, tapi dengan filosofi berlawanan: array mengutamakan kecepatan akses, linked list mengutamakan kecepatan sisip-hapus.

// Array unggul di…

  • Akses by index — langsung O(1), tanpa menelusuri.
  • Cache locality — elemen berdempetan, iterasi cepat di praktik.
  • Overhead memori kecil — tidak ada pointer per elemen.
  • Random access & binary search (kalau terurut).

// Linked list unggul di…

  • Insert/delete di awal/tengah — O(1) begitu punya referensi node-nya.
  • Ukuran benar-benar dinamis tanpa proses resize/copy.
  • Tidak butuh blok memori berdempetan yang besar sekaligus.
  • Cocok untuk struktur seperti queue/stack yang sering berubah.
◆ Catatan

Linked list tidak punya akses O(1) by index — untuk sampai ke elemen ke-i, kamu tetap harus menelusuri node satu per satu dari awal, jadi O(n). Itu sebabnya array tetap jadi pilihan default kalau random access sering dipakai.

◆ Keputusan · Pakai atau jangan

Kapan harus pakai array (dan kapan tidak)

Aturan praktisnya: kalau kamu tahu ukuran datanya & sering mengakses elemen by posisi, pakai array. Kalau ukurannya sering berubah drastis atau sisip-hapus di tengah adalah operasi utama, pertimbangkan struktur lain.

// Pakai array saat…

  • Ukuran data diketahui/diperkirakan di awal.
  • Random access by index adalah operasi dominan.
  • Butuh cache locality untuk performa (mis. numerik/matrix).
  • Data akan di-binary search (setelah diurutkan).
  • Butuh struktur ringan tanpa overhead pointer.

// Jangan, pertimbangkan lain saat…

  • Sering insert/delete di awal/tengah dalam jumlah besar.
  • Ukuran benar-benar tak terduga & berubah drastis.
  • Butuh akses cepat by key, bukan by posisi (pakai hash map).
  • Elemen sering pindah urutan/reorder (linked list bisa lebih pas).
◆ Pertanyaan penentu

Tanyakan ke datamu: "Apakah aku lebih sering mengambil elemen ke-berapa, atau lebih sering menyisipkan/menghapus di tengah?" Kalau jawabannya akses by posisi → array. Kalau sisip-hapus di tengah yang dominan → pertimbangkan linked list atau struktur lain.

Studi kasus · Di dunia nyata

Array di sistem production

Tiga contoh di mana array (atau layout mirip array) jadi fondasi performa, bukan sekadar struktur data buku teks.

// networking

Buffer paket data

Kasus: stack jaringan & driver perangkat menampung byte yang masuk/keluar di ring buffer — array melingkar berukuran tetap. Kenapa array: ukuran buffer diketahui di awal, dan akses/tulis by posisi harus secepat mungkin tanpa alokasi memori berulang.

// image processing

Pixel array pada gambar

Kasus: sebuah gambar direpresentasikan sebagai array 2D (atau array 1D yang diperlakukan sebagai grid) berisi nilai piksel per baris-kolom. Kenapa array: operasi seperti filter/konvolusi butuh akses berurutan ke piksel tetangga — cache locality array bikin proses ini jauh lebih cepat dibanding struktur bertaut.

// database

Column store

Kasus: database analitik (column-oriented) menyimpan nilai-nilai dari satu kolom secara array-like, berdempetan di memori/disk, alih-alih per baris. Kenapa array: query yang men-scan satu kolom penuh (mis. SUM(harga)) memanfaatkan locality itu supaya lebih efisien dibaca berurutan.

◆ Benang merahnya

Di ketiga kasus itu, alasan memilih array bukan cuma "gampang dipakai" — tapi karena pola aksesnya berurutan & dapat diprediksi, sehingga layout memori yang berdempetan benar-benar terasa manfaatnya di performa nyata, bukan cuma di atas kertas Big-O.

Penutup

Array: sederhana di permukaan, fondasi di bawahnya

Array adalah struktur data paling dasar — tapi hampir semua struktur lain (stack, queue, hash table, bahkan sebagian tree) dibangun di atasnya atau terinspirasi olehnya. Paham array dengan benar berarti paham kenapa layout memori itu penting.

  • Blok memori berurutan — alamat elemen ke-i dihitung langsung, bukan ditelusuri.
  • Akses O(1) — kekuatan utama array, apa pun ukurannya.
  • Insert/delete di tengah O(n) — harga dari layout yang berdempetan.
  • Dynamic array = array + resize otomatis — amortized O(1) untuk tambah di akhir.
  • Cache locality nyata — bukan cuma teori, tapi performa di dunia nyata.
  • Pilih dari pola akses — random access dominan → array; sisip-hapus tengah dominan → pertimbangkan lain.

Lanjut ke struktur berikutnya

Sekarang kamu paham kenapa array cepat diakses tapi mahal disisipi di tengah. Struktur berikutnya, Linked List, mengambil pendekatan sebaliknya — melepas syarat "berdempetan di memori" demi sisip-hapus yang murah. Bandingkan trade-off-nya langsung setelah ini.
