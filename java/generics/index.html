Generics

Tulis kode sekali, pakai untuk banyak tipe — dan compiler tetap menjaga supaya tipenya tidak tertukar.

$ Kotak berlabel: kotak “apel” hanya boleh diisi apel.

Tanpa generics, list bisa diisi apa saja. Error baru ketahuan saat program jalan.

📦

List berisi Object

String, Integer, apa saja bisa masuk.

🔄

Harus cast manual

(String) list.get(0) di mana-mana.

💥

ClassCastException saat jalan

Bug baru muncul di produksi.

Kotak berlabel

compiler mengecek isi kotak

◆ Buat apa ini? Kenapa pakai ini?

Given — kita butuh wadah atau method yang bisa dipakai untuk banyak tipe.

When — kita memakai Object lalu cast manual.

Then — salah tipe baru ketahuan saat program jalan.

→ makanya kita pakai Generics — supaya salah tipe ketahuan saat compile.

warm-up

Kenapa ini error saat jalan, bukan saat compile?

List list = new ArrayList();   // tanpa <…>
list.add("halo");
list.add(42);
for (Object o : list) {
  String s = (String) o;   // ← ClassCastException di sini
}
  • Compiler diam saja. Error baru muncul di depan user.
ide dasar

Sebelum dan sesudah generics

✗ Tanpa generics
List names = new ArrayList();
names.add("Budi");
names.add(42);          // lolos, tidak ada yang protes

String n = (String) names.get(1);
// ClassCastException saat jalan!
✓ Dengan generics
List<String> names = new ArrayList<>();
names.add("Budi");
names.add(42);          // ERROR saat compile

String n = names.get(0); // tanpa cast
Salah tipe ketahuan di editor, bukan di produksi.
contoh

Membuat kelas dan method generik

// kelas generik: T = tipe apa saja
public record Result<T>(T value, String error) {
    static <T> Result<T> ok(T v)  { return new Result<>(v, null); }
    static <T> Result<T> fail(String e) { return new Result<>(null, e); }
}

Result<User>  r1 = Result.ok(user);
Result<Order> r2 = Result.fail("stok habis");

// method generik dengan batas
static <T extends Comparable<T>> T max(List<T> xs) {..}

Gampangnya

  • T = nama sementara untuk tipe.
  • Diisi saat dipakai: Result<User>.
  • extends = batas: T harus bisa dibandingkan.
T, E, K, V cuma kebiasaan nama: Type, Element, Key, Value.
lanjutan

Wildcard: ? extends dan ? super

BentukGampangnyaContoh
List<? extends Number>Boleh dibaca sebagai NumberMenjumlahkan list Integer atau Double
List<? super Integer>Boleh diisi IntegerMenambahkan angka ke list Number
Hafalan: PECSProducer Extends, Consumer SuperBaca → extends · Tulis → super
Ingat PECS: baca pakai extends, tulis pakai super.
salah → benar

Method generik daripada copy-paste

✗ satu method per tipe
Integer firstInt(List<Integer> l) {
  return l.isEmpty() ? null : l.get(0);
}
String firstStr(List<String> l) {
  return l.isEmpty() ? null : l.get(0);
}   // ← isinya kembar
✓ satu untuk semua
<T> Optional<T> first(List<T> l) {
  return l.isEmpty()
      ? Optional.empty()
      : Optional.of(l.get(0));
}
first(names);  first(prices);
T itu kayak tempat kosong di formulir: diisi tipe apa pun saat dipakai.
aturan PECS

Kapan extends, kapan super?

Producer Extends

? extends Number

Kita membaca dari list. Isinya pasti Number atau turunannya.

Consumer Super

? super Integer

Kita menulis ke list. List-nya pasti bisa menampung Integer.

Ingat: baca → extends, tulis → super.
jebakan

Hal yang bikin bingung di generics

  • Type erasure: saat jalan, List<String> dan List<Integer> sama-sama cuma List.
  • Tidak bisa new T() atau new T[10]. Tipe T sudah hilang saat jalan.
  • List<Integer> bukan turunan List<Number>. Pakai wildcard.
  • Hindari raw type (List tanpa <>). Compiler akan memberi warning, jangan diabaikan.
