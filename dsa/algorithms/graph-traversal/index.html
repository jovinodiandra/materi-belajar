// DSA — Algorithms · lanjutan dari representasi graph, kali ini soal menjelajahnya

Dari satu titik, jelajahi semuanya — dan temukan jalur terpendeknya.

Punya graph (representasinya sudah dibahas di topik sebelumnya) itu satu hal — tahu cara menjelajahinya adalah hal lain. Dua pertanyaan paling umum di dunia nyata: "apakah A bisa mencapai B?" dan "apa jalur tercepat dari A ke B?" Deck ini fokus ke algoritma traversal & shortest path: BFS & DFS sebagai fondasi, lalu Dijkstra untuk graph berbobot, topological sort untuk urutan dependency, dan sekilas minimum spanning tree — diselingi kalimat dari buku & tokoh rujukan.

Peta, package manager, social network — traversal ada di mana-mana
◆ Buat apa ini? Kenapa pakai ini?

Given — kamu punya adjacency list dari social network dengan ribuan node/edge, dan kamu cuma tahu siapa terhubung langsung ke siapa — belum ada cara pasti untuk menjawab "apakah user A bisa dicapai dari user B?" atau "berapa langkah minimal dari A ke B?".

When — kamu coba telusuri manual pakai rekursi naif dari satu node, ikuti edge ke edge; tapi graph-nya punya cycle (A follow B, B follow A lagi), jadi node yang sama dikunjungi berulang-ulang.

Then — programnya infinite loop atau stack overflow karena tidak ada penanda "sudah dikunjungi", dan kalaupun dipaksa jalan, kamu tidak bisa menjamin jalur yang ditemukan itu benar-benar yang terpendek.

Akar masalah · Dua pertanyaan paling umum

Terhubung, atau tidak? Dan kalau ya, seberapa dekat?

Hampir semua masalah berbasis graph, kalau dikupas, ujung-ujungnya jadi salah satu dari dua pertanyaan ini: "apakah node A bisa mencapai node B?" (reachability/connectivity) dan "apa jalur terpendek dari A ke B?" (shortest path). Menjawab keduanya butuh cara sistematis untuk mengunjungi node satu per satu tanpa mengunjungi node yang sama berulang-ulang — itulah graph traversal.

◆ Analogi — menjelajahi semua kota terhubung dari satu titik

Bayangkan kamu berdiri di satu kota dan punya peta jalan (graph-nya) tapi tidak tahu kota mana saja yang bisa dicapai dari sana. Cara paling jujur: mulai dari kotamu, telusuri jalan-jalan yang keluar darinya, catat kota baru yang ditemukan, lalu ulangi dari tiap kota baru itu — sambil mencoret kota yang sudah pernah dikunjungi supaya tidak muter-muter selamanya. Itulah inti dari traversal: sistematis, dan tidak mengunjungi ulang.

Bedanya dengan topik "Graph" sebelumnya: di situ kamu belajar cara menyimpan peta jalan itu (adjacency list/matrix). Di sini, kamu belajar cara berjalan di atasnya — dan urutan/strategi berjalan itu ternyata sangat menentukan: apakah kamu menemukan jalur terpendek, atau cuma jalur apa saja yang kebetulan ditemukan lebih dulu.

Konsep inti · Dua strategi dasar

BFS: level demi level. DFS: sedalam mungkin dulu.

BFS (breadth-first search) memakai queue — mengunjungi semua tetangga langsung dulu, baru tetangga dari tetangga, level demi level. Karena sifatnya inilah BFS cocok untuk shortest path di graph tak berbobot — node pertama yang ditemukan lewat BFS pasti lewat jalur dengan jumlah edge paling sedikit. DFS (depth-first search) memakai stack (atau rekursi) — menelusuri satu cabang sedalam mungkin dulu sebelum mundur (backtrack) dan mencoba cabang lain.

GraphBFS.java — traversal level demi levelJava
import java.util.*;

public class GraphBFS {

    static List<Integer> bfs(Map<Integer, List<Integer>> graph, int start) {
        List<Integer> order = new ArrayList<>();
        Set<Integer> visited = new HashSet<>();
        Queue<Integer> queue = new LinkedList<>();

        queue.add(start);
        visited.add(start);

        while (!queue.isEmpty()) {
            int node = queue.poll();        // ambil dari DEPAN antrean
            order.add(node);

            for (int neighbor : graph.getOrDefault(node, List.of())) {
                if (!visited.contains(neighbor)) {
                    visited.add(neighbor);  // tandai SEBELUM masuk queue
                    queue.add(neighbor);    // masuk ke BELAKANG antrean
                }
            }
        }
        return order;
    }
}
GraphDFS.java — telusuri sedalam mungkin duluJava
import java.util.*;

public class GraphDFS {

    static void dfs(Map<Integer, List<Integer>> graph, int node,
                    Set<Integer> visited, List<Integer> order) {
        if (visited.contains(node)) return;   // sudah dikunjungi, berhenti

        visited.add(node);
        order.add(node);

        for (int neighbor : graph.getOrDefault(node, List.of())) {
            dfs(graph, neighbor, visited, order); // telusuri sedalam mungkin dulu
        }
    }
}

Perhatikan satu kemiripan penting di keduanya: visited. Tanpa itu, graph yang punya siklus (cycle) akan membuat traversal berputar-putar selamanya. BFS & DFS sama-sama butuh cara menandai "sudah pernah ke sini" — bedanya cuma urutan node mana yang dikunjungi lebih dulu.

Konsep lanjutan · Saat edge punya bobot & arah

Dijkstra untuk graph berbobot, topological sort untuk DAG

BFS hanya benar untuk shortest path kalau semua edge dianggap sama beratnya. Begitu edge punya bobot berbeda (jarak, biaya, waktu tempuh), kamu butuh Dijkstra's algorithm — memakai priority queue/heap untuk selalu memproses node dengan jarak sementara terkecil berikutnya. Untuk kebutuhan berbeda — graph terarah tanpa siklus (DAG) yang merepresentasikan dependency — ada topological sort: mengurutkan node sedemikian rupa sehingga setiap edge A → B selalu menempatkan A sebelum B.

“Jalur terpendek ke suatu node bisa dibangun secara greedy: selalu proses dulu node dengan jarak sementara terkecil berikutnya — dan begitu diproses, jarak itu final, asalkan semua bobot edge non-negatif.”

— parafrase dari Edsger W. Dijkstra, pencipta algoritma shortest path yang menyandang namanya
Dijkstra.java — pakai PriorityQueue (lihat topik Heap)Java
import java.util.*;

public class Dijkstra {

    static int[] shortestPath(int n, List<int[]>[] adj, int src) {
        int[] dist = new int[n];
        Arrays.fill(dist, Integer.MAX_VALUE);
        dist[src] = 0;

        PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[1] - b[1]);
        pq.add(new int[]{src, 0});

        while (!pq.isEmpty()) {
            int[] curr = pq.poll();          // jarak sementara terkecil dulu
            int node = curr[0], d = curr[1];
            if (d > dist[node]) continue;   // sudah ada jarak lebih pendek, skip

            for (int[] edge : adj[node]) {
                int next = edge[0], weight = edge[1];
                if (dist[node] + weight < dist[next]) {
                    dist[next] = dist[node] + weight;
                    pq.add(new int[]{next, dist[next]});
                }
            }
        }
        return dist;
    }
}
BFS dipaksa ke graph BERBOBOT — hasilnya salahJava
// edge berbobot: A-B(1), A-C(10), B-C(1)
// BFS anggap semua edge "1 langkah" — tak peduli bobot
List<Integer> order = bfs(graph, "A");
// BFS bilang: A ke C = 1 langkah (lewat edge langsung A-C)
// padahal lewat A-B-C, TOTAL BOBOTnya cuma 1+1 = 2, lebih pendek dari 10
// BFS tak tahu soal bobot -> shortest path versi BFS SALAH
Dijkstra pada graph yang sama — hasilnya benarJava
// edge berbobot: A-B(1), A-C(10), B-C(1)
int[] dist = Dijkstra.shortestPath(3, adj, 0);
// Dijkstra proses A dulu (dist 0), lalu B (dist 1, terkecil berikutnya)
// dari B ketemu C lewat B-C: dist[C] = 1 + 1 = 2, LEBIH KECIL dari 10
// dist[C] akhirnya 2 -> BENAR, karena bobot ikut diperhitungkan
◆ Topological sort — urutan valid di DAG
syaratgraph HARUS directed & acyclic (DAG)
ide DFSDFS tiap node → catat urutan SELESAI-nya → balik urutan itu
ide Kahnhitung in-degree tiap node → proses yang in-degree 0 dulu

Contoh paling gampang dibayangkan: mata kuliah prasyarat. Kalau "Kalkulus 2" butuh "Kalkulus 1" (edge Kalkulus1 → Kalkulus2), topological sort menjamin urutan pengambilan matkul yang tidak pernah melanggar prasyarat — persis seperti urutan instalasi dependency di package manager.

◆ Praktik · Kebiasaan aman menulis traversal

Best practice graph traversal

Kebiasaan ini akan menyelamatkanmu dari bug traversal paling umum — dari infinite loop sampai shortest path yang diam-diam salah.

  1. Selalu pakai visited set — tanpa ini, graph bersiklus membuat traversal berputar selamanya. Ini berlaku untuk BFS, DFS, maupun Dijkstra.
  2. BFS untuk shortest path TANPA bobot — kalau semua edge dianggap setara, BFS sudah cukup dan lebih sederhana daripada Dijkstra.
  3. Dijkstra untuk shortest path DENGAN bobot non-negatif — begitu edge punya bobot berbeda (jarak, biaya, waktu), BFS tidak lagi menjamin hasil benar.
  4. Cek dulu: berbobot atau tidak, terarah atau tidak — sebelum menulis kode, tentukan bentuk graph-nya; salah asumsi di sini bikin algoritma yang "jalan" tapi hasilnya salah.
  5. Topological sort hanya valid di DAG — kalau ada siklus, tidak ada urutan valid yang mungkin; deteksi cycle dulu sebelum mengandalkan hasil topological sort.
  6. Waspada bobot negatif — Dijkstra tidak benar kalau ada edge berbobot negatif; untuk kasus itu, algoritma seperti Bellman-Ford dibutuhkan.
◆ Roadmap · Bertahap sesuai levelmu

Tier belajar graph traversal

Graph traversal punya jenjang yang cukup jelas — dari sekadar bisa mengunjungi semua node, sampai menghitung jalur terpendek pada graph yang jauh lebih rumit.

Beginner

BFS/DFS dasar

Mulai dari bisa mengunjungi seluruh node dan mengenali bagian-bagian graph yang saling terhubung.

  • BFS & DFS pada graph sederhana
  • Connected components
  • Deteksi "apakah A bisa mencapai B?"
  • BFS/DFS pada grid (matrix) 2D
Middle

Shortest path tak berbobot & urutan

Naik ke masalah yang butuh urutan atau jarak minimum, tapi masih di graph tanpa bobot berbeda.

  • Shortest path unweighted (pakai BFS)
  • Topological sort (Kahn / DFS)
  • Deteksi cycle di directed graph
  • Multi-source BFS
Advance

Graph berbobot & optimisasi

Level ini mulai menyentuh algoritma yang jadi andalan sistem production — rute, jaringan, biaya minimum.

  • Dijkstra's algorithm (heap-based)
  • Bellman-Ford (menangani bobot negatif)
  • Minimum spanning tree — Kruskal (Union-Find) & Prim (Greedy)
  • A* search (Dijkstra + heuristik)
◆ Harga · BFS vs DFS

Trade-off: optimal tapi boros vs hemat tapi tak terjamin

BFS & DFS sama-sama benar untuk mengunjungi seluruh node — tapi keduanya membayar harga yang berbeda, dan cocok untuk tujuan yang berbeda pula.

// BFS

  • Optimal untuk shortest path di graph tak berbobot — node pertama ditemukan pasti lewat jalur terpendek.
  • Cocok untuk pencarian "jarak minimum" atau "level terdekat".
  • Lebih boros memori — queue bisa menampung seluruh node di satu level sekaligus (lebar graph).

// DFS

  • Tidak menjamin jalur yang ditemukan adalah jalur terpendek.
  • Lebih hemat memori — stack hanya menyimpan satu jalur aktif sedalam apa pun graph-nya.
  • Natural untuk backtracking, deteksi cycle, & topological sort.

“BFS & DFS adalah dua strategi traversal fundamental yang menjadi basis hampir semua algoritma graph lanjutan: BFS mengeksplorasi level demi level dan alami untuk shortest path di graph tak berbobot, sementara DFS mengeksplorasi sedalam mungkin dan menjadi basis algoritma seperti topological sort & deteksi cycle.”

— parafrase dari Thomas H. Cormen, Charles E. Leiserson, Ronald L. Rivest, Clifford Stein, Introduction to Algorithms (CLRS)
◆ Keputusan · Sinyal soal

Kapan (dan algoritma mana) yang harus dipakai

Sebagian besar soal graph traversal sebenarnya "membocorkan" algoritma yang harus dipakai lewat kalimatnya sendiri — kenali sinyalnya.

// Sinyal kalimat soal → algoritma

  • "Jalur terpendek" tanpa bobot → BFS.
  • "Jalur terpendek/termurah" dengan bobot/jarak/biaya → Dijkstra.
  • "Apakah A bisa mencapai B?" / terhubung → BFS atau DFS.
  • "Urutan valid berdasar dependency/prasyarat" → topological sort.
  • "Hubungkan semua node dengan biaya minimum" → minimum spanning tree.

// Jangan asal pilih saat…

  • Graph-nya berbobot tapi kamu pakai BFS — hasilnya bisa diam-diam salah.
  • Ada edge bobot negatif tapi kamu pakai Dijkstra — perlu Bellman-Ford.
  • Graph-nya bersiklus tapi kamu paksakan topological sort — tidak ada urutan valid.
  • Rekursi DFS pada graph sangat dalam tanpa batas — risiko stack overflow.
◆ Pertanyaan penentu

Tanyakan tiga hal ke soalmu secara berurutan: (1) apakah edge-nya punya bobot berbeda? (2) apakah arahnya penting & adakah dependency? (3) apakah ada siklus? Jawaban dari ketiganya langsung mengarahkanmu ke BFS, DFS, Dijkstra, atau topological sort — jarang ada ambiguitas kalau tiga pertanyaan ini sudah dijawab jujur.

Studi kasus · Di dunia nyata

Di mana graph traversal benar-benar dipakai di production

Tiga contoh nyata di mana algoritma di deck ini bukan sekadar latihan buku teks, tapi menjadi inti dari fitur yang dipakai jutaan orang setiap hari.

// navigasi

Google Maps / Waze

Kasus: mencari rute tercepat dari titik A ke titik B di jaringan jalan raya yang jaraknya berbeda-beda tiap ruas. Kenapa: memakai varian algoritma shortest path — Dijkstra atau A* (Dijkstra + heuristik arah tujuan) — karena jalan punya bobot (jarak/waktu tempuh) yang tidak seragam.

// package manager

npm / Maven / apt

Kasus: sebuah package butuh package lain sebagai prasyarat, yang juga butuh package lain lagi. Kenapa: memakai topological sort untuk menentukan urutan instalasi yang benar — dependency selalu terpasang sebelum package yang membutuhkannya.

// social network

Fitur "teman tingkat 2"

Kasus: menampilkan "mutual connections" atau saran pertemanan berbasis "teman dari temanmu". Kenapa: memakai BFS dari satu user — level 1 adalah teman langsung, level 2 adalah teman dari teman — persis pola level-demi-level yang menjadi ciri khas BFS.

◆ Benang merahnya

Di ketiga kasus, pertanyaannya selalu balik ke dua hal yang dibahas di bab 01: keterhubungan dan jalur/urutan optimal. Bedanya cuma bentuk graph-nya — berbobot (jalan raya) butuh Dijkstra, terarah tanpa siklus (dependency) butuh topological sort, tak berbobot (pertemanan) cukup BFS.

Penutup

Menjelajah dengan sistematis, memilih algoritma sesuai bentuk graph

Graph traversal, pada intinya, cuma soal berjalan dari node ke node tanpa muter-muter — dan memilih strategi berjalan (BFS, DFS, Dijkstra, topological sort) yang cocok dengan bentuk graph & pertanyaan yang ingin dijawab.

  • Visited set — wajib, supaya graph bersiklus tidak membuatmu berputar selamanya.
  • BFS — level demi level, optimal untuk shortest path tak berbobot.
  • DFS — sedalam mungkin dulu, hemat memori, fondasi topological sort & deteksi cycle.
  • Dijkstra — shortest path saat edge punya bobot non-negatif, pakai priority queue.
  • Topological sort — urutan valid berdasar dependency, hanya berlaku di DAG.
  • MST (Kruskal/Prim) — biaya minimum menghubungkan semua node, dibangun di atas Union-Find & Greedy.
