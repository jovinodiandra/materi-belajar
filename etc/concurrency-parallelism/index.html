Concurrency vs
Parallelism

Concurrency: mengurus banyak hal secara bergantian. Parallelism: mengerjakan banyak hal benar-benar bersamaan. Mirip, tapi beda.

$ Satu koki memasak 3 menu bergantian vs 3 koki memasak bersamaan.

ide dasar

Bedanya dalam gambar

Concurrency = struktur. Parallelism = eksekusi.

Concurrency

1 koki, 3 panci.
Aduk A → tunggu → aduk B → aduk C.
Banyak urusan, satu tangan.

Parallelism

3 koki, 3 panci.
Semua mengaduk di detik yang sama.
Banyak urusan, banyak tangan.

JavaScript: concurrency tanpa parallelism. Java: bisa keduanya.
warm-up

Concurrency atau parallelism?

Tebak:

  • Satu pelayan restoran melayani 5 meja bergantian.
  • Lima kasir melayani 5 antrean di saat yang sama.
  • Browser memuat 10 gambar sambil menunggu jaringan.
  • Mengubah ukuran 1.000 foto di 8 core CPU.

Race condition

bahaya

Deadlock

Virtual threads: ribuan tugas menunggu tanpa berat

kode
try (var exec = Executors.newVirtualThreadPerTaskExecutor()) {
  for (var id : orderIds) {
    exec.submit(() -> notify(id));   // panggil API
  }
}   // menunggu semua selesai
kenapa ringan
Thread biasa:   ±1 MB memori, ribuan = berat
Virtual thread: beberapa KB, jutaan bisa

Banyak urusan, bersamaan. Untuk kerja yang menghitung.
