MVP

Model–View–Presenter: View dibuat sebodoh mungkin. Semua keputusan tampilan diambil oleh Presenter.

$ View itu boneka. Presenter dalangnya.

Activity Android berisi logika. Tidak bisa dites tanpa menyalakan HP.

📱

Logika di dalam Activity/Form

Validasi, format, keputusan semua di kelas UI.

🧪

Tes butuh emulator

Lambat dan sering gagal sendiri.

🔁

Logika tidak bisa dipakai ulang

Terikat ke kelas UI tertentu.

View pasif

semua keputusan di Presenter

◆ Buat apa ini? Kenapa pakai ini?

Given — aplikasi punya layar dengan logika tampilan yang lumayan banyak.

When — logika itu ditulis langsung di kelas UI (Activity, Form).

Then — logika tidak bisa dites tanpa UI sungguhan.

→ makanya kita pakai MVP — supaya logika tampilan pindah ke kelas biasa yang gampang dites.

contoh

Presenter bisa dites tanpa UI

✗ Presenter
interface LoginView {
  void showError(String msg);
  void goToHome();
}
class LoginPresenter {
  LoginPresenter(LoginView v, AuthService a) {..}
  void onLoginClicked(String email, String pw) {
    if (email.isBlank()) { view.showError("Email kosong"); return; }
    if (auth.login(email, pw)) view.goToHome();
    else view.showError("Password salah");
  }
}
✓ Tes tanpa UI
@Test
void emailKosong_tampilkanError() {
  var view = mock(LoginView.class);
  var p = new LoginPresenter(view, auth);

  p.onLoginClicked("", "rahasia");

  verify(view).showError("Email kosong");
}
View diganti mock saat tes. Jalan dalam milidetik.

View palsu untuk mengetes Presenter

view palsu
class FakeLoginView implements LoginView {
  String error; boolean wentHome;
  public void showError(String m) { error = m; }
  public void goToHome() { wentHome = true; }
}
tes tanpa emulator
@Test void email_tanpa_at_ditolak() {
  var view = new FakeLoginView();
  var p = new LoginPresenter(view, fakeAuth());
  p.onLoginClicked("budi", "rahasia");
  assertEquals("Email tidak valid", view.error);
  assertFalse(view.wentHome);
}
View yang bodoh itu bagus: tidak ada logika yang perlu dites di sana.
jebakan

Layar diputar, Presenter bocor

Activity dibuat ulang
→
Presenter lama pegang View lama
→
View lama tidak dibuang
→
Memory leak
  • Panggil presenter.detach() di onDestroy untuk melepas View.
  • Inilah salah satu alasan Android modern beralih ke MVVM.
praktik

Aturan main MVP yang sehat

  • View tidak mengambil keputusan. Cuma meneruskan klik dan menampilkan.
  • Presenter tidak import kelas Android/Swing. Hanya interface View.
  • Satu layar, satu Presenter. Kalau Presenter 1.000 baris, pecah layarnya.
  • Nama method View berbentuk perintah: showLoading(), showError().

❯ interface

View diakses lewat interface, jadi bisa di-mock.
