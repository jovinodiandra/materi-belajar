Browser Storage

Tempat menyimpan data di browser user: cookie, localStorage, sessionStorage, dan IndexedDB. Beda kapasitas, beda umur, beda keamanan.

$ Saku, tas, dan lemari: beda barang, beda tempat.

ide dasar

Empat tempat menyimpan

TempatKapasitasUmurCocok untuk
Cookie±4 KBSesuai expiresSesi login (HttpOnly), ikut terkirim ke server
localStorage±5 MBSampai dihapusPreferensi: tema, bahasa
sessionStorage±5 MBSampai tab ditutupData sementara per tab
IndexedDBBesar (ratusan MB)Sampai dihapusData offline, file, cache besar
Cookie ikut terkirim tiap request. localStorage tidak.
contoh

Pakai localStorage dengan aman

✗ Rawan error
const prefs = JSON.parse(localStorage.getItem("prefs"));
prefs.theme;   // error kalau belum ada / rusak
✓ Aman
function readPrefs() {
  try {
    return JSON.parse(localStorage.getItem("prefs")) ?? DEFAULT;
  } catch {
    return DEFAULT;   // mode private, data rusak, diblokir
  }
}
Storage bisa kosong atau diblokir. Selalu siapkan nilai default.

Jebakan yang sering kejadian

jebakan

Token di localStorage

Bisa dibaca script mana pun (XSS). Pakai cookie HttpOnly.

jebakan

Data sensitif

Jangan simpan data pribadi atau kartu di browser.

jebakan

Lupa versi

Bentuk data berubah? Beri versi supaya data lama bisa dibuang.

tips

Hanya string

localStorage hanya menyimpan teks. Pakai JSON.stringify.

Tiga hal untuk diingat

❯ pilih

Cookie untuk sesi, localStorage untuk preferensi, IndexedDB untuk data besar.

❯ aman

Token di cookie HttpOnly, bukan localStorage.

❯ rapuh

Storage bisa kosong. Siapkan default.
