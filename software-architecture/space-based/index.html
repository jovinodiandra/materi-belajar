Space-Based Architecture

Untuk trafik super tinggi: data utama disimpan di memori bersama yang tersebar di banyak server, bukan langsung di database.

$ Kasir di depan, gudang di belakang.

◆ Buat apa ini? Kenapa pakai ini?

Given — aplikasi menghadapi lonjakan trafik yang ekstrem dan tidak terduga.

When — semua request langsung membaca dan menulis ke satu database.

Then — database menjadi leher botol dan akhirnya tumbang.

→ makanya kita pakai Space-Based — supaya data utama dilayani dari memori yang bisa ditambah kapan saja.

Data grid (memori bersama)

salinan data disinkronkan antar unit, mis. Hazelcast

↓

Data writer → Database

menulis ke database belakangan (asinkron)

Database tetap ada, tapi diisi belakangan.
contoh

Contoh sederhana dengan Hazelcast

HazelcastInstance hz = Hazelcast.newHazelcastInstance();
IMap<String, Integer> stock = hz.getMap("stock");

boolean buy(String productId) {
    stock.lock(productId);
    try {
        int left = stock.get(productId);
        if (left <= 0) return false;      // habis
        stock.put(productId, left - 1);   // di memori
        return true;
    } finally { stock.unlock(productId); }
}
// MapStore menulis ke DB secara asinkron

Gampangnya

  • Stok disimpan di memori bersama, bukan dibaca dari DB tiap request.
  • Lock per produk supaya tidak terjual lebih.
  • Database di-update belakangan oleh MapStore.
Write-behind: memori dulu, database menyusul.
