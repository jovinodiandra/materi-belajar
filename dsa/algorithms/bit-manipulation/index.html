// DSA — Algorithms · operasi paling native yang dipahami CPU

Bicara langsung dengan 0 dan 1, tanpa perantara.

Di balik semua abstraksi — int, boolean, List — angka tetap cuma barisan bit di memori. Bit manipulation adalah operasi yang bekerja langsung pada representasi biner itu: AND, OR, XOR, NOT, dan geser bit (shift). Karena ini operasi native yang dipahami CPU secara langsung, ia jadi salah satu operasi tercepat yang bisa kamu tulis. Deck ini buat pemula: dari kenapa ia ada, operator dasarnya, trik-trik populer, sampai kapan dipakai di dunia nyata — diselingi kalimat dari buku rujukan.

◆ Buat apa ini? Kenapa pakai ini?

Given — kamu perlu simpan & cek banyak status boolean sekaligus (misal 32 permission user, atau subset dari sebuah set), lalu kamu simpan tiap status sebagai boolean[] terpisah atau objek per-flag, dan cek genap/ganjil atau tukar dua variabel pakai pembagian, modulo, atau variabel bantu.

When — jumlah flag/status itu membesar (ratusan permission, subset di soal DP bitmask, atau loop ketat yang jalan jutaan kali), dan struktur boolean/array itu ikut dialokasikan serta di-loop satu per satu.

Then — memori boros (tiap boolean makan minimal 1 byte, padahal cuma butuh 1 bit), operasi jadi lambat karena bukan instruksi native CPU, dan kode gampang berantakan karena logika "flag mana yang nyala" tersebar di banyak variabel/percabangan.

→ makanya kita pakai Bit Manipulation.

Akar masalah · Bahasa asli komputer

Komputer pada dasarnya cuma paham 0 dan 1

Setiap angka, karakter, gambar, atau instruksi yang berjalan di komputer, pada level paling dasar, cuma barisan bit — 0 dan 1, mati atau nyala. Semua tipe data yang kita pakai sehari-hari (int, char, boolean) adalah abstraksi di atas barisan bit itu. Bit manipulation adalah cara bekerja tanpa abstraksi itu — langsung ke representasi asli angkanya.

◆ Analogi — saklar lampu yang bisa dikombinasi jadi kode

Bayangkan satu baris saklar lampu di dinding, masing-masing cuma bisa on atau off. Satu saklar saja cuma bisa mewakili dua keadaan. Tapi delapan saklar berjajar, dikombinasikan, bisa mewakili 256 kombinasi berbeda — cukup untuk mengkodekan huruf, angka, atau kombinasi status apa pun. Itulah persis yang dilakukan bit dalam sebuah angka biner: tiap bit adalah satu saklar, dan kombinasinya membentuk kode.

Banyak operasi aritmatika & logika yang terlihat butuh banyak langkah sebenarnya bisa diselesaikan dengan beberapa operasi bit native yang jauh lebih cepat — asal polanya dikenali.

— parafrase dari Henry S. Warren Jr., Hacker's Delight

Karena operasi bit (AND, OR, XOR, shift) langsung dieksekusi oleh Arithmetic Logic Unit (ALU) di CPU dalam satu siklus instruksi, ia jauh lebih cepat dibanding operasi yang terlihat setara secara matematis tapi ditulis lewat pembagian, modulo, atau percabangan berulang. Inilah kenapa bit manipulation dipakai saat performa benar-benar penting.

Konsep inti · Operator bitwise

Lima operator dasar: AND, OR, XOR, NOT, shift

Semua trik bit manipulation dibangun dari lima operator ini. Java menyediakannya langsung sebagai operator native: & (AND), | (OR), ^ (XOR), ~ (NOT), << (shift kiri), dan >> / >>> (shift kanan).

BitBasics.java — cek, set, clear, toggle bit ke-iJava
public class BitBasics {

    // cek apakah bit ke-i bernilai 1
    static boolean checkBit(int num, int i) {
        return ((num >> i) & 1) == 1;
    }

    // set bit ke-i jadi 1
    static int setBit(int num, int i) {
        return num | (1 << i);
    }

    // clear (paksa jadi 0) bit ke-i
    static int clearBit(int num, int i) {
        return num & ~(1 << i);
    }

    // toggle (balik) bit ke-i
    static int toggleBit(int num, int i) {
        return num ^ (1 << i);
    }

    public static void main(String[] args) {
        int n = 0b1010; // 10 dalam desimal
        System.out.println(checkBit(n, 1));   // true, bit index-1 = 1
        System.out.println(setBit(n, 0));     // 11 (0b1011)
        System.out.println(clearBit(n, 1));   // 8  (0b1000)
        System.out.println(toggleBit(n, 3));  // 2  (0b0010)
    }
}
◆ Ringkasan operator
AND &1 jika KEDUA bit 1 — dipakai untuk cek/clear bit
OR |1 jika SALAH SATU bit 1 — dipakai untuk set bit
XOR ^1 jika bit BERBEDA — dipakai untuk toggle & swap
NOT ~balik semua bit — dipakai bareng AND untuk clear
shift<< kali 2, >> bagi 2 (bulat ke bawah)

Pola 1 << i membuat angka dengan cuma bit ke-i yang menyala — dasar dari hampir semua trik set/clear/toggle bit di atas.

Trik populer · Pola yang sering muncul

Genap-ganjil, power of two, dan hitung bit 1

Beberapa trik bit muncul berulang-ulang di soal maupun kode production, karena mereka mengganti operasi aritmatika (pembagian, modulo, loop) dengan satu-dua operasi bit native yang jauh lebih murah.

cara biasa — modulo & divisionJava
// cek genap/ganjil pakai modulo
boolean genap = (n % 2 == 0);

// cek power of 2 pakai loop pembagian
boolean isPowerOfTwo(int n) {
    if (n <= 0) return false;
    while (n % 2 == 0) n /= 2;
    return n == 1;
}
// modulo & division: lebih banyak siklus CPU
bit trick — operasi nativeJava
// cek genap/ganjil pakai bit terakhir
boolean genap = ((n & 1) == 0);

// cek power of 2: hanya 1 bit yang menyala
boolean isPowerOfTwo(int n) {
    return n > 0 && (n & (n - 1)) == 0;
}
// & langsung: satu operasi, tanpa loop

Trik n & (n-1) bekerja karena n-1 mematikan bit 1 paling kanan dari n dan menyalakan semua bit di kanannya. Jika n adalah pangkat dua (cuma punya satu bit 1), hasil AND-nya pasti nol. Trik yang sama juga jadi dasar Brian Kernighan's algorithm untuk menghitung jumlah bit 1 (popcount):

PopCount.java — Brian Kernighan's algorithmJava
static int countSetBits(int n) {
    int count = 0;
    while (n != 0) {
        n = n & (n - 1); // matikan 1 bit paling kanan tiap iterasi
        count++;
    }
    return count; // loop sebanyak jumlah bit 1, bukan jumlah total bit
}

Trik lain yang sangat berguna: bitmask untuk representasi subset. Satu int 32-bit bisa mewakili subset dari sampai 32 elemen — bit ke-i menyala berarti elemen ke-i ada di subset itu. Ini jadi fondasi teknik bitmask DP yang dibahas lebih lanjut di bab Tier Belajar.

◆ Praktik · Kebiasaan aman pakai bit manipulation

Best practice bit manipulation

Bit manipulation gampang dipakai berlebihan sampai kodenya susah dibaca. Kebiasaan berikut membantu memakainya di tempat yang tepat, tanpa mengorbankan kejelasan kode.

  1. Pakai bitmask untuk representasi subset/flags yang hemat memori — satu int bisa menggantikan array boolean atau Set, jauh lebih ringkas untuk cek/gabung status.
  2. Hati-hati signed vs unsigned shift — >> di Java melakukan arithmetic shift (mempertahankan bit tanda), sedangkan >>> melakukan logical shift (selalu isi 0 di kiri). Salah pilih bisa menghasilkan bilangan negatif yang tak terduga.
  3. XOR untuk swap tanpa variabel temp bisa dipakai, tapi jangan dipaksakan kalau mengurangi keterbacaan — int temp = a; a = b; b = temp; lebih jelas dibaca siapa pun dibanding tiga baris XOR.
  4. Beri nama & komentar pada bitmask — gunakan konstanta bernama (mis. FLAG_READ = 1 << 0) daripada angka ajaib seperti 5 yang tidak jelas maksudnya.
  5. Uji dengan nilai batas — 0, negatif, Integer.MAX_VALUE, dan bit paling signifikan — karena overflow & perilaku shift di batas ini sering jadi sumber bug.
  6. Jangan mikro-optimasi prematur — kalau kode belum terbukti jadi bottleneck, versi yang lebih mudah dibaca (modulo, boolean array) sering cukup; simpan bit trick untuk saat performa/memori benar-benar dibutuhkan.
◆ Roadmap · Bertahap sesuai levelmu

Tier belajar bit manipulation

Dari operator dasar sampai bitmask DP — berikut jalur belajarnya dari pemula sampai lanjut.

Beginner

Operator dasar

Kenalan dengan operator bitwise dan trik paling sederhana yang langsung terasa manfaatnya.

  • AND, OR, XOR, NOT, shift
  • Cek genap/ganjil pakai n & 1
  • Set/clear/toggle bit ke-i
  • Konversi biner ↔ desimal
Middle

Trik & representasi compact

Mulai memakai bit sebagai struktur data ringkas, bukan cuma trik aritmatika.

  • Hitung jumlah bit 1 (Kernighan)
  • Cek power of two
  • Bitmask untuk representasi subset
  • Bitmask sebagai state di dynamic programming
Advance

Bitmask DP & trik lanjutan

Di level ini, bit manipulation jadi fondasi teknik algoritma yang lebih kompleks.

  • Bitmask DP (mis. traveling salesman kecil)
  • Lowest set bit isolation (n & -n)
  • Enumerasi semua subset dari sebuah mask
  • Trik XOR untuk mencari elemen unik
◆ Harga · Bit manipulation vs cara konvensional

Trade-off: kecepatan mentah vs keterbacaan

Bit manipulation bukan "selalu lebih baik" — ia menukar keterbacaan dengan kecepatan & kehematan memori. Pilih berdasarkan apakah pertukaran itu benar-benar dibutuhkan di tempat itu.

// Bit manipulation

  • Sangat cepat — operasi native satu siklus CPU.
  • Hemat memori — satu int bisa mewakili 32 flag/subset.
  • Cocok untuk state compact di algoritma (bitmask DP).

// Cara konvensional

  • Lebih mudah dibaca & dipahami tim baru.
  • Kurang rawan bug tersembunyi (overflow, signed shift).
  • Kalau dipakai berlebihan, bit trick bisa susah di-maintain.

Manipulasi bit bukan cuma "trik obscure" — ia adalah alat yang mendasari cara komputer merepresentasikan & memproses informasi di level paling rendah, dan menjadi fondasi banyak algoritma kombinatorial.

— parafrase dari Donald Knuth, The Art of Computer Programming, Volume 4A: Combinatorial Algorithms
◆ Soal keterbacaan

Kode seperti x = x & (x - 1) jelas bagi yang sudah kenal trik ini, tapi terlihat seperti sihir bagi yang belum. Beri komentar singkat di titik-titik trik seperti ini, atau bungkus dalam fungsi bernama jelas (clearLowestSetBit) supaya niatnya tetap terbaca tanpa harus menghafal triknya.

◆ Keputusan · Pakai atau jangan

Kapan harus pakai bit manipulation

Aturan praktisnya: pakai saat performa kritis atau representasi compact (flags, subset) benar-benar dibutuhkan. Hindari kalau ia mengorbankan keterbacaan tanpa manfaat nyata.

// Pakai bit manipulation saat…

  • Performa jadi bottleneck nyata & sudah diukur.
  • Butuh representasi flags/subset yang hemat memori.
  • State algoritma alami berupa kombinasi on/off (bitmask DP).
  • Bekerja di level protokol/format biner (network, file).

// Hindari saat…

  • Belum ada bukti performa jadi masalah (optimasi prematur).
  • Tim/kode-base tidak terbiasa membaca trik bit.
  • Alternatif yang lebih jelas (boolean array, Set) sudah cukup cepat.
  • Manfaat kecepatannya tak sebanding risiko bug tersembunyi.
◆ Pertanyaan penentu

Tanyakan: "Apakah kecepatan/kehematan memori dari bit trick ini benar-benar dibutuhkan di sini, atau aku cuma ingin terlihat pintar?" Kalau performa/memori memang kritis dan terukur, bit manipulation memberi keuntungan nyata. Kalau tidak, versi yang lebih mudah dibaca biasanya pilihan yang lebih sehat jangka panjang.

Studi kasus · Di dunia nyata

Di mana bit manipulation benar-benar dipakai di production

Tiga area di mana bekerja langsung dengan bit bukan sekadar latihan, tapi kebutuhan nyata dari bentuk masalahnya.

// access control

Flags & permission system

Kasus: sebuah sistem perlu menyimpan kombinasi izin (baca, tulis, hapus, admin, dst) untuk tiap pengguna. Kenapa bit: kombinasi permission direpresentasikan sebagai bitmask — satu integer bisa mewakili banyak on/off flag sekaligus, dicek & digabung cukup dengan AND/OR.

// format & codec

Compression & encoding data

Kasus: memampatkan data atau mengubahnya ke format tertentu. Kenapa bit: banyak format file & algoritma kompresi bekerja di level bit — menyusun, membaca, dan menata ulang bit adalah operasi inti dari cara data dikemas menjadi lebih ringkas.

// networking

Header protokol jaringan

Kasus: paket data yang dikirim lewat jaringan punya header dengan banyak field kecil (versi, flag, panjang) yang harus muat dalam beberapa byte. Kenapa bit: protokol jaringan menyusun informasi dalam bit-bit tertentu di header — membaca & menyusunnya butuh operasi shift dan mask langsung ke level bit.

◆ Benang merahnya

Di ketiga kasus di atas, kebutuhannya sama: representasi yang compact (banyak informasi kecil dalam ruang sesempit mungkin) dan/atau kecepatan pemrosesan di level yang sangat rendah. Bit manipulation bukan dipilih karena tren, tapi karena bentuk masalahnya memang bekerja di level bit sejak awal.

Penutup

Cepat karena native, tapi tetap harus terbaca

Bit manipulation lahir dari kenyataan paling dasar komputer: semua cuma 0 dan 1. Ia bersinar saat kamu butuh kecepatan mentah atau representasi paling compact — dan tersandung saat dipaksakan ke tempat yang tidak membutuhkannya, mengorbankan keterbacaan tanpa manfaat nyata.

  • Semua data = bit — operasi bit adalah bahasa asli komputer.
  • Lima operator dasar — AND, OR, XOR, NOT, shift.
  • n & (n-1) — dasar cek power of two & hitung jumlah bit 1.
  • Bitmask — representasi subset/flags yang hemat memori.
  • Cepat tapi kurang terbaca — trade-off yang harus disadari.
  • Pakai saat terbukti perlu — bukan karena ingin terlihat pintar.

Aturan emasnya

Kenali operator dasarnya sampai reflek, kuasai beberapa trik populer (genap-ganjil, power of two, popcount, bitmask subset) — lalu pakai di tempat yang memang membutuhkan kecepatan atau kehematan memori. Beri nama & komentar yang jelas supaya kecepatan yang kamu dapat tidak dibayar dengan kode yang tak bisa dibaca lagi enam bulan kemudian.
