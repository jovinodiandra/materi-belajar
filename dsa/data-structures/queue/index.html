// Data Structures & Algorithms — antrean digital, sama seperti antrean loket

Yang datang duluan, dilayani duluan.

Bayangkan loket bank: orang masuk barisan dari belakang, dan yang dilayani selalu orang di paling depan. Tidak ada yang menyerobot. Itulah queue — struktur data FIFO (First In, First Out) dengan operasi enqueue (masuk antrean) dan dequeue (keluar antrean), keduanya O(1). Deck ini membahas queue dari dasar, varian circular queue & deque, sampai studi kasus production seperti BFS dan message queue.

◆ Buat apa ini? Kenapa pakai ini?

Given — Antrean tugas (print job, request API, task di browser) kamu simpan di array biasa, lalu diambil dari ujung yang salah — misalnya .pop() seperti stack, atau splice di tengah array.

When — Job baru terus berdatangan sebelum job lama selesai diproses: ratusan print job masuk beruntun, atau BFS harus mengunjungi node graph level demi level.

Then — Job yang datang lebih dulu malah tertahan (bisa starvation) karena job baru "menyerobot" duluan, BFS diam-diam berubah jadi DFS karena urutan kunjungan kacau, dan operasi insert/delete di posisi sembarang array bisa jatuh ke O(n).

→ makanya kita pakai Queue.

Akar masalah · Kenapa queue ada

Butuh urutan yang adil — bukan urutan bebas

Banyak proses di dunia nyata butuh keadilan urutan: siapa datang duluan, dilayani duluan. Kalau kamu simpan daftar tugas di struktur yang mengizinkan ambil-sembarang atau ambil-yang-terakhir, orang yang antre paling lama bisa tidak pernah dilayani. Queue memaksa disiplin: masuk dari belakang, keluar dari depan.

◆ Analogi — antrean loket bank

Di loket bank, nasabah baru berdiri di paling belakang barisan. Teller memanggil nasabah di paling depan barisan. Tidak peduli siapa yang lebih penting atau lebih cepat — urutan datang menentukan urutan dilayani. Kalau ada yang menyerobot dari tengah, seluruh sistem terasa tidak adil. Queue di kode meniru disiplin ini persis: First In, First Out (FIFO).

Bandingkan dengan stack (LIFO — terakhir masuk, duluan keluar) yang cocok untuk hal seperti riwayat "undo". Queue justru dipakai saat urutan kedatangan harus dihormati: antrean cetak dokumen, antrean request server, atau urutan penjelajahan graph secara lapis demi lapis (breadth-first).

Konsep inti · FIFO

Enqueue di belakang, dequeue di depan

Queue punya dua operasi utama: enqueue menambah elemen baru di tail (belakang), dan dequeue mengambil elemen dari head (depan). Karena kedua ujung ini dijaga terpisah, tidak perlu menggeser elemen lain — keduanya berjalan dalam O(1).

“Queue mengikuti disiplin first-in, first-out — ENQUEUE menyisipkan elemen di bagian belakang, DEQUEUE mengeluarkan elemen dari bagian depan, dan keduanya berjalan dalam waktu O(1); queue pula yang secara alami dipakai algoritma breadth-first search.”

— parafrase gagasan Thomas H. Cormen dkk., Introduction to Algorithms (CLRS)

Di Java modern, kamu tidak perlu bikin queue dari nol. Interface Queue/Deque di java.util, diimplementasikan lewat ArrayDeque, sudah menyediakan operasi ini secara efisien:

Queue.java — ArrayDeque sebagai queue FIFOJava
import java.util.ArrayDeque;
import java.util.Deque;

public class TicketCounter {
    public static void main(String[] args) {
        // ArrayDeque dipakai sebagai queue murni lewat interface Deque
        Deque<String> antrean = new ArrayDeque<>();

        // enqueue = masuk dari belakang (tail)
        antrean.offerLast("Budi");
        antrean.offerLast("Sari");
        antrean.offerLast("Andi");

        // dequeue = keluar dari depan (head)
        while (!antrean.isEmpty()) {
            String dilayani = antrean.pollFirst(); // O(1)
            System.out.println("Melayani: " + dilayani);
        }
        // output: Budi, lalu Sari, lalu Andi — urut sesuai kedatangan
    }
}

Perhatikan: offerLast (enqueue) dan pollFirst (dequeue) sama-sama O(1) di ArrayDeque karena strukturnya array melingkar (dibahas di bab berikutnya) — tidak ada elemen yang perlu digeser saat elemen depan diambil.

Varian penting · Circular queue & deque

Array boros vs array melingkar, lalu antrean dua arah

Kalau queue dibangun naif di atas array biasa, slot yang sudah dequeue dari depan jadi terbuang percuma — array terus "bergeser maju" sampai penuh padahal ruang di depan sebenarnya kosong. Circular queue memecahkan ini dengan membungkus indeks kembali ke posisi 0 memakai modulo, jadi seluruh slot array terus dipakai ulang.

naive queue — array lurus, boros slotJava
int[] arr = new int[5];
int head = 0, tail = 0;

// enqueue: taruh di tail, tail++
arr[tail++] = 10;
arr[tail++] = 20;

// dequeue: ambil head, head++
int keluar = arr[head++]; // slot arr[0] KOSONG selamanya

// tail terus maju ke kanan; begitu tail == arr.length,
// queue dianggap "penuh" walau slot 0..head-1 sebenarnya kosong
circular queue — array melingkar, efisienJava
int[] arr = new int[5];
int head = 0, tail = 0, size = 0;

// enqueue: taruh di tail, tail bungkus pakai modulo
arr[tail] = 10;
tail = (tail + 1) % arr.length;
size++;

// dequeue: ambil head, head bungkus pakai modulo
int keluar = arr[head];
head = (head + 1) % arr.length;
size--;

// slot yang sudah dequeue otomatis dipakai ulang
// saat tail "melingkar" balik ke indeks 0

Varian lain yang lebih fleksibel: deque (double-ended queue) — antrean yang bisa insert maupun delete dari kedua ujungnya, depan maupun belakang. Itu artinya satu struktur data bisa berperan sebagai queue (FIFO) sekaligus stack (LIFO), tergantung ujung mana yang kamu pakai.

“Deque menggeneralisasi stack dan queue sekaligus — karena mengizinkan insert & delete dari kedua ujungnya, deque bisa dipakai sebagai stack maupun sebagai queue tergantung kebutuhan.”

— parafrase gagasan Robert Sedgewick & Kevin Wayne, Algorithms
◆ Priority queue — sekilas saja

Ada juga priority queue: bukan FIFO murni, elemen keluar berdasarkan prioritas tertinggi/terendah, bukan urutan kedatangan. Biasanya diimplementasikan pakai heap — pembahasan lengkapnya ada di topik Heap tersendiri, bukan di sini.

◆ Praktik · Best practice

Cara pakai queue yang benar di Java

Queue itu simpel, tapi ada beberapa jebakan umum. Berikut kebiasaan yang layak dipegang.

  1. Pakai ArrayDeque, bukan LinkedList, untuk implementasi queue di Java. ArrayDeque lebih cepat & lebih hemat memori karena tidak ada overhead pointer per-node seperti linked list.
  2. Pilih circular buffer saat ukuran queue punya batas atas yang jelas (mis. buffer streaming) — hindari alokasi ulang array terus-menerus.
  3. Gunakan offer/poll, bukan add/remove, kalau kamu ingin queue penuh/kosong dikembalikan sebagai nilai (null/false), bukan melempar exception.
  4. Jangan pakai Vector atau array manual tanpa alasan kuat — Vector ter-synchronize secara default (lebih lambat), array manual gampang salah menghitung index melingkar.
  5. Untuk konteks multithread, pakai BlockingQueue (mis. LinkedBlockingQueue, ArrayBlockingQueue) — bukan queue biasa yang tidak thread-safe.
  6. Ukur kapasitas awal (new ArrayDeque<>(capacity)) kalau kamu sudah tahu perkiraan ukuran, supaya menghindari resize berulang saat elemen bertambah.
◆ Level · Tier belajar

Dari dasar sampai concurrency

Queue kelihatan sederhana di awal, tapi penerapannya bisa jauh lebih dalam. Berikut peta belajar bertahap.

Beginner

Dasar FIFO

Kuasai operasi inti & satu algoritma klasik yang memakainya.

  • Enqueue & dequeue dasar pakai ArrayDeque
  • Cek queue kosong/penuh sebelum operasi
  • BFS (breadth-first search) sederhana di graph/tree
Middle

Deque sebagai alat bantu

Pakai deque bukan cuma sebagai antrean, tapi sebagai struktur bantu algoritma.

  • Sliding window maximum pakai deque monotonic
  • Level-order traversal dengan penanda batas level
  • Circular buffer untuk kapasitas tetap
Advance

Skala & concurrency

Queue di sistem nyata: banyak thread, banyak proses, throughput tinggi.

  • Circular buffer untuk sistem streaming
  • Pola producer-consumer
  • Thread-safe queue (BlockingQueue) untuk concurrency
◆ Harga · Queue vs stack

FIFO vs LIFO — dua disiplin, dua kegunaan

Queue dan stack sama-sama struktur data linear dengan operasi O(1), tapi disiplin urutannya berlawanan. Memilih yang salah tidak akan error secara sintaks — tapi hasil program jadi salah urutan.

// Queue (FIFO) — cocok saat…

  • Urutan kedatangan harus dihormati (antrean tugas, request).
  • Penjelajahan level-by-level (BFS di graph/tree).
  • Buffer antara producer & consumer yang beda kecepatan.
  • Scheduling yang harus adil (round-robin, print job).

// Stack (LIFO) — cocok saat…

  • Yang paling baru justru harus diproses duluan (undo/redo).
  • Penjelajahan depth-first (DFS, backtracking).
  • Melacak konteks pemanggilan (call stack, parsing kurung).
  • Membalik urutan elemen dengan cepat.
◆ Catatan

Keduanya sama-sama bisa diimplementasikan lewat interface Deque di Java — bedanya cuma ujung mana yang kamu pakai untuk masuk & keluar. Itu sebabnya deque disebut generalisasi dari keduanya.

◆ Keputusan · Pakai atau jangan

Kapan harus pakai queue

Aturan praktisnya: kalau urutan kedatangan/proses harus dihormati secara adil, pakai queue. Kalau kamu justru butuh akses acak atau LIFO, cari struktur lain.

// Pakai queue saat…

  • Butuh disiplin FIFO — adil, urut kedatangan.
  • Traversal graph/tree secara level-by-level (BFS).
  • Buffer antara proses cepat & proses lambat.
  • Task scheduling, print job, request handling.
  • Sliding window dengan kebutuhan akses dua ujung (deque).

// Jangan, pilih struktur lain saat…

  • Butuh akses elemen di tengah secara cepat — pakai array/list.
  • Butuh keluar berdasarkan prioritas, bukan urutan — pakai priority queue/heap.
  • Butuh urutan terbalik (terakhir masuk duluan keluar) — pakai stack.
  • Butuh pencarian cepat berdasarkan key — pakai hash table/map.
◆ Pertanyaan penentu

Tanyakan: "Apakah yang datang paling dulu memang harus diproses paling dulu?" Kalau ya → queue. Kalau yang penting justru prioritas, bukan urutan datang → priority queue/heap. Kalau yang terbaru harus diproses duluan → stack.

Studi kasus · Di dunia nyata

Queue di sistem production

Tiga contoh nyata di mana disiplin FIFO queue jadi fondasi — dari algoritma graph sampai sistem operasi.

// graph algorithm

BFS (breadth-first search)

Kasus: menjelajah graph/tree lapis demi lapis — mis. mencari jalur terpendek tanpa bobot, atau level-order traversal di tree. Kenapa queue: node yang ditemukan lebih dulu (lapis lebih dekat) harus diproses lebih dulu — persis disiplin FIFO.

// distributed systems

Message queue

Kasus: mengirim pesan/event antar service tanpa membuat pengirim menunggu penerima. Kenapa queue: konsep dasarnya sama dengan queue in-memory — producer enqueue pesan, consumer dequeue & proses. Detail arsitekturnya dibahas di folder infrastructure/message-broker di situs ini.

// operating system

Print job & task scheduling

Kasus: printer melayani dokumen sesuai urutan dikirim; OS menjadwalkan proses ke CPU secara round-robin. Kenapa queue: keduanya butuh keadilan urutan — job yang lebih dulu masuk antrean, lebih dulu dilayani/dialokasikan waktu CPU.

◆ Benang merahnya

Di semua kasus di atas, intinya sama: ada proses yang menghasilkan pekerjaan dan proses yang mengerjakannya, dengan kecepatan yang bisa berbeda. Queue jadi penyangga (buffer) yang menjaga urutan tetap adil sambil memisahkan kedua sisi itu.

⚙ Ekosistem · Alat & referensi

Tools untuk kerja dengan queue

Sebagai pemula di Java, kenali dulu dua kelas ini — cukup untuk hampir semua kebutuhan queue sehari-hari.

// single-thread

ArrayDeque

Implementasi queue & deque standar Java. Lebih cepat & lebih hemat memori daripada LinkedList untuk kebutuhan FIFO/LIFO biasa.

// multi-thread

BlockingQueue

Interface untuk queue yang aman dipakai lintas thread — otomatis memblokir saat queue penuh (producer) atau kosong (consumer). Implementasi umum: LinkedBlockingQueue, ArrayBlockingQueue.

// visualisasi

Visualizer BFS

Alat visualisasi algoritma graph (banyak tersedia sebagai situs interaktif) membantu melihat langsung bagaimana queue mengatur urutan node yang dikunjungi saat BFS berjalan.

Penutup

Antrean yang adil, satu ujung masuk satu ujung keluar

Queue itu sederhana di permukaan — masuk dari belakang, keluar dari depan — tapi disiplin FIFO ini jadi fondasi banyak sistem: dari BFS di algoritma graph sampai message broker di sistem terdistribusi.

  • FIFO — yang datang duluan, dilayani duluan.
  • Enqueue di tail, dequeue di head — keduanya O(1).
  • Circular queue — hindari pemborosan slot array.
  • Deque — generalisasi stack & queue, dua ujung sekaligus.
  • ArrayDeque di Java — lebih cepat dari LinkedList.
  • BlockingQueue — untuk queue yang aman lintas thread.

Lanjut ke Heap

Queue biasa memproses berdasarkan urutan kedatangan. Tapi bagaimana kalau yang harus keluar duluan bukan yang paling dulu datang, melainkan yang paling penting? Itulah priority queue — dan struktur data di baliknya, Heap, adalah topik berikutnya.
