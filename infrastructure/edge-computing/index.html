Edge Computing

Menjalankan kode di lokasi yang dekat dengan user — di server CDN atau di perangkat itu sendiri — bukan di satu data center jauh.

$ Dapur kecil di tiap cabang, bukan semua dimasak di pusat.

Redirect bahasa sederhana harus bolak-balik ke server di Singapura.

🌏

Server cuma di satu region

User di Eropa menunggu 300 ms tiap request.

🔁

Logika kecil bolak-balik jauh

Cek negara, A/B test, redirect.

📡

Perangkat IoT banyak data

Kirim semua mentah ke cloud = mahal.

kode kecil di tepi jaringan

◆ Buat apa ini? Kenapa pakai ini?

Given — user dan perangkat tersebar di banyak lokasi.

When — semua logika, sekecil apa pun, dijalankan di satu server pusat.

Then — respons lambat dan biaya kirim data tinggi.

→ makanya kita pakai edge computing — supaya logika ringan berjalan dekat dengan user.

ide dasar

Contoh: Cloudflare Worker

export default {
  async fetch(request) {
    const country = request.cf?.country;   // negara user
    const url = new URL(request.url);

    if (url.pathname === "/" && country === "ID") {
      return Response.redirect(url.origin + "/id", 302);
    }
    return fetch(request);                 // teruskan ke origin
  },
};
// jalan di ratusan kota, dekat dengan user

Gampangnya

  • Kode jalan di lokasi terdekat user.
  • Cocok untuk logika kecil & cepat.
  • Sisanya tetap diteruskan ke server pusat.
Ada batasan: waktu jalan pendek, memori kecil.

Cocok dan tidak cocok

Cocok di edge ✅Tetap di pusat ❌
Redirect & aturan berdasarkan negaraTransaksi database utama
A/B test, feature flag ringanProses berat & lama
Cek token / bot sederhanaLogika yang butuh banyak data pusat
Olah data sensor sebelum dikirim (IoT)Laporan & analitik besar
Kode di edge yang harus bertanya ke DB pusat = keuntungannya hilang.
